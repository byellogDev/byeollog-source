## 결론

자동·격리 검증 범위의 핵심 경로는 통과했다. 점검 중 후원 직후 룰렛 결과의 저장 순서가 뒤집힐 수 있는 경쟁 조건을 발견해 중앙 게이트웨이에 수정 배포했고, 개별 SDK 이벤트 형식 오류도 다음 이벤트 처리를 막지 않도록 격리했다. 종료된 룰렛/TTS 서버리스 의존성과 로컬 예약 작업, OBS의 중복 `액션` 소스도 제거 또는 비활성화했다.

최종 게이트웨이 배포 과정에서 서버 루트 디스크가 100%가 되어 새 컨테이너가 `ENOSPC` 재시작 루프에 들어가는 배포 병목도 확인했다. 빌드 캐시 2.385GB를 회수한 뒤 컨테이너를 정상화했으며, 이후 health `healthy`, 프로세스 재시작 0회, worker heartbeat와 두 워크스페이스의 정상 오프라인 대기를 확인했다. 현재 사용률은 87%(가용 약 1.3GiB)라 런타임에는 문제가 없지만 다음 이미지 빌드 전에는 용량 확장이 필요하다.

실제 SOOP 방송과 실제 후원이 있어야만 증명되는 항목은 통과로 간주하지 않고 아래 17시 확인 목록에 남겼다.

10. 방송 종료 후 게이트웨이가 `waiting_for_live`로 돌아오고 회차는 계속 선택 가능하되 과거 회차 SOOP imgUrl은 사용하지 않는지 확인한다.
