# TTS 1단계: 현재 경로 감사와 공통 벤치마크

작성일: 2026-08-29
상태: 완료 — 운영 경로 변경 없음

## 목적

TTS 공급자 이름이나 구현 방식에 끌려가지 않고, 별록 방송에서 실제로 중요한 **첫 음성 도착 속도·안정성·음성 품질**을 같은 조건으로 비교하기 위한 기준선을 만든다.

출시 목표는 SOOP 이벤트를 별록이 받은 시각부터 오버레이가 재생 가능한 첫 PCM을 받는 시각까지 다음과 같다.

- p50: 450ms 이하
- p95: 800ms 이하
- p99: 1,200ms 이하
- 요청 성공률: 99.9% 이상

이는 공급자 구간의 1차 합격선이다. 실제 스피커 출력에는 SOOP 이벤트 전달, 별록 서버, 오버레이 전송, AudioWorklet 버퍼 지연이 더해지므로 최종 단계에서 별도 E2E 계측이 필요하다.

## 현재 운영 경로 감사 결과

감사 대상은 공통 OBS 오버레이의 실제 운영 클라이언트다.

- 명령 수신: 180ms HTTP 폴링
- 폴링 자체 이론 지연: 평균 90ms, p95 171ms, 최악 180ms
- 음성 엔진: 브라우저/운영체제 `speechSynthesis`
- 공급자 제어 음색: 없음
- 첫 음성 조각 및 실제 재생 시작 계측: 없음
- 스트리밍 PCM, AudioWorklet, 지터 버퍼, 끊김 없는 큐: 없음
- 룰렛 결과 사전 생성 음원 사용: 없음

따라서 현재 경로는 기능 폴백으로는 쓸 수 있지만, 동일한 음색과 1초 안팎의 재생 체감을 보장하는 출시용 TTS 경로로 판정할 수 없다.

기계 판독 보고서: `output/tts-phase1/current-path-baseline.json`

## 공통 한국어 시험 문장

`tools/tts-benchmark/corpus.ko.json`에 다음 방송 상황을 고정했다.

- `딸깍` 같은 매우 짧은 후원 후 첫 채팅
- 룰렛 당첨 결과
- 별풍선 수량과 룰렛 횟수
- OBS 등 영문 혼용어
- 채팅 웃음과 은어
- 문장부호와 억양
- 단컷·움짤 등 상품명
- 비교적 긴 후원 메시지

화면 표시용 `[N초전]` 값은 시험 데이터의 `displayText`에만 있고 `ttsText`에는 포함하지 않는다.

## 측정값 정의

- First byte: HTTP 요청 시작부터 첫 응답 바이트 수신까지
- TTFA: 요청 시작부터 첫 재생 가능한 PCM16LE 조각 수신까지
- Total response: 전체 음성 PCM 수신 완료까지
- 자동 음성 검사: 길이, 무음 비율, RMS, 피크, 클리핑, SHA-256
- 표본 음원: 후보별·문장별 WAV 한 개

TTFA는 **실제 스피커가 소리를 낸 시각이 아니다**. 4단계 오버레이 계측에서 브라우저 재생 시작 시각을 추가한다.

## 실행 방법

도구 자체와 청크 수신 계측을 검증하는 로컬 시험:

```powershell
npm run audit:tts-path
npm run benchmark:tts:selftest
```

실제 공급자 시험은 `tools/tts-benchmark/providers.example.json`을 복사해 후보별 설정을 작성한다. 인증값은 JSON에 쓰지 않고 환경변수 이름만 참조한다.

```powershell
$env:TTS_CANDIDATE_AUTHORIZATION = 'Bearer ...'
node tools/Benchmark-TtsCandidates.mjs --config tools/tts-benchmark/providers.local.json --allow-remote --iterations 20 --warmups 2 --concurrency 1
```

안전장치:

- 원격 호출은 `--allow-remote`를 명시해야 한다.
- 원격 주소는 HTTPS만 허용한다.
- URL 안의 계정정보와 fragment를 거부한다.
- 비밀값은 환경변수에서만 읽는다.
- 요청 제한시간과 최대 음성 크기를 적용한다.

## 로컬 자체검증 결과

로컬 fixture는 실제 TTS가 아니라 벤치마크 도구의 정확성과 청크 수신 경로를 확인하기 위한 합성 PCM 서버다.

- 24/24 요청 성공
- TTFA p50 약 46ms
- TTFA p95 약 61ms
- TTFA p99 약 62ms
- 8개 WAV 표본 생성

이 숫자는 공급자 성능 비교 자료가 아니며, 벤치마크 장치가 첫 청크와 전체 응답을 구분해 재현 가능하게 측정한다는 증거다.

결과 위치:

- `output/tts-phase1/benchmark-report.json`
- `output/tts-phase1/samples/`

## 1단계 완료 조건

- 운영 TTS 경로와 이론 지연을 자동 감사한다.
- 공통 한국어 문장으로 후보를 반복·동시성 조건에서 측정한다.
- 첫 바이트와 첫 재생 가능 PCM을 별도로 기록한다.
- 무음·클리핑·포맷 오류와 요청 실패를 기록한다.
- 후보별 블라인드 청취용 WAV를 남긴다.
- 원격 시험에서 인증정보가 설정 파일이나 결과에 저장되지 않는다.
- 테스트와 로컬 자체검증이 통과한다.

## 2단계에서 결정할 것

실제 후보 API를 동일 리전·동일 문장·동일 반복 횟수로 측정한다. 자동 지연 결과와 블라인드 청취를 함께 보고 주 공급자와 예비 공급자를 정한다. 비용, 한국어 상업 이용 조건, 동시 요청 제한도 이때 확정한다.
