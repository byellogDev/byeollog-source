# 별록 핵심 제품 구조

## 제품 범위

- 운영 기능: 풍벽지, 업보
- 실시간 원본: 중앙 SOOP Chat SDK 게이트웨이
- 로컬 Agent 역할: OBS 풍벽지 표시와 상태 동기화만 담당
- 종료 기능: 별록 자체 룰렛, 액션 실행, Weflab 운영 입력
- 임시 검증: 지정된 내부 테스트 워크스페이스의 Weflab 자료만 별도 격리 저장하여 SDK 결과와 대조한다.
- 보존 원칙: 종료 기능의 과거 데이터와 실행 기록은 삭제하지 않는다.

## 실시간 데이터 흐름

1. 중앙 게이트웨이가 워크스페이스별 SOOP 방송 채팅에 연결한다.
2. 후원 이벤트를 내구성 outbox에 SDK 순번과 함께 저장한다.
3. 서버가 후원을 멱등 저장하고 같은 트랜잭션에서 풍벽지 카드를 기록한다.
4. 외부 룰렛 서비스가 채팅에 `룰렛 결과 : 상품명`을 남기면 게이트웨이가 해당 메시지만 서버에 전달한다.
5. 서버가 같은 워크스페이스와 같은 방송 연결 안에서 후원과 결과를 보수적으로 연결한다.
6. 명시된 후원자명, 짧은 연속 결과, 또는 최근의 유일한 미처리 후원일 때만 매칭한다.
7. 후보가 둘 이상이면 임의로 고르지 않고 `ambiguous`로 보관한다.
8. 매칭된 결과는 기존 업보 분류 규칙을 거쳐 업보로 생성된다.

## 정확성 경계

- 후원과 결과는 `workspace_id + broadcast_key` 경계 밖으로 절대 연결하지 않는다.
- outbox 파일명 순서가 아니라 SOOP SDK `connection.sequence` 순서로 전송한다.
- 스트리머 계정이 룰렛 결과를 작성하므로 채팅 작성자 ID를 후원자 ID로 간주하지 않는다.
- 모든 후원, 풍벽지 카드, 업보 생성에는 공급자 이벤트 기반 멱등 키를 사용한다.
- 다회 룰렛은 첫 결과가 연결된 뒤 30초 이내의 끊기지 않은 결과만 같은 후원에 이어 붙인다. 더 최근의 미처리 후원이 있으면 자동 연결을 중단한다.

## 장애 처리

- 게이트웨이에서 서버 전송이 실패하면 암호화 outbox에 남겨 재시도한다.
- 영구적으로 잘못된 이벤트만 제한 횟수 후 dead letter로 격리한다.
- 업보 처리 실패는 수집 이벤트를 잃지 않고 staging에 남겨 재처리한다.
- Agent가 꺼져도 중앙 수집과 업보 기록은 계속된다. Agent가 다시 켜지면 서버 풍벽지 스냅샷을 동기화한다.
- SOOP 재인증이 필요한 상태와 단순 방송 종료 상태를 분리한다.

## Weflab 그림자 검증

- Weflab 자료는 풍벽지·업보·통계 처리 대기열에 넣지 않는다.
- 검증 자료는 서비스 역할만 접근 가능한 별도 테이블에 보관한다.
- 서버 환경 변수로 명시한 워크스페이스만 업로드를 허용한다.
- 일반 Agent에서는 수집하지 않으며, 검증 PC에서만 로컬 환경 변수로 임시 활성화한다.
- 최소 3회 방송과 룰렛 결과 100건 이상을 확보하고, 다회 룰렛·후원 겹침·게이트웨이 재연결 사례를 각각 포함할 때까지 유지한다.
- 위 표본에서 누락·중복·오매칭이 없음을 확인한 뒤 검증 수집과 관련 자원을 함께 제거한다.

## 성능 원칙

- 일반 채팅은 중앙 서버로 보내지 않는다. 후원과 명시적인 외부 룰렛 결과만 전달한다.
- 후원 hot path에는 룰렛 애니메이션, TTS, 액션 실행을 포함하지 않는다.
- 매칭 조회는 워크스페이스, 방송 연결, 시간순 부분 인덱스를 사용한다.
- 내부 상관관계 원본은 30일 뒤 작은 배치로 정리한다. 영구 보존 대상인 후원, 풍벽지, 업보 데이터는 삭제하지 않는다.

## 배포 순서

1. Supabase 마이그레이션 적용
2. Vercel 웹/API 배포
3. 중앙 SOOP 게이트웨이 배포
4. 풍벽지 전용 Agent 빌드 및 단계 배포
5. 방송 전 대기 상태, 후원 1건, 다회 룰렛, 모호한 동시 후원 시나리오를 확인

이 순서를 지키면 웹이 아직 존재하지 않는 RPC를 호출하거나 구형 게이트웨이가 폐기된 실행 경로를 호출하는 중간 상태를 피할 수 있다.
