# 시그니처 별풍선과 공통 오버레이 운영 메모

## 완료 범위

- 대시보드에 `시그풍` 탭을 추가했다.
- 같은 별풍선 개수에는 시그풍 하나만 등록할 수 있다.
- PC 이미지와 모바일 이미지를 각각 등록하며, 현재 OBS 출력에는 PC 이미지를 사용한다.
- 풍벽지용 이미지는 사용자가 따로 고르지 않는다. PC 원본을 320×240 투명 캔버스의 아래쪽에 맞춰 서버가 자동 파생하고, 룰렛 결과 슬롯이 붙은 세레모니 이미지와 저장 경로를 공유하지 않는다.
- 룰렛 화면의 `공통 OBS 주소 복사`로 룰렛·시그풍이 함께 출력되는 주소를 발급한다.
- 브라우저 소스는 최대 출력 봉투인 460×450으로 추가하고 위치·최종 크기는 OBS에서 직접 조절한다.
- 짧은 알림과 긴 후원 메시지 모두 같은 460×450 경계를 사용해 재생 중 소스 크기가 흔들리지 않는다.
- 기존 웹 오버레이 배치 화면, 배치 저장, OBS 위치 미리보기 실행 경로는 제거했다.

## 후원 이미지 결정 순서

1. 후원 별풍선 개수와 정확히 일치하는 별록 시그풍 PC 이미지
2. SOOP Chat SDK `BALLOON_GIFTED` 이벤트의 `imageUrl`

시그풍은 비공개 Storage 객체이며 오버레이 명령을 가져갈 때 15분짜리 서명 URL로 변환한다. SOOP URL은 HTTPS와 SOOP·AfreecaTV 공식 자산 도메인만 허용한다. 등록 시그풍 로딩이 실패하면 같은 이벤트에 SOOP이 전달한 `imageUrl`로 전환한다. 그 URL까지 없거나 실패하면 이미지 영역을 숨기며, 별록이 임의 대체 이미지를 생성하거나 업로드하지 않는다.

## 풍벽지 이미지 선택과 생성 기준

풍벽지는 공통 OBS 세레모니의 이미지 선택 순서와 구분한다. 수집 시점에는 아래 우선순위로 원본 스냅샷을 기록한다.

1. 후원 별풍선 개수에 걸린 활성 룰렛 이미지
   - 단일 룰렛 금액이면 활성본의 `customSingleImage`
   - 연속 룰렛 금액이면 활성본의 `customSeriesImage`
2. 후원 별풍선 개수와 정확히 일치하는 시그니처 이미지
3. SOOP Chat SDK 후원 이벤트의 `imageUrl`
4. SOOP 기본 별풍선 이미지

룰렛이 걸린 별풍선 개수에는 시그니처를 중복 등록하지 않는 것이 운영 기준이지만, 데이터가 겹치더라도 룰렛 이미지가 항상 우선한다. 이미지 내부에 적힌 숫자나 파일명으로 용도를 추측하지 않고, 활성 룰렛의 금액 필드와 시그니처의 `balloon_count`를 각각 확인한다.

선택한 원본은 `buildSignatureWallpaperBuffer`와 같은 규격으로 회전 정보를 적용한 뒤 320×240 투명 캔버스에 `contain`·하단 정렬하고, 새 그림을 생성하거나 원본을 자르지 않는다. 이후 후원자 이름과 실제 후원 별풍선 개수를 붙여 풍벽지 타일 1건을 만든다.

표시 단계에서는 과거 스냅샷의 이미지가 달라도 해당 별풍선 개수에 현재 등록된 시그니처 이미지를 최우선으로 강제 적용한다. 현재 시그니처가 없으면 활성 룰렛 이미지, 최근 수집된 SOOP 이미지, SOOP 기본 이미지 순으로 통일한다. 따라서 시그풍이 방송 중 바뀌어도 이전 후원과 새 후원이 이미지 차이로 나뉘지 않으며, 같은 별풍선 개수는 하나의 묶음으로 유지된다.

묶음의 각 열은 맨 위 이미지와 겹친 후원자 행으로 보이며, 일반 묶음은 왼쪽 아래부터 위로 쌓이고 마지막 미완성 열도 하단에 붙는다. 같은 묶음의 열 간격은 0px, 자동 묶음 간격은 2px이다. 수동 편집에서는 묶음끼리 겹칠 수 있고 저장한 z축 순서와 좌표를 웹 미리보기와 OBS가 함께 사용한다. 선택한 묶음은 위·아래·좌·우와 네 모서리의 8개 핸들로 크기를 조절하며, 카드가 작아지면 후원자명·개수 글꼴과 테두리가 카드 크기에 맞춰 자동 축소된다. 편집 중에는 실제 열 옆에 반투명 `다음 열`을 보여주고 해당 열·행 수용량까지 저장하므로 이후 후원이 표시한 자리로 들어간다.

`숨김/합병 관리` 팝업에서 숨김 리스트와 사용자별 합병 리스트를 관리한다. 합병 범위는 `1-9, 30-50`처럼 저장하며 각 범위는 한 박스가 된다. 합병 박스 안에서는 별풍선 개수별로 나눈 뒤 우측 하단부터 위·왼쪽 방향으로 쌓는다. 숨김은 원장을 삭제하지 않는 렌더 필터다.

라이브 여부는 45초 안의 최신 게이트웨이 heartbeat와 `connected` 상태를 함께 확인한다. 풍벽지에서만 SOOP 공식 재연결 기준 15분보다 넉넉한 20분을 적용해, 업데이트나 튕김 뒤 20분 안에 다시 연결되면 같은 사용자 표시 방송으로 유지한다. 새 실제 방송이 시작되면 현재 방송이 기본 선택되고 사용자가 이전 회차를 추가로 선택할 수 있다.

### 검증 사례: 테스트 스트리머 33개 룰렛

- 수신 후원: `viewer_example`이 `streamer_example`에게 별풍선 33개 후원
- 활성 룰렛: `balloonsPerSpin=33`
- 선택 원본: 활성 룰렛의 `customSingleImage`
- 검증 SHA-256: `a31e46ec80d525f49c0f474ad60e99c12acd6d8699257dccf4d3a68860b8be57`
- 타일 문구: 후원자 `별빛테스터`, `별풍선 33개`
- 시그니처와 SOOP 이미지는 룰렛 원본이 존재하므로 선택하지 않음

이 사례에서 이미지 내부의 `33` 표기와 별도로, 등록된 시그니처 행의 `balloon_count=100`은 선택 대상이 아니다. 풍벽지 선택은 반드시 위 우선순위와 실제 후원 금액을 함께 적용한다.

## 실행 구조

```text
SOOP Chat SDK
  → 별록 gateway 정규화(imageUrl 포함)
  → 서비스 전용 v3 RPC(멱등 후원 저장 + 이미지 우선순위 결정)
  → 공통 outbox(roulette_spin / donation_ceremony / donation_chat_tts)
  → 단일 OBS 브라우저 소스
```

룰렛 대상 후원은 짧은 세레모니 프리롤 뒤 3초 룰렛과 결과 슬롯을 재생한다. 룰렛 대상이 아닌 후원도 세레모니 명령을 같은 소스로 받을 수 있다.

## 이번 점검에서 즉시 반영한 보안·성능 조치

- 시그풍 테이블은 RLS를 켜고 `anon`·`authenticated` 권한을 명시적으로 차단했다.
- 등록·수정·삭제와 후원 v3 RPC는 `service_role`만 사용할 수 있다.
- 업로드 파일 경로를 워크스페이스와 PC·모바일 용도에 묶고, 실제 바이트 시그니처·크기·SHA-256을 서버에서 재검증한다. 풍벽지 경로는 서버 자동 변환기만 쓸 수 있다.
- 오버레이 CSP의 광범위한 `https:` 이미지 허용을 제거하고 Supabase 프로젝트와 SOOP 공식 자산 도메인만 허용했다.
- 시그풍 목록의 서명 URL을 이미지마다 개별 발급하던 구조를 한 번의 일괄 요청으로 줄였다.
- 시그풍 탭은 룰렛 초안·Agent 장치·액션 규칙을 초기 로딩하지 않는다.
- 사용이 끝난 웹 배치 DOM·스크립트·CSS를 제거했다.

## 기능 변경 가능성이 있어 보고만 남긴 항목

아래 항목은 기존 사용 경험 또는 구형 Agent 계약에 영향을 줄 수 있어 이번 작업에서 바꾸지 않았다.

1. 공통 오버레이 주소의 수명주기는 아직 활성 룰렛 서비스에 묶여 있다. 향후 룰렛 없이 시그풍·구독 알림만 쓰는 사용자를 지원할 때는 `공통 알림 서비스`로 소유권을 일반화해야 한다.
2. Supabase Advisor는 과거 `authenticated` 클라이언트가 호출할 수 있는 일부 레거시 `SECURITY DEFINER` RPC를 경고한다. 구형 Agent 의존성을 조사한 뒤 버전별로 권한을 회수해야 한다.
3. Supabase Auth의 유출 비밀번호 차단 기능이 꺼져 있다. 로그인 거부 경험이 바뀔 수 있으므로 공지·지원 절차와 함께 켜는 것이 안전하다.
4. `@supabase/supabase-js`, `@vercel/functions`는 현재 고정 버전보다 최신 버전이 있으나 알려진 취약점은 없다. 실방송 회귀 테스트 없이 한 번에 올리지 않는다.
5. 모바일 이미지는 현재 저장·관리만 하며 OBS는 PC 이미지를 사용한다. 모바일 공개 화면이 정해질 때 별도 출력 규격을 확정해야 한다.

## 실제 방송에서 남은 검증

- 같은 별풍선 개수의 등록 시그풍이 SOOP `imageUrl`보다 먼저 표시되는지
- 미등록 개수에서 실제 SOOP `imageUrl`이 표시되는지
- 등록 시그풍이 만료되면 SOOP `imageUrl`로 전환되고, SOOP 이미지도 실패하면 이미지가 숨겨지는지
- 룰렛 대상 후원에서 세레모니 프리롤 → 3초 룰렛 → 결과 슬롯 → TTS 순서가 맞는지
- OBS 소스를 두 곳에서 동시에 열었을 때 단일 소비자 잠금과 복구가 정상인지
