# 백업·안정화 작업 결과 (2026-09-06)

## 결론

공개 배포 경계, 데이터베이스 백업·복구 원자성, 현재 제품 핵심 경로 회귀시험, 운영 관측·롤백 기준까지 구현하고 검증했다. 다만 자동백업 스케줄의 실제 운영 실행은 아직 신규 백업 파일로 입증되지 않았다. 이 항목은 수동 Cron 실행 또는 다음 예약 실행 뒤 별도로 확인해야 한다.

- 내부 소스·마이그레이션·운영 스크립트가 공개 산출물에 섞이면 테스트와 배포 가드가 실패한다.

## 2. 백업·복구 — 코드와 격리 복구 통과 / 예약 실행 증거 대기

### 적용 사항

- 백업 형식을 v8로 확장해 현재 제품의 영구 데이터 18개 테이블을 한 PostgreSQL 스냅샷에서 추출한다.
- 복원은 단일 트랜잭션 RPC에서 수행한다. 워크스페이스 소유권, 허용 테이블·컬럼, 중복 키, 참조 관계를 먼저 검증하며 하나라도 실패하면 전체를 롤백한다.
- 백업 실행 임대(lease), 안전백업 선행, 보존기간 정리, 압축 해제 상한(64 MiB)을 유지한다.
- 백업 오류 로그에는 제한된 오류 코드와 실행 종류만 남기며 원문 오류·토큰·본문은 남기지 않는다.
- `/api/backups`의 최대 실행 시간을 60초로 명시했다.

### 검증 증거

- PostgreSQL 17 격리 복구: 18개 테이블 신규 복원, 반복 복원, identity 보존, 중간 실패 전체 롤백, 교차 워크스페이스·잘못된 참조 거부 통과.
- 운영 DB 읽기 전용 v8 내보내기: 활성 워크스페이스에서 18개 테이블이 모두 반환됨을 확인했다. 운영 복원은 실행하지 않았다.
- 전체 서버 테스트: 578/578 통과.
- 현재 저장소의 최신 실제 일일백업: 2026-08-18. 따라서 새 Cron 경로의 실제 파일 생성 여부는 아직 통과 처리하지 않는다.

### 의도적으로 제외한 범위

- DB에는 이미지 파일의 경로·해시·메타데이터가 백업되지만 Supabase Storage의 이미지 원본 바이트는 이 백업에 복제하지 않는다.
- Agent PC의 브라우저 로컬 미디어도 서버 백업 범위가 아니다.
- 원본 바이트 복제는 저장 용량, 보존 정책, 복구 우선순위에 영향을 주므로 별도 설계·승인 없이 활성화하지 않는다.

## 3. 현재 제품 핵심 경로 회귀시험 — 통과(명시된 한계 제외)

- 서버 전체 테스트 578/578 통과.
- Agent 소스 검증 1,052개 assertion 통과.
- 숨김 WebView2 통합 사전검증 통과:
  - 회차 선택 순차 토글 36회
  - 느린 ACK 조건의 빠른 토글 54회
  - 오프라인 배치 유지
  - 계정 문서 재로딩 8회
  - 로컬 HTTP 오버레이 상태 일치

### 검증 한계

- WebView2 검증의 원격 전송부는 모의 환경이다. 실제 사용자 설치판과 실제 OBS에서의 최종 확인을 대체하지 않는다.
- 운영 사용자는 현재 소수이므로 500명 동시 사용 용량을 입증하지 않는다.
- 일일백업은 활성 워크스페이스를 순차 처리한다. 현재 규모에서는 허용되지만 500명 규모 전에 큐/분할 실행을 설계해야 한다.

## 4. 관측·롤백 기준 — 확정

- 운영 로그는 비밀값·요청 본문·백업 내용 없이 경계가 정해진 코드와 결과 수치만 기록한다.
- 배포 후에는 읽기 전용 스모크와 Vercel 런타임 오류를 확인한다.
- 웹 코드 긴급 롤백 1순위는 `dpl_2ZXy5zZJogMQqutQ3LPhc3UYj7sk`이다. 이 배포는 공개 파일 allowlist와 v8 백업 경로를 모두 포함한다.
- 더 이전으로 내려야 할 때에도 공개 파일 allowlist가 포함된 `dpl_BtZor3tAG1gvm18bmy84do2WE18q`보다 오래된 배포는 사용하지 않는다.
- v8 데이터베이스 함수는 추가형이며 기존 v7 경로와 공존한다. 웹 롤백을 위해 파괴적 DB 롤백을 수행하지 않는다.

## 남은 확인 순서

1. Vercel Cron을 한 번 수동 실행하거나 다음 예약 실행을 기다린다.
2. 실행 직후 활성 워크스페이스별 신규 v8 일일백업 생성, 실패 수 0, 로그 비밀값 부재를 확인한다.
3. 운영 데이터에는 복원하지 않고, 생성된 백업 중 하나를 격리 DB에 복원해 행 수·참조 무결성을 다시 비교한다.
4. 이미지 원본 바이트까지 별도 보존할지 비용과 복구 목표를 정한 뒤 독립 작업으로 결정한다.
