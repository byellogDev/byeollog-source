# 기술 사례: 운영 소스 통합과 반복 장애 개선

## 목적

운영 중인 방송 지원 서비스를 유지하면서, 여러 작업 폴더에 분산된 코드를 하나의 검토 가능한 기준으로 모으고 반복 경고·불필요한 재시도를 줄이는 작업입니다.

## 발견과 해결

### 방송 대기를 장애로 판단하는 시간 불일치

방송 대기 상태의 heartbeat는 300초 간격인데 상태 표시가 120초를 기준으로 오래된 연결로 판단했습니다. 대기 상태만 360초 허용하도록 맞추고, 연결 중인 상태의 120초 기준은 유지했습니다. 회귀 검사에서 상태별 경계값을 확인했습니다.

### 정상 오프라인 상태의 빠른 재시도

SDK가 방송 오프라인을 반환할 때 재시도 간격이 빠져 반복 주기가 1초로 돌아갈 수 있었습니다. 정상 방송 대기에 30초 간격을 명시하고 예상된 오프라인 경고를 줄였습니다. 그 밖의 오류는 계속 기록합니다.

후보에서 오프라인 100회 반복 시 재시도 값이 유지되는지 검사했습니다. 방송 시작 감지는 다음 대기 주기까지 늦어질 수 있습니다. 연결된 방송의 이벤트 처리 속도를 바꾸는 수정은 아닙니다. CPU 절감률은 측정하지 않았습니다.

### 운영 회귀를 막는 소스 기준

사용자가 인정한 운영본을 봉인하고 1,183개 파일을 새 구조와 대조했습니다. 그중 변경된 운영 파일은 위 두 문제를 해결하는 3개입니다. 화면 응답을 해시로 비교하고, 실제 배포 후 백업 조회와 수집기 상태를 확인했습니다.

## 설계 선택

- 소스 관리 위치를 통합하되 서비스별 권한·의존성은 보존했습니다.
- 오래된 코드의 일괄 병합보다 현재 운영 코드와 명시적 수정 목록을 기준으로 삼았습니다.
- 검사에 필요한 과거 코드는 테스트 자료로 격리했습니다.
- 결과를 자동 검사, 직접 조회, 사용자 확인으로 나누어 기록했습니다.
