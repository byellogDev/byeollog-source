# 위플랩 실방송 결과 비교 · 2026-10-09

## 판정

2026-10-08 저녁 시작해 10월 9일 새벽 종료한 대상 방송에서 **기존 수집 후원 19건·1,241개와 새 경로의 19건·1,241개, 룰렛 결과 7건이 모두 일치**했다. 이번 방송의 수집 내용 비교는 통과다. 전체 사용자 운영 전환이나 시험 자료의 운영 업보 합산은 하지 않았다.

| --- | ---: | ---: | --- |
| 후원 건수 | 19 | 19 | 19건 모두 유일하게 대응 |
| 별풍선 합계 | 1,241 | 1,241 | 일치 |
| 룰렛 결과 | 7 | 7 | 후원별 결과 문자열·건수 일치 |

| 룰렛 요청 예약·완료 | — | 7 / 7 | 모두 단일 회차 |

## 범위와 근거

- 10월 9일 03시대 KST 사용자의 방송 종료 보고 후 읽기 전용으로 확인했다. 방송 시작 기록은 10월 8일 19:02 KST다. 풍벽지 세션의 closed_at은 아직 비어 있어 DB만으로 정확한 방송 종료 시각을 확정하지 않는다.
- 같은 계정과 같은 broadcast_key의 후원·결과를 사용했다. 읽기 구간은 10월 8일 15:00~10월 9일 03:00 KST이며, 실제 후원 발생은 **10월 8일 19:41:00~10월 9일 01:41:12 KST**다. 자정 전후를 나누어 일부만 비교하지 않았다.
- Supabase에서 계정 한정 전체 배열을 저장했고 사전 count 집계와 내역 수를 대조했다. 이전 방송 자료는 제외했다. 원문·식별자·URL·DB 자료는 비공개 `.local`에만 보관했다.
- 후원 19건의 source와 조회 7건의 request_worker는 모두 Agent였다. 해당 계정의 Windows Agent **1.0.0.52**, 마지막 상태 보고 10월 9일 02:59:38 KST도 확인했다. 설치 완료를 추정하는 수준을 넘어 새 Agent 경로의 실제 수집이 확인됐다.
- 확인 시 서버는 owner·ready이며 최근 오류 표시 없음, 전송 대기 0건이었다. 원격 실행 소스 해시는 정식 기록과 일치했다. 서버 증거가 0건인 것은 계정 전체 수집이 0건이라는 뜻이 아니며, 실제 후원 자료는 Agent가 별도 DB로 전달했다.

## 대응 방식과 실제 결과 검증

1. 계정, 후원자 ID, 수량, **위플랩 원문 발생 시각과 기존 occurred_at의 1초 이내 차이**로 양방향 유일 대응을 요구했다. 금액만 같다고 짝짓거나 가까운 항목을 순서대로 소비하지 않았다.
2. 19건의 실제 시각 차이는 **11~77ms**였다. 같은 후원자의 같은 금액 연속 후원도 모두 구분됐다. 처음의 DB 저장 시각 ±120초 비교에서 모호했던 9건은 결과 불일치로 세지 않았고, 원본 발생 시각 근거로 구분했다.
3. 저장된 후원 당시 규칙으로 요청 계획을 다시 구성해 requestHash와 job_key가 같은지 확인했다. 제공자 API를 다시 호출하지 않았다.
4. 보존된 **원본 응답 7건**을 재해석하고 저장된 assessment와 대조했다. 모두 `api=sql`로 저장 결과를 반환했으며 `save` 응답 0건이다. 이 응답 관측을 제공자 내부 동작 전반에 대한 보증으로 확대하지 않는다.
5. 각 후원에 연결된 기존 결과와 위플랩 결과 배열의 **문자열을 그대로 비교해 7/7 일치**했다. 모든 요청 count가 1이므로 다회 룰렛 내부 순서는 이번에 검증되지 않았다.
6. 나머지 12건은 당시 활성 룰렛 규칙에 해당하지 않았고, 기존 경로에도 룰렛 결과가 없었다. 실패 또는 누락 12건이 아니다. 현재 계획기의 `ambiguous_rule` 사유는 규칙 0개와 여러 개를 함께 표현하므로 기록 해석 시 실제 매칭 규칙 수 0개임을 따로 확인했다.

## 지연과 남은 확인

- 후원 원본 발생부터 시험 DB 첫 저장까지 약 **0.91~10.53초**였다. Agent의 최대 10초 주기 전송을 포함하며, 소켓 자체의 수신 속도가 아니다.
- 시험 DB 첫 저장부터 결과 요청 예약까지 **182.6~183.4초**였다. 승인된 180초 지연 조회에 따른 동작이다.
- 새 결과 저장은 기존 결과 DB 저장보다 약 **179.8~187.3초 뒤**였다. 운영 처리 속도 개선으로 주장하지 않는다.
- 다회 룰렛, 범위 규칙, 규칙 변경, 봇 누락이 실제 발생한 상황에서의 보완 효과는 이번 자료로 확인하지 못했다.
- Agent가 실제 수집했고 이후 서버가 현재 담당권을 보유한 사실은 확인했다. 전체 과거 소켓/담당권 변경 이력과 PC 로컬 원문은 이번 서버 조회에 포함되지 않아 전환 소요 시간·과거 모든 연결 공백이 0이었다고 판정하지 않는다.
- 사용자 요청대로 수집은 유지하고 자동 비교 예약은 재개하지 않았다. 프로세스 재시작·배포·권한 변경·데이터 승격은 수행하지 않았다.
