## 목적과 범위

사용자가 승인한 테스트 계정 하나와 운영 계정 두 개의 기존 수집을 유지하고 관측 전용 경로를 각각 별도 컨테이너에 연결한다. 48시간 후 이벤트 일치, 계정 격리, 자원 비용, 연결 안정성을 기준으로 채택 가능성을 판단한다. 실제 대상 매핑은 비공개 실행 자료에 보관한다. 이 문서는 운영 전환 승인이 아니다.

현재 운영 경로만 이벤트 전달·후원 처리·업보 반영을 수행한다. 후보는 공식 SDK의 인증·입장·keepalive 외 발신을 차단하고 채팅·후원 관련 수신 프레임을 관측한다. DB, outbox, 운영 상태 쓰기 모듈은 불러오지 않는다.

## 측정

| 항목 | 방법 | 해석 한계 |
|---|---|---|

| 혼선 | 계정별 프로세스·컨테이너·인증값 분리, 실제 방 소유자 확인, 계정별 독립 대조 | 합성 음성 대조군과 실제 관측을 구분 |
| 지연 | 같은 프레임의 후보 시각 - 기존 관측 시각 분포 | 네트워크 외 CDP와 관측 경로의 지연도 포함 |

| CPU·프로세스 | 후보 CPU 누계, 각 컨테이너 CPU·메모리·PIDs | 기존 컨테이너에는 큐 처리와 관측 보조 프로세스도 포함 |

CPU·메모리 비교에서 기존 컨테이너 전체를 계정별 순수 브라우저 비용으로 나누지 않는다. 후보에는 실제 DB 전송·내구 큐 비용이 포함되지 않아 완성된 대체 수집기의 자원 절감률로 단정하지 않는다. 실제 500계정 연결도 별도 검증 대상이다.

## 격리와 중단

- 계정별 컨테이너 하나. 비특권 UID/GID, 읽기 전용 파일시스템, capability 제거, 권한 상승 금지, 메모리 256 MiB·CPU 0.25·프로세스 32개 상한.
- 운영 볼륨·Docker 소켓·DB 자격증명은 연결하지 않는다. 운영 이미지의 `VOLUME /var/lib/byeollog` 자동 생성도 tmpfs로 덮어 디스크 볼륨을 만들지 않는다.
- SOOP 자격증명은 메모리와 프로세스 파이프로만 전달한다. 인증값·채팅 원문·후원자 정보는 관측 결과나 공개 저장소에 기록하지 않는다.
- SDK 원본 해시, 기존 고정 `ws@8.21.0` 사용. VM만을 보안 경계로 간주하지 않는다. HTTP·WebSocket 목적지 제한은 코드의 검증이며 호스트 전체 네트워크 방화벽 검증과 동일하지 않다.
- 기존 연결 상태·방 소유자·CDP 종료·감시 응답을 감시한다. 수신 불일치, 자원 압박, 관측 누락, 운영 대기열 증가가 발생하면 후보를 중단한다.
- 감시 프로세스의 표준입력이 끊기거나 heartbeat가 30초 이상 중단되면 후보와 관측 보조 프로세스가 종료한다. 서버 측 실행 시한도 48시간으로 제한한다.
- 독립적으로 확인한 `broadcast_offline`은 방송 대기로 기록하고 기존 연결이 다시 안정된 후 관측을 재개한다. 설명되지 않은 오류는 자동 반복하지 않고 해당 계정을 점검 대기로 남긴다.
- 프레임 비교 대기열과 기록 크기에 상한을 둔다. 상한을 넘으면 조용히 버리지 않고 관측 실패로 중단한다.

## 판정 원칙

실제 연결 시간, 세 계정이 동시에 관측된 시간, 계정별 채팅·후원 종류와 건수, 대조 제외 구간을 먼저 산출한다. 수신 불일치·중복·계정 혼선은 0건이어야 하며, 후보 종료·재개로 생긴 공백은 별도 표시한다. 자연 후원이나 방송 재시작이 없으면 해당 항목은 미검증으로 남긴다. 토큰 갱신과 장애 인계를 실제로 확인하지 않았다면 이 결과로 통과 처리하지 않는다.

지속적 RSS 증가, 후보만의 연결 중단, 기존 연결에 미친 영향, 자원 절감의 측정 한계를 함께 검토한다. 48시간 무오류만으로 무기한 안정성이나 500명 수용을 보증하지 않는다.
