# Vercel Pro 비용과 별록 수용량 · 2026-09-26

## 결론

Pro는 무료 사용량 소진으로 인한 중단을 피하고 초과 사용량을 결제할 수 있게 한다. 회원 수나 동시 방송 수를 정해 판매하는 상품은 아니다. 별록 전체의 실제 수용 인원은 아직 부하 시험으로 확정하지 않았다. 특히 결제만으로 현재 NCP 수집 서버의 **2코어·약 8GB 메모리**가 늘어나지 않는다.

## 확인한 운영 자료

- 최근 30일 누적: CPU 약 3.15시간, provisioned memory 51.1GBh, 함수 호출 687,079회, CDN 요청 약 729,114회. 조회 당시 누적값이며 월말 예측이 아니다.
- Tokyo 요율로 CPU 약 $0.64 + 메모리 약 $0.85 + 호출 약 $0.41 = **세 항목 합계 약 $1.90**다. 현재 무료 CPU 한도의 약 79%를 썼다는 사실과 유료 자원 비용이 큰지는 서로 다르다.
- 기존 호출 구성과 지역이 유지되면 이 세 항목의 약 10.5배가 $20에 해당한다. CDN·빌드·기타 자원은 별도다. 고정 작업·개발 트래픽과 사용자 작업이 섞인 값이므로 `현재 사용자 수 × 10.5`를 지원 인원으로 해석할 수 없다.
- NCP 확인 시 전체 서버는 2코어·메모리 약 8GB, gateway 메모리 제한은 6GB였다. 순간 컨테이너 RSS 약 468MiB와 CPU 0.07%는 방송 부하의 최댓값이 아니다. 이 값으로 계정당 자원을 나누어 500명 수용을 계산하지 않는다.

## 현재 공식 요금

Pro는 월 $20에 배포 좌석 하나와 사용 크레딧 $20를 포함한다. 사용량 초과분은 종량 청구한다. [Pro 요금](https://vercel.com/docs/plans/pro-plan).

Tokyo 함수는 CPU $0.202/h, 메모리 $0.0167/GBh, 호출 $0.60/백만 회다. I/O 대기에도 메모리 요금은 발생하고 동시 요청은 인스턴스 메모리를 공유할 수 있다. [Fluid Compute 요금](https://vercel.com/docs/functions/usage-and-pricing).

Flat Rate CDN 적용 시 기본 100만 요청·1TB, 추가 월 $20 구간은 1,000만 요청·50TB, 추가 월 $100 구간은 5,000만 요청·50TB다. 초과 규모에 따라 다음 주기 구간이 달라진다. 실제 전환 시 팀의 Flat Rate 적용 여부와 선택 구간을 확인해야 한다. [CDN 요금](https://vercel.com/docs/pricing/flat-rate-cdn).

## 사용자 수별 조건부 비용 시산

다음은 **성능 검증이나 실제 청구 예측이 아닌 부분 비용 모델**이다. 등록 회원 수가 아니라 매일 아래 조건으로 활동하는 스트리머 수를 뜻한다.

가정:

- 매일 8시간 방송, 16시간 대기, 월 30일.
- 연결 상태 보고는 방송 중 60초·대기 중 300초, 웹 중계를 포함해 상태 보고 한 번당 함수 2회.
- 시간당 처리 이벤트 100건, 이벤트당 함수 2회. 이벤트 배치/추가 처리 차이는 생략한 가정이다.
- 계정당 월 함수 호출 `2 × (8×60 + 16×12) × 30 + 2×100×8×30 = 88,320회`.
- 함수 100만 호출당 CPU·메모리·호출 비용은 관측된 전체 평균 약 $2.77를 그대로 사용한다. 이 평균은 이벤트별 처리 시간이나 큰 백업의 비용을 보장하지 않는다.
- 이 모델에서는 각 HTTP 함수 호출에 CDN 요청도 하나씩 계산한다. 실제 청구는 플랫폼 집계가 기준이다.

| 활동 스트리머 | 모델의 월 호출 | 함수 3항목 | CDN 추가 구간 | 기본료·크레딧 반영 후 부분 합계 |
| --- | ---: | ---: | ---: | ---: |
| 10명 | 88만 | 약 $2.4 | $0 | 약 $20 |
| 50명 | 442만 | 약 $12.2 | $20 | 약 $40 |
| 100명 | 883만 | 약 $24.5 | $20 | 약 $45 |
| 500명 | 4,416만 | 약 $122.3 | $100 | 약 $222 |

계산식은 `$20 + max(0, 함수 3항목 − $20) + CDN 구간 추가료`다. 세금·NCP·Supabase·백업·대시보드/OBS·전체 reconcile·lease 갱신·빌드·저장소·기타 Vercel 항목은 **미포함**이다. 특히 100명 모델은 CDN 1,000만 경계와 가까워 생략한 요청만으로 상위 구간에 들어갈 수 있다. 따라서 위 금액을 전체 예산의 상한으로 삼으면 안 된다. 방송일이나 이벤트가 줄면 내려가고, 복잡한 이벤트·화면 조회·백업이 늘면 올라간다.

**실무 판단:** Pro 기본료만으로 500명까지 된다고 판단할 근거는 없다. Vercel 쪽은 규모에 맞춰 추가 요금을 내는 방식이고, 동시 수집 병목은 별도 NCP/DB 구조에서 검증해야 한다. 현재 자료로는 50명/100명조차 전체 서비스 수용이 검증된 숫자가 아니다.

## 수용 인원을 확정하는 기준

후보 수집기를 별도 환경에서 10→50→100→500 동시 연결로 검사한다. 기존/후보 계정 격리, 이벤트 누락·중복, DB 반영 p95/p99 지연, 큐 증가, 프로세스/스레드 한도, 메모리 상한, 대량 재연결을 함께 측정해야 한다. 운영 서버에 인위적인 500계정 부하를 발생시키지 않았다. 현재 직접 WebSocket 후보의 장기 관측 결과를 곧바로 DB 쓰기·백업·사용자 화면을 포함한 서비스 용량으로 대체할 수 없다.
