# 위플랩 브라우저 없는 결과 조회·서버/PC 인계 후보

후속 변경: [정식 Agent 1.0.0.52와 별도 수집](../releases/2026-10-08-agent-10052-weflab.md). 기존 비교 예약과 원시 관측 타이머는 중지했다. 승인된 180초 지연 자동 조회를 별도 워커가 수행하며, 비교는 방송 후 사용자 요청 시에만 진행한다. 아래는 변경 전 기록이다.

상태: 연구 후보, 운영 미반영. 2026-10-08 07:41 KST 실제 테스트 조회 확인.

## 이번에 확인한 결과

사용자가 화면에서 최종 결과를 확인한 테스트 후원 한 건에 한해 조회하도록 승인했다. 기존 테스트 이벤트의 UID 생성 방식과 정확한 금액 규칙·확률표·회차 수를 원본 페이지 코드에 맞춰 구성했다. 당시 규칙 스냅샷과 현재 선택 규칙 및 요청 해시가 같음을 확인한 뒤 한 번만 요청했다.

- 30개 테스트 후원의 사용자 확인 결과: `꽝`.
- 실제 결과 API 응답: `api=sql`, 저장된 결과 `꽝`, 일치.
- 브라우저·WebView·OBS 실행 없음. 채팅 결과나 별록 DB를 요청 조건으로 사용하지 않았다.
- 테스트 후원 생성은 이전 사용자의 동작이다. 이번 후보가 실행한 결과 요청은 1회이며 운영 후원은 조회하지 않았다.
- 요청 전 근거·규칙·계정 고정값, 전체 API 응답, 판정과 완료 상태는 비공개 `.local`에 보존했다.

이는 브라우저 없는 저장 결과 조회가 실제로 가능함을 확인한 한 건의 증거다. 소켓에서 결과가 푸시된다는 뜻이나 모든 종류의 후원·다회 추첨이 검증됐다는 뜻은 아니다. 이전 [소켓 알림 시험](2026-10-08-weflab-displayed-results.md)과 다른 경로다.

## 구조와 구현

`tools/weflab-lab/browserless-core.mjs`는 원본 이벤트에서 요청을 구성하고 계정별 담당권 및 후원별 요청 예약을 관리한다. `browserless-service.mjs`는 인증된 중앙 RPC와 fsync 저널을, `browserless-worker.mjs`는 서버/PC에서 공통으로 쓸 조회 워커와 주기적 담당권 처리를 제공한다.

1. 수집 연결이 준비된 서버가 기본 담당한다.
2. Agent의 수집 연결이 준비되면 서버는 새 결과 조회를 멈추고 진행 중 요청을 마무리한 뒤 담당권을 해제한다. 다음 Agent 주기에 인계한다.
3. Agent가 사라지면 마지막 갱신 기준 15초 유효기간 후 서버가 담당할 수 있다. 기본 통합 권장 주기는 3초이며, 실제 인계 지연은 주기·네트워크·요청 시간에 따라 달라진다.
4. 이전 담당자가 늦게 보내는 완료 요청은 세대·토큰으로 거절한다. 후원별 조회 예약은 담당권과 별도로 남아 새 담당자가 같은 요청을 반복하지 못한다.
5. 불확실한 요청은 자동 재시도하지 않는다. 응답 원문이 로컬에 있으면 조사할 수 있으며, 원문도 없는 타임아웃은 미확인 상태로 보존한다.

연결 준비 신호는 호스트의 실제 수신 연결 상태에서 공급해야 한다. 프로그램 실행 여부만으로 준비 완료라고 처리하지 않는다. 두 워커의 주기 처리는 HTTP 통합 검사로 확인했지만 **기존 Windows Agent에 준비 신호·전송·실행 수명주기를 연결하거나 패키징한 상태는 아니다.** 운영 계정 인증 API와의 연결도 남아 있다.

## 계정·중복·진단 보호

- 중앙 서비스 한 개가 한 계정을 담당하며 서버/Agent에 서로 다른 비밀값을 부여한다. 클라이언트가 보낸 계정·계획을 신뢰하지 않고 운영자가 등록한 테스트 계획만 조회한다.
- 요청 예약을 디스크에 동기 저장한 후 외부 요청한다. 저장 실패 시 프로세스 내 조정 기능도 차단한다.
- 재시작해도 예약은 유지한다. 다른 규칙으로 같은 후원을 다시 요청하거나 잘못된 결과를 완료 처리하지 못한다.
- 중복 중앙 프로세스는 배타 잠금으로 차단한다. 비정상 종료의 잠금·미완성 저널은 자동으로 지우지 않고 점검한다. 저널 한도는 64MiB이며 초과 시 중단한다.
- 원본 응답은 별도 비공개 파일에 먼저 저장한다. 공개 오류에는 비밀값·URL·후원 원문을 넣지 않는다.
- 후보 RPC는 loopback에만 바인딩한다. 서버/PC 사이 실사용은 인증된 암호화 터널 또는 제품 인증 API에 연결해야 한다. 평문 공용 포트로 공개하지 않는다.
- 중앙 서비스 자체가 끊기면 새 결과 요청도 멈춘다. 이번 구조는 수집 위치 인계이며 중앙 제어 서버의 고가용성까지 구현한 것은 아니다.

## 검증과 미검증

`node --test tests/weflab-browserless.test.mjs tests/weflab-observation.test.mjs`: 28건 통과. 신규 15건과 기존 관측 회귀 13건이다. 계정 격리, 서버 기본/Agent 우선, 준비 전 대기, 인계·복귀, 동시 Agent, 오래된 담당 거절, 재시작 후 중복 방지, 타임아웃, 저장 실패, 원문 보존, 잘못된 규칙·회차·응답을 검사했다. 두 역할은 같은 PC의 HTTP 통합 테스트이며 실제 원격 PC 장애 시험은 아니다.

실제 조회는 위의 완료된 테스트 후원 한 건뿐이다. 현재 API는 결과가 없으면 `save`로 추첨을 생성할 수 있다. `save` 응답을 검증 실패로 처리하는 것은 **생성을 예방하는 보장과 다르다**. 방송 화면의 처리 완료를 기다렸다는 시간 가정만으로 운영 자동 조회를 열지 않는다. 현 후보는 운영 후원을 명시적으로 거절하며, 승인된 테스트 계획만 허용한다.

남은 제품 과제는 실제 연결 준비와 Agent 수명주기 통합, 서버 배포·암호화/계정 인증 연결, 후원 intake와 결과 전송의 영속 큐, 인계 중 수신 공백 대조, 다회/범위 규칙 검증, 운영 자동 요청의 생성 부작용 처리 기준이다. 이번 결과로 이 항목들을 완료 처리하지 않는다.

기존 10월 9일 예약 관측은 수신 전용으로 유지했다. 운영 경로·사용자 데이터·SOOP WebSocket 연구·권한·배포·자동화를 변경하지 않았다. 브라우저 없는 구조 선택 전 작성한 WebView 실험은 비공개 보관으로 옮겼고 Agent 소스에 포함하지 않았다.
