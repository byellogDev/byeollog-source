# 위플랩 독립 결과 수신 경로 조사

## 목표와 확인한 사실

후보는 기존 별록/SOOP 수집 결과를 기다리지 않고 후원과 최종 결과를 받아야 한다. 기존 경로는 검증 기간의 사후 대조 기준일 뿐이다. 앞선 확정 결과 조회 도구는 진단용이며 독립 수집기가 아니다.

2026-10-08 공식 `main.js?ver=20261003210115`를 다시 GET했다. 이전 사본과 동일하며 SHA-256은 `a92646704a5fb478dd32de683045eeb5ef4108a59061abe7a06865381d6e890e`다. 제3자 원본은 저장소에 복제하지 않는다.

- `socket.receive`는 `alertlist` 및 `roulette` 메시지를 후원 관리 화면으로 전달한다.
- 관리 화면은 결과 데이터의 `uid`에 해당하는 후원을 찾아 `roulette`, `percent`, `list`를 표시한다. 다회 결과 목록도 처리한다.
- 이것은 **결과 알림을 처리하는 클라이언트 코드**의 증거다. 제공된 후원알림 URL 권한으로 그 결과 채널을 구독할 수 있다는 증거는 아니다. 서버 인증·배포 코드는 미확인이다.
- 후원알림 화면의 허용 이벤트에 `chat`도 있다. 위플봇 결과 채팅이 이 연결에 전달된다면 기존 SOOP 수집기 없이 파싱할 수 있다. 실제 전달, 봇 발신자 확인, 후원 연결, 결과 채팅 OFF 상태는 미검증이다.
- 실제 표시 브라우저는 추첨 API의 응답을 받아 화면을 만든다. 그 응답을 복사하면 별도 추첨 요청은 필요하지 않다.
- 조사한 스크립트에는 외부 iframe으로 결과를 전송하는 `postMessage` 경로가 보이지 않았다. iframe만 추가하면 내부 결과를 읽을 수 있다고 가정하지 않는다.

## 테스트 계정 한정 실험

| 요청 | 관측 결과 | 판단 |
| --- | --- | --- |
| 이전 테스트 ID, 수량·횟수·확률표 생략 | HTTP 200, noparam | 저장 결과 조회 불가 |
| 새 합성 ID, 동일 생략 | HTTP 200, noparam | 매개변수 누락 거절 |
| 이전 테스트 ID, 수량/횟수 포함, 빈 확률표 `{}` | HTTP 200, api=save, 빈 결과 및 빈 목록 항목 | 빈 표로 생성을 막을 수 없음. 추가 호출 중단 |

실제 방송 계정에는 결과 API를 호출하지 않았다. 마지막 요청은 서버측 상태 변경 가능성이 있는 요청으로, 읽기 전용 성공으로 기록하지 않는다. 이전 정상 테스트 응답은 별도로 보존했다. 기존 ID가 save로 처리된 원인은 캐시 키·확률표·보관 기간 등 서버 내부를 확인하지 않아 확정할 수 없다. UID만 같으면 항상 기존 결과를 반환한다는 보장도 하지 않는다.

## 해결 방향

| 방향 | 기존 수집 의존 | 남은 조건 |
| --- | --- | --- |
| 결과 전용 알림 구독 | 없음 | 정당한 URL/권한으로 결과 채널 수신, UID·다회 결과 대조 |
| 위플랩 연결의 봇 결과 채팅 파싱 | 없음 | 해당 연결의 실제 전달, 봇/후원 식별, 봇 설정 의존 확인 |
| 실제 표시 브라우저의 응답 복사 | 없음 | 그 브라우저에 Agent/지원 관측 기능 연동 |
| 일정 시간 후 추첨 API 재호출 | 결과 존재의 외부 근거 필요 | 재생성 방지 보장 부족으로 독립 수집 해법에서 제외 |

우선 URL 중심 구조를 유지할 수 있는 결과 알림과 채팅 전달을 검증한다. 관리 채널에 로그인한 것처럼 위장하지 않는다. 별도 후원 관리 공유 주소가 필요하다면 사용자가 실제 제공한 주소로 검증한다.

대안은 **방송에 사용되는 렌더러 하나의 실제 응답을 관측**하는 것이다. 오버레이를 별도로 하나 더 실행하면 추첨 경쟁이 재발할 수 있다. Agent WebView2에서 렌더링한다면 OBS 표시·투명도·음성 전달까지 별도 구현 범위다. OBS 브라우저를 그대로 관측하는 방식은 설치 버전의 지원과 로컬 접근 제한을 확인해야 한다. 일반 OBS WebSocket 연결만으로 응답 본문을 얻을 수 있다고 가정하지 않는다.

## 수락 조건과 운영 상태

후보는 기존 DB 조회 없이 후원 UID와 결과를 받아야 한다. 단일/다회 결과, 중복, 순서 역전, 재연결, 방종을 구분해 실제 화면과 대조한다. 추가 추첨·결과 변경·봇 결과 누락·계정 혼선이 없어야 하며 후보의 결과 생성 API 호출은 0회여야 한다.

이번에는 코드 분석과 제한된 API 실험만 했으며 독립 결과 수신 성공을 선언하지 않는다. 10월 9일 19시 예약은 후원 수신과 원문 보관 연구로 유지한다. 운영 코드·권한·데이터·OBS 변경 없음.
