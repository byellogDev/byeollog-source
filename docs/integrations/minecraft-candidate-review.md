# Minecraft 인계 검토와 운영 전제 · 2026-09-24

## 인계 결과

이번 인계까지는 마크 메인 1에서 기능 구현·로컬 검사 후 별록 canonical 저장소로 넘겨 선택 병합과 후보 검증을 수행했습니다. **2026-09-24 사용자 결정으로 앞으로 별록↔마크 연결 모듈은 별록 프로젝트에서 직접 개발·검증·빌드·배포합니다.** 별록에 배포할 코드를 다른 작업 공간에서 만든 뒤 다시 옮기는 과정을 없애기 위한 변경입니다. 최신 SOOP 인증 파일이나 배포 폴더를 과거 사본으로 통째로 교체하지 않습니다.

양쪽은 API·이벤트 형식과 검증 결과를 맞춥니다. 별록용 연결 코드를 마크 프로젝트에서 별도 사본으로 개발해 다시 가져오는 방식을 앞으로의 기본 절차로 사용하지 않습니다. 이번 결정은 담당 범위를 바꾸는 것이며, 파일 이동이나 미구현 후원 전달 기능의 배포를 수행한 것은 아닙니다.

현재 후보에서는 프록시 헤더 누락, 발급 응답 유실 후 키 삭제, 공유 OAuth 콜백 충돌, 잘못된/과도한 요청 본문, 만료 세션 처리 문제를 수정했습니다. [검증 기록과 미검증 범위](../releases/2026-09-24-minecraft-candidate.md)를 운영 승인 판단의 기준으로 사용합니다.

## 요청 제한과 자료 정리 정책

아래는 상시 활성화 전 적용할 정책이며 **현재 적용됐다는 뜻이 아닙니다**.

| 항목 | 현재 코드에서 확인한 동작 | 상시 활성화 전 기준 |
| --- | --- | --- |
| 요청 제한 | Minecraft 조회에 전용 분산 제한 없음 | 인증된 서버별 분당 60건을 초기 상한으로 적용하고 429·재시도 안내를 검증. 실제 동시 입장 규모에 따라 측정 후 조정. 인증 실패에도 별도 IP 제한 필요 |
| nonce | 서버별 다음 유효 요청에서 만료 nonce 삭제. 저장 시 만료 10분. 허용 timestamp ±5분 | 미사용 서버의 잔여 항목도 정기 삭제. 만료 전 삭제는 금지. 만료된 행만 제한된 묶음으로 처리 |
| 서버 audit | 조회 결과마다 기록. 자동 보관 만료 작업 없음 | 성공/거절 조회 기록은 30일 후 정리하는 초기 운영안을 적용·검증. 발급/폐기 등의 관리 이력은 별도 정책으로 분리하며 일괄 삭제하지 않음 |

요청 제한은 프로세스 메모리만으로 구현하면 여러 Vercel 인스턴스에서 상한이 보장되지 않습니다. 공유 저장소 또는 플랫폼 제한을 사용하고, 허용 요청의 DB 트랜잭션·nonce 중복 거절을 유지해야 합니다. audit 테이블에는 현재 service_role 삭제 권한이 없으므로 정리 편의를 위해 광범위 권한을 추가하지 않습니다. 필요한 후속 마이그레이션·제한된 정리 함수는 별도 검토 대상입니다.

## 서버 키 발급·재개

canonical의 `tools/provision-minecraft-server.mjs`는 승인된 서버 ID/키를 비공개 `.local/minecraft-server-credentials/`에 먼저 저장합니다. 첫 실행 후 결과가 불명확하면 파일을 지우거나 새 키를 발급하지 않고 같은 인자에 `--resume`을 사용합니다. 도구는 DB의 키 해시와 활성 grant를 확인하며, 확인하지 못하면 원문 키를 보존하고 실패합니다.

DB 주소·관리 인증값은 승인된 비공개 실행 환경에서 주입합니다. 명령 인자·문서·Git 파일에 실제 값을 넣지 않습니다. Windows에서는 POSIX mode만으로 ACL 격리를 보장할 수 없으므로 운영 키를 발급할 때 저장 폴더의 Windows 접근 권한도 확인합니다. 이번 작업에서는 실제 서버 키를 발급하거나 다른 개발 작업에 전달하지 않았습니다.

## 승격 경계

현재 후보의 프런트와 관리자는 통합 검사용으로 서로 연결돼 있습니다. 등록된 OAuth 콜백, 환경값, 운영 관리자 대상이 일치하는 승격 후보를 별도로 검증하기 전 운영 alias를 바꾸지 않습니다. DB의 기존 마이그레이션을 다시 실행하거나 기존 사람의 grant를 테스트 용도로 바꾸지 않습니다.
