# 직접 WebSocket 후보 실수신 대조 · 2026-09-26

## 상태와 범위

- 상태: 연구 체크포인트. 운영 전환·코드 수정·재시작 없음.
- 확인 시각: 2026-09-26 13:27 KST. 관측 종료 예정 시각 전의 중간 결과다.
- 대상: 직접 WebSocket 후보와 기존 Chromium 수집기의 비교 기록. 기존 경로만 운영 데이터에 반영한다.
- 이전 기준: [유휴 연결 오종료 수정](2026-09-25-idle-connection-fix.md), [연구 실행 기록](../research/2026-09-23-direct-soak.md).

## 목적과 변경 전 문제

합성 검사와 초기 프레임 비교를 넘어 실제 후원 수신의 동등성·연속성·자원 사용을 확인한다. 수정 전 유휴 종료 구간 및 계정 간 선행조건으로 대기한 구간을 현재 수정본의 실적으로 합산하지 않는다.

## 변경 내용과 소유 구성요소

연구 전용 JSONL을 읽기 전용으로 내려받아 세션 종료 시점의 최종 비교 집계를 합산했다. 누적 스냅샷을 반복 합산하지 않았다. 공개 문서는 계정 식별자·메시지 원문·프레임 해시를 제외한 결과만 포함한다. 애플리케이션·관측기 소스와 서버 실행 상태는 변경하지 않았다.

## 검증

수정 후 실제 연결이 발생한 운영 대상 한 계정에서 두 세션이 확인됐다.

- 9월 25일 18:30:07부터 21:58:40까지 수신 후 `duration_reached`로 종료했다. 종료 시 소켓 오류 0, close code 1000이었다.
- 22:00:33에 새 세션이 준비됐다. 이전 후보 수신 종료부터 약 113초의 관측 공백은 성공 시간에서 제외한다. 이 재접속은 제한된 세션 종료 후 감독기의 재개이며, 임의 네트워크 장애 복구나 실제 OAuth 토큰 갱신을 입증하지 않는다.
- 두 번째 세션은 9월 26일 02:29:49에 `original_packet_decode_failed`로 종료됐다. 해당 시각은 정리 완료를 포함한다. 실제 동시 관측은 합계 약 7시간 57분이며 정밀한 소켓 연결 시간과 동일하지 않다.

첫 세션 503개, 두 번째 1,094개다. 양쪽 수신 수·코드·세션별 HMAC 프레임 내용 및 반복 횟수가 일치했다. 한쪽에만 수신된 프레임, 최종 비교 대기, 종료부 대기 항목은 각각 0개다. 공통 관측 범위 밖의 이벤트와 비교 대상이 아닌 프로토콜 코드는 이 결론에 포함하지 않는다. 미션 4개는 정산·알림 등을 포함하는 프로토콜 메시지 수이며 후원 4건이라는 뜻이 아니다. 두 번째 후보 업무 이벤트 집계의 미션 후원은 1건이었다.

### 지연과 자원

- 후보 도착 시각에서 기존 관측 도착 시각을 뺀 구간 집계: `(-100,-20]ms` 1개, `(-20,0]ms` 1,231개, `(0,20]ms` 365개. 1,596/1,597개가 절대 차이 20ms 이내였다. 원시 시각 분포가 아닌 버킷이므로 정확한 평균·중앙값·우위는 계산하지 않는다. CDP와 프로세스 전달 비용을 포함하는 관측 지연이며 DB 정리 완료나 화면 반영 속도가 아니다.
- 후보 Node RSS: 70.50~76.88 MiB, 표본 중앙값 73.92 MiB. heapUsed 8.36~9.44 MiB. 텔레메트리 1,910개.
- Docker 표본 중앙값: 기존 전체 컨테이너 메모리 575.7 MiB, 후보 23.56 MiB; CPU 0.23% 대 0.00%. 후보의 표시 0.00%는 반올림된 표본값이다. Docker 메모리와 프로세스 RSS는 측정 기준이 달라 서로 대체하지 않는다.
- 기존 컨테이너는 여러 계정·DB 전송·큐·관측 보조를 포함하고 후보는 한 계정 수신 전용이다. 위 비율을 운영 전환 절감률이나 500명 수용량으로 사용하지 않는다.

### 유휴 유지와 격리

- `idle_unconfirmed` 표본 뒤 같은 세션에서 업무 이벤트 수가 증가한 복귀 10회를 확인했다. 가장 긴 해당 표본의 무수신 시간은 약 661초였고 이후 이벤트가 24→25개로 증가했다. 180초 침묵만으로 종료하던 문제는 이 실제 관측에서 재발하지 않았다.
- 두 후보 컨테이너의 격리 검사가 통과했고 종료 후 회수도 확인됐다. 955개 기존 경로 상태 표본에서 roomMatches 실패 0개였다.
- 나머지 두 대상은 수정 후 세션 0개다. 세 계정 동시 연결·계정 간 혼선 방지의 실사용 교차 검증은 미완료다. 단일 계정의 소유자 검사 통과를 다중 계정 검증으로 대체하지 않는다.

### 새 중단과 한계

기존 Chromium 프레임을 관측하는 `soak-monitor.mjs`의 `decodePackets` 예외가 `original_packet_decode_failed`로 기록됐다. 중단 직전 02:29:47의 기존 경로는 connected, pending 0, deadLetters 0, roomMatches true였다. 후보는 안전 정책에 따라 회수됐고 자동 재시작되지 않았다. 연구 서비스 전체가 active여도 해당 대상의 관측은 멈춰 있다.

현재 관측기는 실패한 프레임의 opcode·길이·세부 오류를 저장하지 않는다. 따라서 실제 원인을 제어 프레임, 다른 소켓, 길이·인코딩 등의 특정 조건으로 단정할 수 없다. 코드상 CDP 이벤트의 requestId/opcode별 분리 없이 모든 수신 프레임을 SOOP 파서로 보내는 지점은 후속 조사 대상이다. 실패 프레임은 비교 집계에 들어가지 않으므로 앞선 1,597개 일치가 그 프레임까지 정상이라는 뜻은 아니다.

수정 전 자료에서는 유휴 종료 전 73개 채팅 일치, 약 35분 관측을 별도 확인했다. 선행조건 수정 전 자료는 수신 세션 0개다. 이 자료를 현 수정본의 실적으로 합치지 않았다.

## 사용자 영향과 복구

- 이번 작업은 읽기 전용 검증과 문서 기록이다. 운영 데이터·수집기·예약 자동화를 변경하지 않았다.
- 판정: 관측한 콘텐츠의 프레임 동등성은 확인됐으나 장기 안정성 검증은 관측기 오류로 불완전하다. 운영 채택 합격으로 판정하지 않는다.
- 남은 항목: 중단 원인 구체화, 다중 계정 동시 관측, 장애 복구·토큰 갱신, 미발생 이벤트 종류, 후보에서 기존 처리기·DB·OBS까지의 종단 검증.
- 오류 후보를 재시작하거나 안전 중단을 우회하지 않았다. 후속 수정 시 기존 증거를 보존하고 새 구간으로 검증해야 한다.

## 제거·보존한 파일과 근거

삭제 없음. 현 구간·수정 전 두 구간의 JSONL과 집계는 비공개 `.local`에 보존했다. 공개 저장소에는 원문·회원 정보·접근값을 포함하지 않는다.
