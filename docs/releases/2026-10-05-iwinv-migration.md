# iwinv 운영 이전 · 2026-10-05

## 상태와 범위

- 상태: **운영 수집 호스트 이전 완료. 기존 NCP VM 정지·복구 원본 보존.**
- 확인 시각: 2026-10-05 06:30 KST. 대상은 기존 Chromium 수집기, 암호화 전송 큐, 호스트 예약 작업 6개, 독립 백업, 직접 WebSocket 연구다.
- 이전 기준: [iwinv 후보 생성·검증](2026-10-05-iwinv-candidate.md). 웹·DB·Agent 버전 및 공개 도메인은 변경하지 않았다.

## 목적과 변경 전 문제

현재 규모에 비해 큰 서버 고정비를 줄인다. 검증한 2vCPU·8GB 후보로 기존 수집 경로를 옮기되, 단일 쓰기와 복구 자료를 유지한다. 관측기는 기존 transient unit 대신 부팅 복구와 오류 재시작 차단을 갖춘 서비스로 이전한다.

## 변경 내용과 소유 구성요소

- 새 호스트의 읽기 전용 인증 조회에서 기존 5개 계정 확인 후 전환했다. 이미지 ID와 운영 환경변수 해시가 이전 전과 일치한다. 소스를 새로 빌드하거나 수집 로직을 바꾸지 않았다.
- 모든 계정이 방송 대기이고 미전송·실패 큐가 0일 때 기존 연구와 예약 작업을 멈추고 수집기를 정상 종료했다. 기존 자동 재시작을 해제한 뒤 새 호스트를 기동했다.
- 240개 상태·백업·연구 파일, 42,032,353바이트의 SHA-256 대조에서 불일치 0. SSH 스트리밍으로 전송했고 대형 로컬 아카이브를 만들지 않았다. 기존 원본은 삭제하지 않았다.
- 백업 계정 UID 충돌을 피하고 보관 파일 소유권을 새 전용 계정에 맞췄다. 운영 알림의 감시 위치를 iwinv로 변경하고 호스트 CPU·네트워크 누적값의 이전 표본을 초기화했다. 과거 일별 집계와 알림 상태는 보존했다.
- 6개 타이머와 연구를 새 호스트에서 재개했다. 연구는 새 구간으로 분리하고 로컬 receipt·조회 도구도 갱신했다. 세 대상의 독립 시작 및 사용자 선언까지 관측하는 방침은 그대로다.
- 연구 부팅 보호기는 기존 `needs_review`, 손상된 기록, 32MiB 초과 기록에서 시작을 거부한다. 서비스 자동 Restart는 사용하지 않는다.
- 기존 실연결 기록의 SOOP TLS 채팅 포트 TCP 9001만 outbound에 추가했다. SSH는 관리 IP만 허용하고 수집 상태 포트는 loopback에 유지했다.

## 사용자 영향과 복구

- 이용 주소와 Agent 설치본은 같다. 운영 후원 반영은 기존 SDK 경로를 유지하며 직접 WebSocket은 연구 상태다.
- 새 서버 기본 신청 요금은 VAT 포함 월 36,740원이다. 월 중간 사용은 일 요금 조건이 적용되고 트래픽 초과 등은 별도다. NCP 정지는 반납이 아니므로 디스크·공인 IP 등 잔여 요금이 있을 수 있다.
- **기존 백업 보관 정리 오류는 미해결이다.** 이전 전 NCP의 06:10 작업에 HTTP 500 45회, 파일 처리 실패 15건이 기록되어 있었다. 새 호스트 수동 검사가 길어져 종료했고, 공유 잠금 해제 후 독립 백업을 단독 실행해 성공했다. 기존 정기 보관 정책은 유지했다. 이전 성공을 이 오류 해결로 표현하지 않는다.
- 새 호스트의 큐 증가·인증 실패·계정 혼선이면 먼저 신규 쓰기를 멈춘다. 최신 큐·처리 이력을 보존하고 기존 디스크와 비교한 뒤에만 NCP를 재개한다. NCP의 컨테이너 restart policy와 타이머는 의도적으로 꺼져 있으므로 VM 시작만으로 수집이 재개되지는 않는다.
- NCP 반납은 복구 원본 삭제를 수반하므로 이번 작업에서 실행하지 않았다. 검증되지 않은 실방송 수신을 완료로 계산하지 않는다.

## 제거·보존한 파일과 근거

기존 운영 파일·백업·관측 구간을 모두 보존했다. 새 호스트의 UID에 맞춘 권한, 감시 위치, 호스트 누적값 기준만 변경했다. 비밀값·회원 식별자·원문 로그·접속 주소·공급자 식별자는 비공개 운영 기록에만 남긴다.
