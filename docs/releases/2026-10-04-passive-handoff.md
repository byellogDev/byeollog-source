## 목적과 변경 전 문제

10월 2일 후보 두 개가 약 26분 10초 후 연결 종료했습니다. 이전 무이벤트 교체 구현은 실제 SOOP에서 관측되지 않은 challenge/pong 응답에 의존했고, 상위 관측기가 연결 종료 상세를 버리고 있었습니다. 감독기 active 상태와 실제 수신 상태도 구분해야 합니다.

**기존 기록에는 종료 코드가 없으므로 26분 단절의 원인을 확정하지 못했습니다.** 이번 변경은 확인된 교체 조건 문제와 진단 누락을 수정하고, 새로 추가했던 능동 WebSocket ping을 제거합니다. ping 제거만으로 단절 해결을 보증하지 않습니다.

## 변경 내용과 소유 구성요소

- `client.mjs`: 10초 주기의 native WebSocket ping 및 pong 의존을 제거했습니다. 기존 공식 SDK 사본과 대조한 60초 간격 SOOP 응용 유지 패킷만 보냅니다. 연결 종료 코드, 종료 이유의 바이트 길이, 연결 경과 시간, 마지막 수신 경과 시간·서비스 코드, 수신 프레임 수를 반환합니다. 종료 이유 원문은 기록하지 않습니다.
- `rolling-observer.mjs`: 새 연결의 인증과 같은 계정·방송 입장을 확인하고, 준비 1초 이후 최소 30초 공존합니다. 양쪽 콘텐츠가 없을 때는 준비 구간 이후 실제 수신한 SOOP 제어 패킷(0/4/127, ret=0)이 최근 60초 이내여야 교체합니다. `quiet_provider_traffic`, `contentVerified=false`, 근거 코드·경과 시간을 기록합니다. 후원·채팅이 있으면 기존 내용·순서·횟수 대조가 우선입니다.
- 서버 트래픽이 전혀 없거나 오래됐거나, 알 수 없는 코드·거절 응답만 온 경우 교체하지 않습니다. 보내기 성공·입장 ACK만으로 연결 상태를 판정하지 않습니다. 90초 준비 제한, 기존 연결 유지, 최대 두 소켓, 단일 출력 권한을 유지합니다.
- 연결마다 `connection_ended`를 기록하고, 예기치 않은 활성 연결 종료의 상세를 최종 결과까지 전달합니다. 정상 교체로 닫은 연결과 실패로 닫힌 연결을 구분합니다.
- `soak-controller.py`: 일반 처리 및 종료 후 drain 모두에서 연결 종료 기록을 보존합니다. 허용된 단계·이유·숫자만 저장하여 인증값·서버 원문 유출을 막습니다. 비정상 종료의 검토 대기와 불일치 중단 조건은 유지합니다.
- 연구 bundle 버전 `direct-ws-rolling-v4`. 자동 무조건 재시작이나 운영 쓰기 경로 연결은 추가하지 않았습니다.

## 사용자 영향과 복구

기존 운영 데이터는 Chromium 경로만 반영합니다. 각 대상은 기존 연결이 안정되면 독립적으로 연구 수신을 시작합니다. 다른 테스트 계정의 선행 통과를 기다리지 않습니다.

실제 방송에서 26분 이후 연결 유지, 무이벤트/콘텐츠 교체 근거, 종료 상세, 계정 분리·누락·중복을 확인해야 합니다. 지금은 방송 대기이므로 이 항목을 완료로 판정하지 않습니다. 과거 내용 일치 검증 수락은 유지합니다. 500명 수용이나 무중단 운영을 보증하지 않습니다.

복구 시 현재 연구 단위를 정리하고 보존된 이전 receipt·bundle과 대조합니다. 이전 v3 자체도 중단 결함이 있으므로 단순 재실행을 정상 복구로 간주하지 않습니다. 운영 Chromium·사용자 데이터는 유지하고 관측 구간을 분리합니다.

## 제거·보존한 파일과 근거

사용자 파일 삭제 없음. 이전 실패 기록 전체와 배포 전 receipt는 비공개 `previousPassiveSegment` 및 로컬 보관본으로 연결했습니다. 새 배포·검사 결과, 수정 전 회귀 재현은 비공개로 보존합니다. 공개 저장소에는 구현·검사·익명화 문서만 게시합니다.
