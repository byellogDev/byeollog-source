# 업보 수집 설정 배포 준비 · Agent 1.0.0.56 · 2026-10-11

## 상태와 범위

- 상태: **운영 승격 보류**. 웹·관리·수집 API 후보 READY. 운영 도메인과 안정 업데이트 채널은 이전 버전 유지.
- DB 구조는 추가했으나 인증된 후보 검증을 완료하지 못해 새 트리거·기존 함수 변경을 복구했다. 신규 테이블·설정은 보존하고 5개 수집 제어는 기존 protocol 0.
- 설치 자산 1.0.0.56은 별도 저장소에 게시했으며 자동 업데이트 안정 채널은 1.0.0.55다.
- 이전: [업보 수집 설정 소스 후보](2026-10-11-upbo-collection-settings.md). 후보 기록을 운영 완료로 바꾸지 않는다.

## 목적과 변경 전 문제

후원알림 주소와 ON 중심 설정을 운영에 반영하기 위해 DB·세 개 웹 런타임·Agent 안내를 함께 준비했다. 로그인된 사용자의 실제 저장 경로 검증은 아직 남아 있다.

## 변경 내용과 소유 구성요소

- 관리 API·수집 API·웹에 소스 후보를 배치하고 기존 구성과 분리 경계를 유지했다. 실행 지역 hnd1, 운영 별칭 미연결, 배포 보호 유지.
- 웹의 첫 후보는 새 메뉴와 생성 화면이 맞지 않아 빌드 실패했다. 생성 파일도 포함한 후보로 수정하여 통과했다. 실패 후보는 승격하지 않았다.
- Agent 버전·서명 카탈로그·설치 기본값·배포 출처를 1.0.0.56으로 준비했다. 릴리스 자산만 게시되었고 안정 피드와 다운로드 버튼은 이전 상태다.
- 운영 DB에 설정·이벤트명 구조를 적용하고 RLS 및 계정 검증을 확인했다. 이후 인증 검증 보류로 기존 후원 처리 함수를 복귀시켰다. 새 기록 삭제나 과거 자료 재처리는 하지 않았다.

## 사용자 영향과 복구

- 아직 새 설정 화면을 운영에 승격하지 않았다. 기존 운영 화면·다운로드·수집 동작을 유지한다.
- Vercel 민감 환경변수는 값을 반환하지 않았고 브라우저 제어 도구도 실행 오류였다. 기존 점검 자료의 인증값 재사용은 자동 승인 검토가 명시적 승인이 없다는 사유로 차단하여 사용자 확인을 요청했다. 해당 인증값은 읽거나 사용하지 않았다.
- 승인 후 테스트 계정 로그인→후보 API→DB→화면 검증, DB 재활성화, 같은 후보 승격, 운영 피드/다운로드 확인이 남는다. DB만 새 동작으로 장시간 두지 않도록 이번에는 기존 함수와 트리거로 복귀했다.
- 복구 자료·후보 ID·정확한 설정은 비공개 보존. 운영 마이그레이션 기록은 settings 20261011065012, 보류 복구 20261011071639이며 최초 소스 파일의 시간 접두사는 20261011054734다.
- 이전 후보의 제한 유지: 지원하지 않는 주소/조건은 거절, 오버레이 시험 결과의 운영 합산·누락 보완은 미포함, 실제 방송 검증과 고객 PC 설치는 미완료.

## 제거·보존한 파일과 근거

실행 중인 서비스나 사용자 자료를 삭제하지 않았다. 후보·패키지·복구·검증 증거는 비공개 보존하고 공개 저장소에는 출처와 문서만 기록한다.
