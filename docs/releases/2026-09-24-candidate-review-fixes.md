## 목적과 현재 반영 범위

마크 계정 연동과 직접 WebSocket 관측의 [사전 리뷰](../reviews/2026-09-24-candidate-code-review.md)에서 재현한 4건을 수정했습니다. **코드 수정·자동검사 완료와 운영 채택을 구분합니다.**

| 항목 | 수정 | 현재 반영 |
| --- | --- | --- |
| R1 정지 연동 재활성화 | 완료 RPC의 잠금 구간에서 SOOP·Minecraft 양쪽 정지를 거절. 메모리 저장소·오류 응답도 동일하게 처리 | 운영 DB 후속 migration 적용, 앱은 보호된 후보 |
| R2 관측 준비의 토큰 갱신 | 별도 `observe` 계약은 연결된 계정의 접근 토큰만 조회. 만료 120초 이내·만료 정보 불명은 관측 대기. 공급자 갱신·DB PATCH·lease 발급 없음 | 기존 인증 경계인 관리자 런타임에 관측 API만 운영 반영, 실제 세 계정 조회 확인 |
| R3 남은 게임 쿠키 충돌 | 일반/게임 인증 시작 시 다른 흐름 쿠키 삭제. 기존 모호한 콜백은 두 시도를 정리하고 재시도 요구. state 검증 유지 | 새 웹·관리자 보호 후보 응답 확인. 운영 웹·관리자 배포 유지 |
| R4 종료 직전 불일치 누락 | 제한된 큐 정리 후 최종 비교. 불일치·비교 미완료·정리 미완료는 정상 종료보다 우선하는 검토 대상 | 연구 서버의 예약 코드 교체 및 서버 내 합성 검사 완료 |

후속 승인 이후 실제 요청 경로를 확인하면서 최초 수정 위치가 잘못된 것을 발견했습니다. 인증정보 조회는 **관리자 런타임**이 담당하고, 수집 런타임에는 공급자 비밀값을 두지 않는 구조였습니다. 초기 단위검사가 내부 라우팅·허용 목록을 거치지 않아 이 오류를 놓쳤습니다. 구현을 관리자 런타임으로 옮기고 검사도 웹 라우팅·관리자 내부 인증·수집 런타임 거절까지 거치도록 보강했습니다. 생성한 수집 런타임 Preview는 운영에 반영하지 않았고 해당 소스 변경도 되돌렸습니다.

운영 원본 140개와 canonical Git 기준 `36d02ac`의 바이트 일치를 확인한 후, 관측 API에 필요한 관리자 파일 **3개만** 선택해 별도 후보를 만들었습니다. 일반 SOOP 콜백·마크 후보 변경은 이 운영 배포에서 제외했습니다. 보호된 후보와 실제 운영 경로에서 세 계정의 `observe` 응답 200, 무서명 요청 401을 확인했습니다. 세 계정 연결 행의 전체 digest도 조회 전후 동일합니다. 자세한 반영 기록은 [관측 API 릴리스](2026-09-24-observation-api.md)에 있습니다.
