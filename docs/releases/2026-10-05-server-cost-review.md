# 서버 비용·4GB 후보 검증 · 2026-10-05

## 상태와 범위

- 상태: **연구 체크포인트. NCP 축소·이전·운영 설정 적용 없음.** 사용자가 절감액을 확인한 뒤 국내 저가 서버 비교로 방향을 바꿨다.
- 확인 시각: 2026-10-05 05시 KST. 운영 SDK 수집 이미지, 별도 연구 관측기, 자원 상한 및 공개 요금을 검토했다.
- 이전 기준: [SDK 수집기](2026-10-05-sdk-lifecycle.md), [연구 관측기 v5](2026-10-05-semantic-comparison.md).
- 후속: [iwinv 이전 후보 생성](2026-10-05-iwinv-candidate.md). 아래 미생성·운영 불변 기록은 비용 비교 시점의 상태다.

## 목적과 변경 전 문제

소규모 수집기의 실제 부하에 비해 서버 고정비가 높았다. 같은 업체의 메모리 축소가 충분한 절감인지, 실제 사용량과 후보 실행으로 판단한다. 청구 원문·계정·서버 식별자·원격 경로는 비공개 자료로만 보존했다.

## 변경 내용과 소유 구성요소

- `operations/ncp/probe-browser-capacity.mjs`: 운영과 같은 이미지에서 공개 SDK 페이지 5개를 5회 생성·회수하는 용량 검사. 운영 인증값·볼륨·후원 처리기는 사용하지 않는다.
- `operations/ncp/compose.4gb-candidate.yml`: 미적용 후보. 수집기 RAM 1.5GiB, RAM+swap 2GiB, 예약 512MiB. 현행 compose와 합성했을 때 이 세 값만 바뀌는 것을 확인했다. 예시 compose 자체를 배포 기준으로 사용하지 않는다.
- 현재 연구 관측기는 transient systemd unit이므로 VM 재부팅 뒤 자동 복원이 보장되지 않는다. 현행 unit 정의·관측 receipt·compose·볼륨 위치를 비공개로 보존했다.

## 검증

| 항목 | 방법 | 결과 | 한계 |
| --- | --- | --- | --- |
| 과거 부하 | 14일 8,873개 표본 | CPU 평균 1.17%, p95 2%; 가용 메모리 최저 76% | 표본 사이 순간 부하·향후 증가를 보증하지 않음 |
| 방송 중 표본 | 4,323개, 동시 최대 2방송 | CPU p95 2.2%, 가용 메모리 최저 76% | 5계정 동시 실방송 검증 아님 |
| SDK 페이지 자원 | 같은 운영 이미지, 1.5GiB RAM·swap 불허·0.5 CPU·384 PID 제한 | 3페이지 5회: 최대 533MiB; 5페이지 5회: 최대 727MiB, OOM 0, 최종 약 26MiB | 인증된 연결·후원 수신·큐 재전송 없는 생성·정리 시험 |
| 재연결·격리 | 같은 제한에서 기존 Chromium 합성 SDK 검사 | 14개 종료·오류·재연결 시나리오, 컨텍스트 회수·저장소 격리 통과 | 실제 SOOP 인증·토큰 교체와 구분 |
| 안전성 | 시험 전 방송 대기·빈 큐 확인, 종료 후 inspect | 임시 컨테이너 삭제 확인, 운영 ID·이미지·기동 시각 불변 | VM 축소·부팅은 미실행 |
| 설정 후보 | 실제 compose + override, config JSON 대조 | 메모리 관련 3개 값 외 동일 | 설정 미적용 |

확대 시험의 첫 실행은 검증 스크립트의 data URL에서 절대 import 경로를 해석하지 못해 실패했다. 명시적인 file URL로 수정했다. 다음 시도는 방송 대기 조건에서 벗어나 실행 전에 차단됐으며, 다시 모든 채널의 대기를 확인한 후 최종 검사를 통과했다. 실패 시에도 임시 컨테이너 회수와 운영 불변을 확인했다.

1.5GiB 운영 후보 + 연구 수신기 최대 3×256MiB + 연구 감독자 최대 384MiB는 합계 2.625GiB이다. 여기에 OS·Docker·모니터링·캐시 여유가 별도로 필요하다. 전체 4GB VM의 실부하 상한을 증명한 결과가 아니며, 축소를 강행할 근거로 사용하지 않는다.

## 공개 요금 비교

2026-10-05 확인한 공개 요금이며 할인·서비스 품질·성능 동등성을 보증하지 않는다. 서버 외 별도 백업과 초과 트래픽 비용을 구분한다.

- [NCP 계산기](https://www.ncloud.com/charge/calc/ko?category=compute#server): 한국 G3 Linux, 720시간 기준 순수 서버 2vCPU/8GB 82,240원 → 2vCPU/4GB 66,240원(부가세 별도). 동일 기준 절감 16,000원, VAT 포함 17,600원. 디스크·IP는 별도이며 실제 청구 월과 직접 같은 금액이 아니다.
- [iwinv 공개 요금](https://www.iwinv.kr/server/server): 국내 General Purpose 단독형 gna_2.4_n 2vCPU/4GB 27,800원, gna_2.8_n 2vCPU/8GB 33,400원(각 VAT 별도). VAT 포함 30,580원/36,740원. NVMe 50GB, 공인 IP 1개, 트래픽 20GB/일(월 600GB 안내) 포함. 공유형은 CPU 50% 제한이 있어 같은 숫자의 단독형과 혼동하지 않는다. 월 중 개통·해지는 일 요금 적용.
- [카페24 Linux 가상서버](https://hosting.cafe24.com/?controller=new_product_page&page=virtual): 자이언트 4GB/SSD 100GB/월 1.2TB/공인 IP 1개, 월 33,000원(VAT 포함), 설치비 22,000원 별도. CPU 배정·Docker/cgroup 제약은 미확인이며 하위 상품 변경 불가 안내가 있다.

권고: NCP 축소는 보류하고 iwinv 2vCPU/8GB를 우선 이전 후보로 검토한다. 4GB보다 월 6,160원만 추가하여 연구 관측과 브라우저 여유를 유지한다. 후보 서버를 결제·생성하지 않았으며 SOOP 접근성·패킷 지연·장시간 성능·장애 복구는 미검증이다.

## 사용자 영향과 복구

- 운영 기능·데이터·권한·서버 사양은 그대로다. 시험 컨테이너만 생성 후 정리했다.
- 실제 축소는 [공식 절차](https://guide.ncloud-docs.com/docs/server-manage-vpc)에 따라 VM 정지가 필요하다. 현재 서버의 타입 변경 가능 목록과 복구 용량도 변경 직전에 확인해야 한다.
- 축소/이전 실행 시: 방송 대기·빈 큐 확인 → 현행 이미지·설정·큐 볼륨·관측 원문 보존 → 연구를 정상 종료하고 종료 지점 기록 → 운영 변경 → 동일 환경·큐 복원 → 연구를 이전 구간과 구분해 재개. 두 서버가 같은 계정을 동시에 운영 반영하지 않도록 담당권한을 이관한다.
- OOM, 반복 재연결, 큐 증가, 계정 격리 이상이면 이전 서버/사양·원래 compose로 복구한다. 이전 서버 삭제와 원문 삭제는 검증 후 별도 결정한다.

## 제거·보존한 파일과 근거

사용자 파일 삭제 없음. 일회성 검사 컨테이너만 제거했다. 요금 원문·사전 상태·시험 결과·복구 자료는 비공개 `.local`에 보존하고 공개 문서에는 요약만 포함한다.
