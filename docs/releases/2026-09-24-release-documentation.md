# 2026.09.24 · 릴리스 문서와 GitHub 기록 규칙

## 목적과 변경 전 문제

주요 작업마다 GitHub에 업로드하고 하루 한 번 점검하는 규칙에 더해, 릴리스 문서 작성도 필수로 지정했습니다. 일일 기록만으로는 버전별 목적·검증·운영 반영 범위를 찾기 어려워 별도 목록으로 정리합니다.

## 상태와 변경

문서 변경이며 서비스 배포는 없습니다. 기존 릴리스 7건을 [목록](README.md)에 연결하고, 작업 지침·개발 절차·릴리스 양식에 필수 작성 항목과 상태 구분을 추가했습니다. 일일 점검은 릴리스 문서, CHANGELOG와 작업 기록의 연결 누락도 확인하도록 합니다.

## 검증과 한계

문서의 상대 링크와 게시 대상 diff, 민감정보 게시 검사를 확인합니다. 실행 코드 변경이 없어 기능 검사를 다시 실행하지 않습니다. 이 문서 정리가 이전 릴리스의 미검증 항목을 완료로 바꾸지는 않습니다.

## 사용자 영향과 복구

서비스 동작·사용자 데이터·권한 변경은 없습니다. 기록 규칙을 바꿔야 하면 해당 문서 변경만 되돌리거나 수정하며 운영 배포는 필요하지 않습니다. 일일 자동화 지침은 별도로 갱신합니다.
