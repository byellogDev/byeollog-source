# SOOP 입장 계정 접미사 처리 · 2026-10-05

## 상태와 범위

- 상태: 운영 SDK 수집기 및 직접 WebSocket 관측 v6 반영.
- 반영 시각: 2026-10-05 19:25 KST. SDK 경로만 운영 데이터를 저장하며 후보는 수신 전용이다.
- 대상: 채팅방 소유자 검증과 연구 관측. 웹·DB·Agent·인증 권한·방화벽 변경 없음.
- 이전 기준: [iwinv 이전](2026-10-05-iwinv-migration.md), [의미 비교 v5](2026-10-05-semantic-comparison.md). 이전 구간과 이미지는 보존한다.

## 목적과 변경 전 문제

18:58부터 한 방송의 SDK 입장 검증이 반복 실패했고 19:05 수집 채널 경고가 발생했다. OAuth 기반 채팅방 조회·접속 URL은 기본 계정 ID를 사용했지만 실제 JOIN 응답에는 같은 ID 뒤에 `(2)`가 붙어 있었다. 방 번호는 같았다. 문자열 전체 비교가 이를 다른 계정으로 오인하여 연결을 종료했다. 직접 연결 후보의 JOIN 검증에도 같은 결함이 있었다.

서버 자원 부족이나 접속 포트 차단은 이번 원인이 아니다. 다른 방송은 기존·신규 수신이 진행 중이었고, 장애 방송도 실제 소켓 입장까지 도달했다. 해당 방송의 연구 후보는 기존 연결 실패 때문에 대기 중이었다.

## 변경 내용과 소유 구성요소

- SDK는 계정 ID 전체 형식을 검증하고 끝의 숫자 접미사만 제거한 기본 ID로 계정을 대조한다. 검증된 기본 ID를 후속 이벤트와 서버에 전달한다.
- 연구 후보의 JOIN·후원 소유자 확인·기존 SDK 페이지 선택에도 같은 공통 함수를 적용한다. 인증된 chatinfo 소유자와 JOIN 방 번호 검증은 유지한다.
- 다른 계정, 다른 방, 문자열 덧붙임·중첩 괄호·제어문자는 계속 거부한다.
- 연결 로그에 접미사 정규화 여부, 거부 로그에 소유자 일치·형식·방 번호 유효성을 기록한다. 식별자 원문은 출력하지 않는다.
- 연구 v6는 새 구간에서 시작했다. 계정별 독립 관측, 수신 전용 권한, 사용자 종료 선언까지 관측, 재부팅 시 오류 구간 재시작 방지는 유지한다.

## 사용자 영향과 복구

- 정상 계정의 숫자 접미사를 타 계정으로 오인하지 않고 수집한다. 실제 다른 계정은 계속 차단한다.
- 운영 교체 과정에서 기존 연결들도 재연결되었다. 장애 발생부터 복구 전까지의 미수신 이벤트 자동 복구나 누락 0건은 보증하지 않는다.
- 재발 시 새 수집·관측을 멈추고 최신 큐를 보존한 뒤 이전 이미지와 compose를 복구한다. 과거 큐를 무조건 재생하지 않는다.
- NCP VM은 정지·원본 보존 상태이며 반납하지 않았다.
