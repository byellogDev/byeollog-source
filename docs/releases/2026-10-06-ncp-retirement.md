# 기존 NCP 서버 반납 · 2026-10-06

## 상태와 범위

- 상태: **운영 인프라 정리 완료**. iwinv 이전 후 정지해 둔 NCP 서버를 사용자 최종 승인에 따라 반납했다.
- 확인 시각: 2026-10-06 19:16 KST.
- 대상: 기존 서버 1대, 기본 디스크 20GB, 연결된 공인 IP 1개. 웹·DB·Agent·현행 수집기 배포 변경은 없다.
- 이전 기준: [iwinv 운영 이전](2026-10-05-iwinv-migration.md), [계정 접미사 오류 수정](2026-10-05-room-owner-suffix.md).

## 목적과 변경 전 문제

이전이 끝난 NCP 서버를 정지 상태로 보관하면서 기본 디스크와 공인 IP가 남아 있었다. 이전 자료와 현행 운영 상태를 확인한 뒤 구 서버를 반납하여 불필요한 자원 보유를 종료한다.

## 변경 내용과 소유 구성요소

- NCP 콘솔에서 이전 기록과 일치하는 정지 서버·기본 디스크·공인 IP를 확인했다. 별도 서버 이미지와 스냅샷은 각각 0개였다.
- 최초 반납 요청은 반납 보호 설정으로 거부됐다. 같은 승인 대상의 반납 보호를 해제하고 공인 IP 동시 반납을 선택해 완료했다.
- 완료 후 한국 VPC 콘솔의 서버, Storage, Public IP 목록이 모두 0개임을 확인했다.
- 운영 복구 문서에서 삭제된 NCP VM 재시작 절차를 제거하고 현행 호스트의 보존 이미지·설정 및 최신 상태를 이용하는 복구 절차로 갱신했다.

반납 후 조회한 최근 로그에는 반납 전 발생한 fetch/401 경고가 남아 있었다. 현재 연결 상태와 과거 경고 이력을 구분하며, 과거 오류가 전혀 없었다고 판정하지 않는다.

## 사용자 영향과 복구

- 사용자 서비스는 iwinv에서 계속 실행한다. 이번 반납으로 운영 수집기와 연구 관측기를 재시작하지 않았다.
- **반납한 NCP VM과 기본 디스크는 복원할 수 없으며 공인 IP를 다시 확보할 수 없다.** 과거 문서의 NCP 재개 절차는 더 이상 사용할 수 없다.
- 현행 호스트에 보존한 운영 이미지·설정과 최신 큐/처리 이력을 이용해 복구한다. 호스트 자체를 잃으면 새 호스트를 준비하고 보존 자료에서 복원해야 한다. 오래된 큐를 무조건 재생하거나 운영 쓰기를 두 곳에서 동시에 실행하지 않는다.
- 이미 발생한 NCP 사용료는 남는다. 이번 결과를 계정 전체 청구액 0원 또는 모든 상품 해지로 표현하지 않는다.

## 제거·보존한 파일과 근거

- 제거: 구 NCP VM과 20GB 기본 디스크. 공인 IP도 동시 반납했다.
- 보존: iwinv로 이전한 상태·백업·연구 자료, 현행 호스트의 복구 이미지, 비공개 로컬 이전·반납 증거.
- 공개 기록에는 서버 식별자·접속 주소·인증값·회원 정보·로그 원문·콘솔 스크린샷을 넣지 않는다.
