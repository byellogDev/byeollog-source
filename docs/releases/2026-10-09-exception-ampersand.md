- 이전 기능 기준: [업보 분류·재시도](2026-09-23-upbo-review-retry.md). 직전 제품 릴리스는 [Agent 1.0.0.54](2026-10-09-agent-10054-ui-cache-tray.md).

## 목적과 변경 전 문제

일반 룰렛은 `A & B`를 각각 업보로 만들지만, 룰렛 예외에서 수동 등록하면 전체 문자열을 한 업보로 저장했다. 누락된 예외 경로에도 분리를 적용한다.

## 변경 내용과 소유 구성요소

- DB 등록 함수는 `&` 기준으로 분리하고 앞뒤 공백과 빈 항목을 제거한다. 입력 수량은 각 항목에 적용하며 같은 이름의 반복은 수량에 반영한다. 예: `A & B`, 수량 2 → A 2개·B 2개. 접두어를 추측하여 추가하지 않는다.
- 등록과 이력 저장은 한 트랜잭션이다. 중간 충돌이면 앞선 업보·새 후원자·이력까지 함께 취소한다. 같은 요청 재전송은 중복 생성하지 않는다.
- 여러 업보의 저장 영수증을 보관하고 되돌리기도 원자적으로 수행한다. 일부가 완료·변경됐으면 전체 취소를 거부한다. 기존 한 건 영수증도 지원한다.
- 현재 운영 저장 함수의 workspace → 결과 → 업보 잠금 순서를 맞춘다. 기존 함수 본문 기준이 달라졌으면 마이그레이션을 중단한다. 권한은 security invoker 및 service_role 전용을 유지한다.
- 기존 입력 길이·수량 제한에 더해 최대 20개 출력, 전체 기여 수량 10,000개를 제한한다. 초과 요청은 일부 등록 없이 거절한다.

## 사용자 영향과 복구

- 이후 예외 등록부터 `&`로 나뉜 업보를 생성한다. Agent 업데이트는 필요 없다.
- 과거에 합쳐 저장한 고객 기록은 자동 분해하지 않는다. 이전 기록의 되돌리기는 기존 조건을 그대로 지킨다.
- 복구 시 등록 v1만 직전 본문으로 되돌리고, 새 다중 영수증 처리를 지원하는 v2는 유지한다. 두 함수를 모두 구버전으로 되돌리면 신규 다중 영수증을 취소할 수 없으므로 금지한다. 비공개 운영 기준·복구 SQL을 보존한다.

## 제거·보존한 파일과 근거

기존 파일·고객 데이터 삭제 없음. 새 마이그레이션과 회귀 검사만 추가한다. 운영 함수 조회와 복구 자료는 비공개 `.local`에 보관한다.
