# 2026.09.25 · 직접 연결 후보 수신 침묵 중단 원인 조사

후속: 18:29 KST [유휴 연결 오종료 수정](2026-09-25-idle-connection-fix.md)을 연구 서버에 반영했다. 아래 내용은 수정 전 조사 당시의 증거와 상태다.

## 상태와 목적

2026-09-25 18:11 KST 조사 기록입니다. 연구 후보가 실제 방송에서 중단된 원인을 분석했으며 실행 코드 수정·배포·후보 재시작은 하지 않았습니다. 예약 자동화도 중지 상태를 유지했습니다.

## 확인한 직접 원인

`tools/soop-direct-lab/client.mjs`의 후보는 마지막 메시지 또는 WebSocket pong 이후 180초가 지나면 `transport_silent`로 스스로 종료합니다. 60초마다 애플리케이션 keepalive와 WebSocket ping을 보내지만, pong 응답 여부를 확인하지 않은 채 수신 침묵을 연결 실패로 처리합니다. 정리 단계에서는 후보가 직접 소켓을 닫습니다. 따라서 결과에 남은 정상 close code만으로 서버가 먼저 연결을 종료했다고 판단할 수 없습니다.

고정 해시의 공식 SDK 원본은 60초마다 같은 애플리케이션 keepalive를 보내며 이 180초 수신 침묵 종료 규칙이나 WebSocket ping 호출은 없습니다. 후보의 추가 규칙은 SDK 동등성 검사에서 검증하지 않았던 별도 동작입니다.

## 실제 관측 근거

- 15:33:48 후보 ready 이후 채팅 73건이 기존 경로와 전부 일치했습니다. 비교 미일치·종료 대조 공백은 0건입니다.
- 마지막 수신 추정 시각은 16:05:35이며, 16:08:33에는 수신 경과가 178.447초였습니다. 16:08:48에 `transport_silent`로 끝났고 후보 회수를 확인했습니다. 소켓 오류 기록은 0건입니다.
- 마지막 여러 비교 집계에서 기존·후보 양쪽 모두 73건으로 유지됐습니다. 직전 기존 상태는 connected, 방 소유자 일치, 전송 대기·실패 보관 0건입니다.
- 15:30~18:30 운영 로그에 해당 계정의 연결 기록은 15:32의 1건이며 추가 연결/오류 전환은 기록되지 않았습니다. 후보 중단 이후에도 기존 경로는 180건을 대기열에 저장하고 모두 전달했습니다. 이는 해당 로그 범위의 전달 근거이며 방송 전체 이벤트 무누락 증명은 아닙니다.

## 합성 재현

고정 공식 SDK와 변경하지 않은 후보를 동일한 로컬 WebSocket 서버에 각각 연결했습니다. 서버는 로그인·입장·애플리케이션 keepalive를 받되 자동 pong은 보내지 않고, 조용한 구간 이후 메시지를 보냈습니다. 대기 시간을 축소하여 후보의 침묵 한도 100ms, keepalive 20ms, 지연 메시지 260ms로 재현했습니다.

| 항목 | 직접 연결 후보 | 공식 SDK |
| --- | --- | --- |
| 초기 입장 | 성공 | 성공 |
| keepalive 바이트 | SDK와 동일 | 기준 원본 |
| 조용한 구간 | transport_silent로 자체 종료 | 연결 유지 |
| 지연 메시지 | 종료하여 수신하지 못함 | 1건 수신 |

Node 22에서도 같은 결과를 확인했습니다. 합성 서버는 실제 공급자의 pong 정책을 입증하지 않습니다. 재현은 정상적으로 나중 메시지를 보낼 수 있는 연결도 현재 후보 규칙이 종료시킨다는 증거입니다. 기존 검사는 pong을 보내지 않는 조용한 연결이 종료하는 것을 기대값으로 삼아, 정상 유휴 상태의 지속 수신을 검증하지 못했습니다.

## 판정과 남은 범위

확정한 것은 후보의 수신 침묵 조건이 종료를 직접 유발했고, 이 규칙이 정상 유휴 연결을 중단할 수 있다는 결함입니다. 실제 당시 후보의 TCP 경로가 계속 정상인지, pong이 서버·중간 경로에서 왜 도착하지 않았는지는 기록만으로 확정할 수 없습니다. 인증 실패·데이터 불일치·메모리 부족을 이번 중단의 원인으로 볼 근거는 없습니다.

수정 시 수신 침묵과 확정된 단절을 구분해야 합니다. 애플리케이션 keepalive를 유지하고, 기존 경로의 같은 방 수신·후보 수신 차이, 명시적 close/error, 쓰기 실패 등 확인 가능한 근거를 연결 상태와 분리해서 판단해야 합니다. 단순 제한 시간 증가나 안전 중단 무시·무조건 재시작은 해결로 보지 않습니다.

## 영향과 복구

연구 후보의 비교 연속성이 끊겼으며 해당 계정은 검토 대기입니다. 기존 운영 수집은 이 조사에서 변경하지 않았습니다. 로컬 분석 자료는 비공개로 보존하며, 후속 수정 검증 전에는 후보를 재시작하지 않습니다.
