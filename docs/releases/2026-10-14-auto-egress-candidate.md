## 목적과 변경 전 문제

SOOP가 기존 허용 목록 밖의 채팅 TLS 포트를 배정하면 출발 통신이 차단될 수 있다. 방화벽 전체 개방 대신, 공식 접속 정보로 검증한 목적지와 포트에 한해 자동 규칙을 추가하는 후보를 준비했다.

## 변경 내용과 소유 구성요소

- `operations/iwinv/auto-egress`: 고정 API 주소·보안 그룹, HMAC 인증, 응답 크기·호출 빈도 제한. 공식 SOOP 응답을 제어기가 독립 조회하고 계정·공인 IPv4·DNS 일치를 확인한다.
- 생성 규칙은 단일 IPv4 `/32`, 단일 TCP 포트의 **출발 통신**이다. 기존 인바운드·SSH·수동 규칙은 보존한다. 최대 24개, 생성은 분당 6개 이하이며 API 전체 호출 간격도 제한한다.
- 생성 의도를 먼저 디스크에 기록하고 실제 목록으로 확인한다. 응답 유실 시 같은 규칙을 다시 생성하지 않는다. 기존 규칙·서버 연결 관계가 달라지면 자동 변경을 중지한다.
- 별도 비특권 서비스가 API 키를 보관하고, 수집기는 커널 UID를 검증하는 Unix 소켓을 이용한다. 수집기에 클라우드 키를 제공하지 않는다. root 관측기는 연결의 해시만 제공한다.
- 15분간 사용되지 않은 **직접 생성한 규칙**만 삭제한다. 신선한 활성 연결 관측이 없으면 삭제하지 않는다.
- 수집기의 기존 승인 포트와 방송 대기는 제어기를 거치지 않는다. 새 포트만 제어기에 요청한다. 제어기 미설정 시 원래 수집 경로를 유지한다.
- 감시는 목적지 해시와 포트를 함께 비교한다. 한 목적지의 자동 허용이 다른 목적지의 같은 포트 오류를 가리지 않는다. Discord 후보는 API 권한·한도·규칙 변경 등 원인을 고정된 문구로 표현한다.

## 사용자 영향과 복구

- 현재 운영 영향 없음. API 키 생성·운영 서버 IP 제한은 사용자가 승인했으나 브라우저 세션 오류로 키 생성 여부와 제한 적용을 확인하지 못했다. 새로 열린 콘솔은 로그인 화면이다. 중복 생성하지 않고 재로그인을 기다린다.
- 실제 그룹·서버 식별자와 API 반환 형식을 읽기 전용으로 대조하고, 기존에 허용된 SOOP 목적지에 한정한 중복 `/32` 후보 규칙의 생성·조회·삭제를 완료해야 한다. 기존 허용 규칙을 제거해 장애를 유도하지 않는다.
- 키 자체의 리소스별 권한 제한은 확인되지 않았다. 코드 제한이 공급자의 권한 분리를 대신한다고 주장하지 않는다. 키의 호출 IP는 운영 호스트 한 곳으로 제한해야 한다.
- 운영 적용은 이전 이미지·compose·감시·규칙 목록을 보존하고, 같은 검증 후보를 설치한 뒤 수행한다. 실제 설치 스크립트와 API 사전 검증은 아직 완료되지 않았다.
- 실패 시 기존 이미지·환경·모니터로 복귀한다. 자동 규칙은 소유 마커·ID·내용을 대조한 후 제거하며, 키 접근은 중지한다. 기존 수동 규칙은 변경하지 않는다.
