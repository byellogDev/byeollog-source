# Agent 1.0.0.54 · UI 캐시·중복 트레이 수정 · 2026-10-09

## 상태와 범위

- 상태: 정식 안정 채널 운영 반영. 버전 1.0.0.54, 서명 sequence 10054.
- 확인 시각: 2026-10-09 KST.
- 대상: Windows Agent의 내장 UI 추출과 로그인 창 수명주기, 설치·업데이트 피드.
- 이전: [1.0.0.53 개별 숨김 배포](2026-10-09-agent-10053-wallpaper-hidden.md). DB·운영 수집 경로·권한 변경 없음.

## 목적과 변경 전 문제

1.0.0.53에서 ×와 숨긴 풍벽지 메뉴가 보이지 않는 신고가 있었다. 실행 파일은 최신이어도 UiAssetStore가 고정된 v1.0.0.50 폴더의 HTML을 재사용했다. 기존 파일이 있으면 쓰기를 생략하므로 새 버튼 스크립트가 연결되지 않았다. 이전 검증은 소스 UI를 직접 열었고, 기존 설치의 추출 캐시를 거치는 경로를 놓쳤다.

다른 고객은 정상 클라이언트와 함께 서버 연결 필요 트레이 아이콘이 하나 더 표시된다고 신고했다. 로그인 폼 생성자가 미리 아이콘을 표시하고, 자동로그인 경로가 FormClosed 없이 Dispose할 때 아이콘·메뉴를 회수하지 않는 결함을 재현했다. 고객 PC의 실제 실행 경로·프로세스 수는 직접 확인하지 않았으며, 모든 이중 실행 사례가 같은 원인이라고 단정하지 않는다.

## 변경 내용과 소유 구성요소

- UiAssetStore는 수동 UI 버전 대신 실제 빌드 MVID로 캐시 폴더를 구분한다. 같은 빌드는 재시작 때 재사용하고, 새 빌드는 새 내장 HTML·JS·CSS를 추출한다. 구버전 캐시와 사용자 데이터는 보존한다.
- 로그인 폼은 실제 표시된 뒤 트레이 아이콘을 표시한다. 자동로그인 준비만으로 아이콘을 만들지 않는다.
- 트레이 아이콘·메뉴·아이콘 리소스 해제를 Dispose로 옮겨 자동로그인 생략·시작 취소·반복 Dispose에도 회수되도록 했다.
- AgentStoreTests에 구 UI 캐시가 있는 준비 경로를 추가했다. 별도 Windows UI 검사 프로젝트는 실제 앱 어셈블리와 실제 로그인 Form을 로드하며 네트워크·실사용자 저장소를 사용하지 않는다. CI에도 이 검사를 추가했다.
- 설치기 기본값, 서명된 피드, 출처 메타데이터와 다운로드 경로를 1.0.0.54로 갱신했다.

## 사용자 영향과 복구

- 업데이트 후 프로그램을 다시 실행하면 새 UI 캐시를 준비하며 ×와 숨긴 풍벽지 목록이 나타난다. 캐시 수동 삭제나 로그인 초기화는 필요 없다.
- 자동로그인 시 생략된 로그인 창의 서버 연결 필요 아이콘이 남지 않는다. 로그인 화면을 실제 사용 중일 때는 트레이 최소화 기능을 유지한다.
- 기존 설정·후원·숨김 내역·위플랩 선택 설정은 그대로 유지한다. 위플랩 URL 없는 사용자의 기존 경로도 유지한다.
- 이전 1.0.0.53 설치 자산과 운영 배포 기록을 보존한다. 복귀하면 해당 UI 캐시·트레이 결함이 다시 나타날 수 있다. 자동 업데이트 복구는 높은 sequence의 새 서명 목록으로 진행하며 이전 피드 덮어쓰기로 대체하지 않는다.

## 제거·보존한 파일과 근거

사용자 데이터와 예전 캐시를 삭제하지 않았다. 새로운 UI 추출 경로·폼 정리 및 검사만 변경했다. 비공개 배포 영수증과 고객 사진·계정 자료는 게시하지 않는다.
