## 목적과 변경 전 문제

계속 쌓인 자료에서 파싱·방종 오류의 재발, 계정 혼선, 세션 교체 공백과 자원 사용을 확인했습니다. 새 연결을 먼저 준비하는 별도 후보는 미배포 상태이며 현재 관측 자료를 그 후보의 실검증 결과로 취급하지 않습니다.

## 변경 내용과 소유 구성요소

현재 연구 JSONL을 비공개 로컬 스냅샷에 보존하고 세션별 수신·자원·종료를 집계했습니다. 소스 수정이나 신규 연결을 만들지 않았습니다. 공개 기록에는 관측 대상 A/B로 표시하고 계정 식별자·원문·토큰·서버 정보는 남기지 않습니다.

### 여전히 남은 연결 교체 공백

방종 대기와 구분한 세션 교체 공백은 총 6회, **36.982~128.662초**였습니다.

| 대상 | 이전 대조 종료 → 다음 준비 완료 (KST) | 공백 |
| --- | --- | --- |
| A | 9/29 00:43:11.636 → 00:45:20.298 | 128.662초 |
| A | 9/30 00:41:14.169 → 00:41:51.151 | 36.982초 |
| B | 9/27 21:54:26.984 → 21:55:05.900 | 38.916초 |
| B | 9/28 05:53:50.298 → 05:54:27.383 | 37.084초 |
| B | 9/28 21:51:53.558 → 21:54:01.507 | 127.949초 |
| B | 9/30 21:48:08.715 → 21:50:15.907 | 127.192초 |

각각 duration_reached 이후 다음 세션으로 이어졌습니다. 약 128초였던 3회는 중간에 observation_token_wait 및 operating_collector_owns_refresh 기록도 있습니다. 현재 `soak-monitor.mjs`는 기존 OAuth 만료 60초 전까지 실행하고, `soak-controller.py`는 토큰 대기 시 60초 기다립니다. 후보가 먼저 닫힌 뒤 운영 수집기의 갱신 토큰을 기다리는 구조가 남아 있습니다.

이 구간의 후보 수신 연속성은 검증되지 않았습니다. 공백만으로 운영 데이터 유실을 단정하지도 않습니다. 서비스 기록은 기존 Chromium만 담당합니다. 새 토큰 연결을 먼저 준비하는 handoff 후보는 운영 관측 bundle에 연결되지 않았고 실제 서버 교체 검증도 아직 수행하지 않았습니다.

### 자원·속도와 한계

- 후보 Node RSS: A **68.7~80.7 MiB**, B **71.4~78.4 MiB**. heap 최대 9.60 MiB 미만, 표본 소켓 1개·타이머 4~5개.
- 후보 Docker 메모리 중앙값 A 28.75 MiB/B 27.13 MiB, CPU 표본 최대 A 0.45%/B 0.13%, PIDs 모두 11. 관측 내 비정상 자원 증가 징후는 없지만 세션 교체가 있으므로 무기한 단일 프로세스의 누수 부재를 보증하지 않습니다.
- 기존 전체 컨테이너는 메모리 567.3~806.4 MiB, PIDs 168~231입니다. 여러 계정의 Chromium·전송·큐·관측 보조를 포함하므로 수신 전용 후보와 단순 비율로 절감률·500명 수용량을 계산하지 않습니다.
- 일치 프레임 시각 차이 버킷은 후보−기존 기준 (-100,-20] ms 5건, (-20,0] ms 10,607건, (0,20] ms 1,115건. 후보가 20ms 넘게 늦은 표본은 없지만 CDP 관측 지연을 포함합니다. DB·업보·OBS 도착 속도를 의미하지 않습니다.
- 현재 실행 세션은 마지막 양쪽 comparison까지만 집계합니다. 이후 telemetry 이벤트를 불일치로 보지 않습니다. 준비 직후 제외 구간·세션 사이 공백·양쪽 동시 누락을 이 일치 수치로 증명하지 않습니다.
- 새로운 합성 검사를 재실행하거나 코드 변경을 하지 않았습니다. 이번 결과는 실제 관측 기록의 집계입니다.

## 사용자 영향과 복구

내용 일치·파싱·계정 격리·방종 재개 관측 결과는 양호합니다. 그러나 **신규 경로 단독 운영 전환은 아직 준비되지 않았습니다.** 자동 토큰 공급과 새·구 연결 교체, 실패 시 기존 연결 유지, 실제 ingress/암호화 outbox/DB·업보·OBS 종단, 계정별 단일 writer 전환·복구가 남습니다. 같은 내용을 더 오래 비교하는 대신 이 과제의 실검증으로 진행해야 합니다.

이번 작업은 관측 종료 선언이 아닙니다. 기존 서비스와 연구 관측은 그대로 유지하며, 오류 후보를 임의로 재시작하지 않습니다.
