# 직접 WebSocket 패킷 비교 중단 원인 분석 · 2026-10-05

## 상태와 범위

- 상태: 연구 체크포인트. 분석과 문서 기록만 수행했으며 후보 코드·운영 데이터·배포·중단 상태는 변경하지 않았다.
- 확인 시각: 2026-10-05 03:00 KST 서버 증거 조회 및 이후 로컬 합성 검사.
- 대상: 직접 WebSocket 관측기의 패킷 비교와 안전 중단. 운영 SDK 페이지 수명 결함과 구분한다.
- 이전 기록: [SDK 운영 수정 및 후보 상태](2026-10-05-sdk-lifecycle.md), [연구 후보 교체 조건](2026-10-04-passive-handoff.md).

## 목적과 변경 전 문제

직접 연결 후보가 일반 별풍선 패킷 코드 18의 `event_mismatch`로 중단된 원인을 추적했다. 패킷 수신 실패, 파싱 실패, 토큰 교체 실패와 비교 기준의 문제를 구분한다.

## 변경 내용과 소유 구성요소

실행 코드를 바꾸지 않았다. 다음 증거와 개선 필요성을 기록한다.

### 실제 중단 순서

1. 10월 4일 19:32:42.481 KST 운영 대상 A의 후보가 연결됐다.
2. 19:39:36.665 KST 후보가 코드 18을 받았고, 기존 경로도 1ms 뒤 같은 코드의 패킷을 받았다. 양쪽 원문 HMAC은 달랐다. 이 시각 근접성만으로 같은 후원 내용이라고 확정하지 않는다.
3. 비교기는 `(패킷 코드, 전체 바이트 HMAC)`으로만 연결하므로 양쪽을 서로 다른 이벤트로 남겼다. 10초 유예를 지나도 일치 항목이 없어 19:39:47.705 KST `event_mismatch`로 후보를 안전 중단했다.
4. 종료 사유는 `supervisor_stopped`였다. 이 구간에는 파싱 오류·토큰 교체·소켓 오류 기록이 없었다. 직전 기존 경로는 연결 상태, 전송 대기는 0이었다.

약 7분 5초 동안 양쪽 각각 76건을 받았다. 채팅 74건과 코드 109 한 건은 일치했고 코드 18 각각 한 건의 해시가 달랐다. 다른 두 대상은 이 구간에 실제 후보 세션이 없었다. 조회 당시 관측 서비스는 active이지만 실행 중 후보 컨테이너는 없었다.

### 비교 기준의 결함을 합성 데이터로 재현

`soak-monitor.mjs`와 `rolling-observer.mjs`는 모두 `p.bytes` 전체를 HMAC한다. `soak-compare.py`는 후원 처리 결과를 비교하지 않는다.

코드 18의 0 기반 필드 4·5·6·9·10을 각각 바꾸면 원문 해시는 달라지지만 현재 별록의 후원 이벤트·종류·이미지 결과는 같았다. 4는 SDK의 fanNumber이며 현재 별록 처리 결과에서 제외된다. 나머지 필드의 서버 의미나 연결별 변동 여부는 확인하지 않았다. 반대로 후원 수량·후원자·이미지 키·이미지 선택 플래그 변경은 처리 결과 차이로 확인됐다.

공식 SDK를 수정하지 않고 로컬 가상 서버에서 실행한 32개 합성 패킷은 SDK와 후보의 별록 처리 결과가 일치했다. 현재 Python 비교기에도 실제 합성 해시를 입력하여 **처리 결과가 같은 두 패킷을 10초 후 불일치로 판정하는 경로**를 재현했다. 이는 오탐 가능한 설계의 증거이며, 당시 실제 후원도 동일했다는 증거는 아니다.

`rolling-observer.mjs`의 이전/새 연결 교체 비교도 원문 해시를 사용한다. 같은 제한이 교체 판단에 영향을 줄 가능성이 있으나 이번 세션에는 교체가 발생하지 않아 실제 실패로 판정하지 않는다.

### 진단 기록 부족

정상 파싱된 패킷은 전체 HMAC과 시각·코드만 남긴다. 원문이나 필드별 비교 자료가 없어 이번 코드 18의 어떤 필드가 달랐는지는 복원할 수 없다. 기록된 해시로 후원 수량·사용자·이미지 차이를 역추적할 수 없다. 따라서 실제 사건의 오탐/내용 불일치 판정은 미확정이다.

### 다음 수정 방향 — 아직 미구현

- 원문 동일성과 별록 처리 결과 동일성을 별도로 비교한다. 계정·방송·후원자·종류·수량·이미지·미션 결과 등 실제 의미가 있는 필드를 포함한다.
- 동일 금액 후원이 반복될 수 있으므로 개수와 대응 관계를 보존한다. 금액 하나나 내용 집합만 비교해서 누락·중복을 숨기지 않는다.
- 원문만 다른 경우는 진단으로 분리하고, 처리 내용·개수 불일치는 안전 중단을 유지한다. 연결 교체에도 같은 기준이 적절한지 별도로 검사한다.
- 다음 차이를 분석할 수 있도록 필드별 HMAC·길이 등 개인정보를 공개하지 않는 진단을 남긴다. 원문이 필요하면 인증정보를 제외한 비공개 제한 보관 정책을 먼저 적용한다.

## 사용자 영향과 복구

서비스 동작 변경 없음. 운영은 기존 Chromium 경로를 사용한다. 후보를 재시작하거나 안전 중단을 해제하지 않았다. 문서만 되돌릴 수 있으며 실행 환경 복구는 필요 없다.
