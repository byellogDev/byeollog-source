## 목적과 변경 전 문제

정상 파싱된 두 패킷의 전체 바이트 HMAC이 다르면 실제 별록 처리 결과가 같아도 관측기가 중단됐다. 이전 진단 보강은 파싱 실패·연결 종료에 한정됐고, 정상 파싱 후 비교 불일치 경로에는 필드 기록이 없었다. 이 누락 때문에 과거 실제 사건의 차이 필드를 복원할 수 없었다.

## 변경 내용과 소유 구성요소

- 연구 전용 `comparison-record.mjs`: 계정·방송 채팅 번호와 별록이 사용하는 이벤트 종류, 후원자, 수량, 이미지, 채팅 내용 등을 정규화해 세션별 HMAC으로 비교한다. 파서는 기존 SDK 대조 대상과 같다. 인증·입장·제어 패킷은 이 기록기에 넣을 수 없다.
- `soak-monitor.mjs`와 `rolling-observer.mjs`: 기존 CDP 경로와 직접 연결 경로 모두 같은 버전의 기록을 생성한다. 방송 범위를 포함하며 계정별 임의 키를 유지한다. 이전/새 토큰 연결 대조에도 같은 의미 비교를 적용한다.
- 직접 연결 전용 Python 비교기: 원문 차이와 처리 결과 차이를 분리한다. 같은 처리 결과이면 원문이 달라도 대응 건수에 포함하고 `wire_only_difference`로 진단한다. 반복 후원을 개별 건으로 대응시키며 누락·중복·내용 차이 중단은 유지한다. 미션 정산·합계 같은 미처리 패킷은 초기 콘텐츠 검증 성공 건수에 넣지 않는다. 이전 SDK 비교기는 변경하지 않았다.
- 원문 필드의 **0 기반 위치별 HMAC·바이트 길이**, 처리 결과의 **필드명별 HMAC·길이**, 양쪽 시각·전체 원문 HMAC을 남긴다. 차이 위치와 업무 필드 차이를 함께 기록한다. 시간상 가까운 미대응 항목은 `time_proximity_not_identity`로 표시하며 동일 후원으로 확정하지 않는다.
- 감독기는 일반 처리와 종료 후 drain 양쪽에서 진단을 저장한다. 토큰 교체 중 내용 차이·원문 차이와 남은 대조 항목도 보존한다. 알려지지 않은 진단 속성·토큰·평문은 저장하지 않는다.
- 비교 형식이 없는 구버전 기록은 조용히 원문 비교로 되돌리지 않고 거절한다. 단일 패킷 진단 256필드, 교체 대조 4MiB, 전체 대조 16MiB, 기존 증거 파일 32MiB 상한을 유지하거나 추가했다. 용량 초과를 성공으로 처리하지 않는다.

## 사용자 영향과 복구

관측계정A·관측계정B·테스트 계정은 각자 기존 연결이 안정되면 독립적으로 연구 관측을 시작한다. 사용자 선언 종료 정책을 유지하고 취소한 예약 작업은 재생성하지 않았다. 기존 Chromium 경로만 운영 데이터에 반영한다.

수정 직후에는 세 대상 모두 방송 대기이므로 실제 수신·토큰 교체·장기 연속성이 확인됐다고 주장하지 않는다. 현재 비교는 기존 원문에 같은 어댑터를 적용한 처리 결과이며, SDK 실행 결과와의 일치는 별도 고정 SDK 합성 검사로 확인했다. 운영 DB 전송 결과 자체를 비교하는 기능은 아니다.

평문 원문은 저장하지 않는다. 새 기록은 어느 원문 필드와 업무 필드가 달랐는지 확인할 수 있지만 원래 값을 복원하는 자료는 아니다. 과거 기록 부족도 소급 해결되지 않는다.

문제 발생 시 연구 관측만 중단하고 증거를 보존한다. 이전 버전에는 알려진 원문 비교 결함이 있으므로 정상 복구로 간주해 무조건 재실행하지 않는다. 운영 경로는 유지한다.
