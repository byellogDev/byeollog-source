# 자동 통신 API 응답 실패 진단 보강 · 2026-10-20

## 상태와 범위

- 상태: 진단·알림 분류 보완 운영 반영. 반복 API 실패 자체의 원인 해결은 미완료.
- 확인 시각: 2026-10-20 18:46 KST.
- 대상: 호스트 자동 방화벽 제어기의 API 진단과 감시기의 HTTP 5xx 분류.
- 이전 기준: [10월 16일 인증 시각 수정](2026-10-16-egress-auth-clock.md).
- 웹·Agent·수집기·오버레이·야추·DB·허용 포트 및 대상 범위 변경 없음.

## 목적과 변경 전 문제

10월 20일 00:00~18:40의 감시 기록에는 정상 1,744개, `api_unavailable` 425개, `controller_error` 7개 표본이 있었습니다. 표본 수는 요청 실패 횟수가 아닙니다. 오류 진입 구간은 12개이며 10:04:42~13:28:35에는 정상으로 돌아오지 못했습니다. HTTP 저널에는 502 응답 8건이 있었고 인증 실패는 없었습니다. 이전 인증 시각 패치의 운영 파일 해시도 일치했습니다.

같은 날 수집 채널 오류·전송 대기·격리가 0을 초과한 감시 표본은 없었습니다. 이 사실만으로 실제 후원 누락이 없었다고 확정하지 않습니다.

기존 API 클라이언트는 HTTP 오류만 상세 기록하고, 시간 초과·DNS·TLS·연결·본문 해석 실패를 모두 `api_unavailable`로 변환했습니다. 따라서 당시 비HTTP 실패의 세부 원인은 복원할 수 없습니다. 감시기도 HTTP 502를 알려진 코드로 분류하지 않아 `controller_error`로 뭉뚱그렸습니다.

실제 서버에서 변경 없는 목록 조회 24회를 실시해 모두 성공했습니다. 응답은 대부분 약 0.3초였으며 최대 4.566초였습니다. 일시 지연은 확인했지만 오후 장애를 재현하지 못했으므로, 공급자 전체 장애나 특정 네트워크 원인으로 단정하지 않습니다.

## 변경 내용과 소유 구성요소

- 비HTTP 실패의 종류를 timeout, dns, tls, connection, incomplete_response, invalid_json, os_error, unexpected로 나누어 저널에 기록합니다.
- 실패 단계(connect/read/decode), 소요 시간, 숫자 errno, 고정된 작업 종류와 시각만 기록합니다. 예외 문자열·URL·키·서명·응답 본문은 기록하지 않습니다.
- 기존 오류 반환 코드와 요청 횟수는 유지합니다. 불확실한 POST/DELETE 재전송이나 안전 중단 우회는 없습니다.
- HTTP 500/502/503/504를 구분해 Discord 안내에 표시합니다. 알림 억제·정상 판정 완화는 없습니다.

## 사용자 영향과 복구

18:46:07 KST에 검증한 API 파일과 감시 함수 변경을 적용하고 자동 제어기만 재시작했습니다. 18:46:42 확인 시 수집 채널 오류·전송 대기·격리는 모두 0입니다. 방화벽 목록·구성, 수집기·오버레이·야추 컨테이너의 이미지와 시작 시각이 유지되었습니다.

자동 제어 실패 중에는 새 목적지 허용과 규칙 정리가 보류될 수 있습니다. 기존 허용 규칙을 삭제하거나 넓히지 않습니다. 공급자 API 응답 실패 자체는 이번 진단 수정으로 해결되었다고 주장하지 않습니다. 향후 실패 원인을 구분할 근거를 확보한 상태입니다.

설치 전 원본과 검증 후보·전후 영수증을 비공개 보존했습니다. 준비 상태·규칙·구성·다른 컨테이너 불변 검증이 실패하면 두 파일을 원복하는 절차를 사용했습니다.
