# 계정별 직접 WebSocket 운영 전환 · 2026-10-08

## 상태와 범위

- 상태: **2026-10-08 04:40 KST 단일 운영 대상 전환 완료**. 해당 계정은 direct, 나머지 4개 계정은 SDK. 배포 이미지와 실행 파일 6개 해시·기존 인증 및 권한/볼륨 설정의 보존을 확인했다.
- 운영 확인: healthy, 전송 대기 0·실패 보관 0·메모리 대기 0. 모든 대상 방송 대기이므로 전환 후 실제 후원 수신 성공으로 계산하지 않는다.
- 구성요소: 지속 실행 수집기. 웹·DB 스키마·Windows Agent·OBS 프로그램은 변경하지 않는다.
- [직전 수신 내용 검증](2026-10-08-direct-observation-review.md)에서 수락한 내용을 바탕으로 운영 전송 경로를 연결한다. 테스트 방송 미진행을 운영 전환의 선행 조건으로 요구하지 않는다.

## 목적과 변경 전 문제

직접 연결 후보는 수신만 했으며 운영 저장은 SDK 수집기가 담당했다. 승인된 한 계정의 실제 저장 경로를 직접 연결로 바꾸되, 나머지 계정의 수집 방식과 기존 전송·권한 경계를 유지한다.

## 변경 내용과 소유 구성요소

- 검증한 v6 프로토콜·파서·연결 교체 코드를 생성 도구로 운영 모듈에 고정한다. 생성 결과와 원본의 일치 검사 및 `ws@8.21.0` 잠금 파일을 추가했다.
- 선택된 활성 소켓의 이벤트만 기존 계정/방 검사, 분류, 재생 중복 방지, 관련 채팅 필터, 계정별 순서 처리, 암호화 outbox, 서명 전송으로 전달한다. 소켓 교체는 하나의 논리 연결 ID와 순번을 유지한다.
- 비공개 상태 볼륨의 `transport-policy.json`에 명시된 계정만 직접 연결을 선택한다. 파일이 없으면 SDK이며, 잘못된 정책은 기존 작업을 유지한 채 오류를 기록한다.
- 방식 변경은 이전 계정 작업을 종료하고 메모리 내 대기 이벤트의 내구성 저장을 기다린 뒤 다음 작업을 시작한다. 다른 계정의 작업은 정책 변경만으로 재시작하지 않는다.
- 인증 철회·계정/앱 불일치는 해당 계정을 중단한다. 일시적인 자격증명 조회 실패나 검증 부족 교체는 현재 소켓을 유지한다. 방종은 방송 대기 정책으로 돌아간다.
- 선택 계정은 연구 수신 대상에서 제거하고 기존 JSONL은 보존한다. 나머지 연구 관측은 계속한다. 캠페인 전체 완료 선언은 아니다.

## 검증

| 항목 | 방법 | 결과와 한계 |
| --- | --- | --- |
| 전체 회귀 | Node 검사 875건 | 샌드박스에서 874건 통과, Windows 바로가기 1건은 프로세스 제한으로 실패한 뒤 실제 사용자 환경에서 단독 통과 |
| 운영 후보 | 외부 네트워크·운영 볼륨 없는 읽기 전용 컨테이너에서 8건 | 생성 소스 일치, SDK→직접→SDK 단일 작업 교체, 두 차례 토큰 교체, 같은 후원의 반복 발생 보존, 암호화 큐 재시작·실패 후 재전송, 다른 방·인증 철회 거부, 방종 대기 통과 |
| 기존 교체 회귀 | 관련 58건 및 전체 회귀 | 잘못된/무응답 대체 소켓, 계정 혼선, 조용한 방송의 제어 패킷, 원문 차이 진단 검사 포함 |
| 실제 DB/OBS | 실제 후원 수신 후 확인 필요 | 합성 검사는 실제 SOOP→DB→풍벽지→OBS 종단 수신의 증거가 아니다 |

성공 경로 검사의 합성 후원은 두 연결의 비교 구간에 진입한 뒤 전달한다. 비교 시작 경계에 걸려 한쪽 기록만 남으면 교체를 거부하고 기존 연결을 유지하는 동작을 성공으로 세지 않는다. 네트워크 경계의 완전한 무손실·exactly-once 및 500명 수용을 보증하지 않는다.

## 사용자 영향과 복구

- 선택 계정은 연구 후보와 SDK를 중복 운영하지 않고 직접 연결 하나를 운영 writer로 사용한다. 토큰 교체 준비 중에는 같은 계정의 소켓이 잠시 두 개일 수 있지만 운영 출력은 하나다.
- 이번 실행 파일 배포는 공용 컨테이너 교체를 수반한다. 사용자에게 다른 계정 SDK 작업의 일시 재시작을 설명하고 명시적 승인을 받았다. 전환 전 모든 계정 방송 대기·빈 큐를 확인한다.
- 정책에서 선택 계정을 제거하면 다음 조정 주기(최대 약 60초, 이전 작업 정리 시간 별도)에 SDK로 돌아간다. 이는 즉시 무공백 전환 보장이 아니다. 실행 파일 자체 문제는 보존한 이전 이미지·Compose 설정으로 복구한다. 암호화 outbox 볼륨과 인증값을 유지한다.
- 초기 배포의 설정 보호 검사는 환경변수 배열 비교 차이로 자동 복귀했다. 이전·후보 이미지와 Compose의 환경변수 키/값이 같음을 확인한 뒤 순서가 아닌 키/값으로 비교하도록 배포 검사를 정정했다. 복귀 상태 정상·대기열 0을 확인했다.
- 실제 방송 중 장시간 운영, 실제 네트워크 장애 복구, DB/OBS 종단, 운영 비용 비교는 별도 관측 대상이다. 세션 실행기의 48시간 상한에 도달하면 기존 재연결 정책으로 새 세션을 시작한다.

## 제거·보존한 파일과 근거

운영 데이터·원문·과거 연구 기록을 삭제하지 않았다. SDK 코드, 이전 이미지, 전환 전 설정은 복구용으로 보존한다. 비공개 정책, 인증값, 연구 자료 및 배포 receipt는 Git에 포함하지 않는다.
