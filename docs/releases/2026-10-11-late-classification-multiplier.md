## 목적과 변경 전 문제

특수룰렛 다음 결과가 처음 보는 유형이면 학습 이후에도 수집 당시의 2배를 적용해야 합니다. 서버 처리에는 해당 결과의 배수 기록을 사용하는 기능이 있었지만, 수신함의 개별 업보등록과 비업보→업보 변경은 브라우저에서 별도의 옛 코드로 1건씩 등록했습니다. 이 경로는 배수와 서버의 중복 방지를 사용하지 않았습니다. 사용자가 보고한 특정 과거 건이 이 경로를 거쳤는지는 확정하지 않았습니다.

## 변경 내용과 소유 구성요소

- 개별 업보등록을 기존 인증된 서버 처리 API로 통일했습니다. 나중에 학습하더라도 결과에 저장된 배수를 사용합니다.
- 비업보→업보 변경은 선택 당시의 수신 시각·상태가 같은 행만 다시 대기로 바꿉니다. 다른 처리와 충돌하면 새로고침을 안내합니다.
- 사용되지 않는 브라우저 직접 업보 생성·자동처리 코드를 제거했습니다. 결과별 원자적 등록, 중복 방지, 후원 통계 분리를 서버가 담당합니다.
- 활성 웹·관리 앱 및 보존된 다른 앱의 동일 함수만 수정하고 배포 HTML을 재생성했습니다.
- DB 마이그레이션, 수집기 재시작, 과거 실제 사용자 업보의 일괄 재계산은 하지 않습니다.

## 사용자 영향과 복구

- 학습 후 개별 등록하거나 비업보를 업보로 바꾸어도 해당 결과의 배수가 적용됩니다. 다시 처리해도 수량이 중복 증가하지 않습니다.
- 배수 수집 기록이 없는 과거 결과를 현재 설정으로 추측하여 2배로 바꾸지 않습니다. 과거 누락 자료의 일괄 보정은 이번 변경에 포함하지 않습니다.
- 문제가 있으면 비공개 배포 기록의 직전 웹·관리 배포로 함께 복구합니다. DB 구조와 수집기는 변경하지 않았습니다.

## 제거·보존한 파일과 근거

브라우저 직접 생성 함수 두 개를 제거했습니다. 사용자 원본·후원·업보·배수 기록은 보존합니다. 비공개 검증 자료와 복구 배포 ID는 `.local`에만 보관합니다.
