- 반영: 2026-09-26 13:37 KST. 기존 14:00 종료 시각 유지, 취소된 예약 자동화 재개 없음.

- 이전 기준: [실수신 비교와 중단 기록](2026-09-26-direct-comparison.md).

## 목적과 변경 전 문제

기존 관측기는 `Network.webSocketFrameReceived`의 모든 opcode를 SOOP 패킷으로 해석했다. 정상적인 ping/pong/close 제어 프레임을 넣어도 `original_packet_decode_failed`로 중단되는 결함을 재현했다. CDP의 텍스트/비텍스트 payload 인코딩 계약은 [공식 프로토콜 정의](https://github.com/ChromeDevTools/devtools-protocol/blob/master/pdl/domains/Network.pdl)의 WebSocketFrame과 대조했다.

02:29 실운영 관측 중단 당시의 실패 프레임·세부 오류는 보존되지 않았다. 이번에 재현한 제어 프레임 결함이 당시 단일 원인이었다고 확정하지 않는다.

## 변경 내용과 소유 구성요소

- `cdp-frames.mjs`: opcode 1/2만 text/base64 데이터로 해석한다. 8/9/10은 SOOP 데이터 파서에 전달하지 않는다.
- 잘못된 base64, 크기 상한, UTF-8, 헤더·길이·필드 경계 오류는 계속 실패로 처리한다. 알 수 없는 opcode도 조용히 버리지 않는다.
- 실제 `Network.webSocketClosed`·관측 연결 단절·소유자 불일치·수신 불일치 중단은 유지한다.
- `soak-monitor.mjs`와 감독기: 실패 시 opcode, 문자 수, 바이트 수, 허용된 고정 파서 코드만 보존한다. payload·requestId·자격증명·임의 예외 문구는 기록하지 않는다.
- 후보 수신기 자체의 observer/client/protocol, 실행 entry, ws 의존성, 비교 알고리즘은 변경하지 않았다. 다른 소켓을 임의로 정상 처리하거나 파서 오류를 무시하는 로직도 추가하지 않았다.

## 사용자 영향과 복구

운영 수집 경로에는 변경이 없다. 수정 전 연구 서비스를 종료하고 후보 잔류 0개를 확인한 뒤 새 연구 구간으로 시작했다. 기존 관측 자료는 그대로 보존했다. 정상 방송 대기를 수신 검증 통과로 계산하지 않는다.

문제가 생기면 새 연구 서비스만 중지하고 자료를 보존한다. 기존 오류 후보를 자동 재시작하지 않는다. 다음 데이터 오류가 발생하면 저장되는 제한된 메타데이터로 원인을 추가 확인한다. 연구 종료 시각을 임의로 연장하지 않았다.
