- 확인 시각: 2026-10-16 06:41 KST.
- 별록과 서버 자원 및 `/yatch` 공개 경로만 공유합니다. 별록 로그인·DB·후원 수집·Agent·앱 배포에는 연결하지 않습니다.
- 게임 개발 소스는 별도 `YATCH_MAIN` 저장소, 커밋 `625dd664e5bfc318ab62c9e479199cd65ea546f6`입니다. 이 별록 저장소에는 운영 기록만 게시합니다.
- 이전 기준: 게임 0.7.2 `b60810dfb55748ca5cd3bd51ceb77933cf9ee39a`. 기존 Sites 서비스와 데이터는 보존합니다.

## 목적과 변경 내용

기존 게임을 별도 프로세스·저장소·인증·복구 단위로 옮기고 상태 전달 지연을 줄였습니다. 유지 중인 브라우저 화면 소스를 사용하며 Unity 빌드 4개의 SHA-256과 게임 규칙은 보존했습니다.

- Node 24.19.0, SQLite WAL/FULL, 이벤트 기반 long poll. 버전 CAS와 요청 영수증 중복 방지를 유지합니다.
- 게임 256MiB/0.5 CPU, HTTPS 프록시 128MiB/0.25 CPU. 게임은 비루트·읽기 전용·전용 볼륨·외부 출발 통신이 없는 내부 네트워크로 실행합니다.
- 전용 경로만 별도 원본으로 연결합니다. 원본 인증 헤더를 덮어쓰고 별록 쿠키를 제거합니다. 원본 직접 요청은 403으로 거부합니다.
- 공인 IP TLS 자동 갱신과 SQLite 일일 백업, 최근 7개 보존을 설정했습니다.
- 사용자 승인하에 TCP 80/443 인바운드만 추가했습니다. 기존 방화벽 8개 규칙과 ID, SSH 제한은 보존했습니다. 자동 통신 제어기에는 승인된 두 수동 규칙을 기준 목록에 반영했습니다.
- iwinv API의 생성 요청은 공급자 서버 오류로 실패했습니다. 규칙 미생성을 재조회한 뒤 로그인된 콘솔에서 두 포트를 적용했습니다.
- 별록 기존 웹 배포를 바꾸지 않고 검증된 경로 규칙 버전만 승격했습니다. 수집기는 재시작하지 않았습니다.

최초 Chromium 검사에서는 서버 상태가 화면 렌더보다 먼저 갱신되는 구간을 즉시 검사해 실패했습니다. 상태와 실제 표시가 모두 일치하는지 제한 시간 내 기다리도록 검사만 수정한 뒤 전체 38개를 통과했습니다. 게임 동작이나 실패 조건을 완화하지 않았습니다.

같은 PC의 소수 표본에서 중앙값은 조회 **168→29ms**(각 8회), 행동 응답 **233→53ms**(각 6회), 상대 상태 반영 **422→53ms**(각 6회)였습니다. 모든 환경의 속도나 물리 애니메이션 시간을 뜻하지 않습니다.

## 사용자 영향과 복구

- 기존 방과 브라우저 재접속 정보는 자동 이전하지 않습니다. 이전 주소에서 진행 중인 게임을 마친 뒤 새 주소에서 새 방을 만듭니다. 안내는 게임에 표시했습니다.
- 같은 도메인 경로이므로 브라우저 origin 자체가 독립된 것은 아닙니다. 계정/DB/쿠키 인증과 저장 키, 서버 실행 경계는 분리했습니다.
- 장애 시 신규 `/yatch` 경로만 비활성화해 되돌립니다. 별록 앱을 재배포하지 않습니다. 게임 DB·TLS 볼륨과 이전 서비스는 보존합니다.
- 게임 변경 시 고정 이미지 ID를 교체합니다. DB 복원 전 현재 DB/WAL을 별도 보관하고 복원 후보를 검증합니다. 정확한 경로 버전·이미지 ID·비공개 소스 번들은 독립 게임 릴리스 및 보호된 운영 기록에 보관합니다.
- 실제 iPhone/Safari의 소리·발열·장시간 부하, 장기 무장애는 이번 검증에 포함되지 않습니다.

## 제거·보존한 파일

독립 복제본의 이전 Sites 자동 배포 연결만 제거했습니다. 원본 Sites 저장소·서비스·데이터는 보존했고 게임 자산·DB·접속값을 별록 공개 저장소에 게시하지 않습니다.
