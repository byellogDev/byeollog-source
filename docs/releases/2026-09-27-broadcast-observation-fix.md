## 목적과 변경 전 문제

기존 파서는 헤더 14바이트와 빈 본문으로 된 정상 SOOP 메시지를 거부했다. 이전 수정의 테스트는 인코더가 만든 본문 1바이트 메시지만 사용해 이 경계를 놓쳤다. 고정 해시 공식 SDK와 독립적으로 만든 14바이트 패킷을 대조해 처리 차이를 재현했다.

추가로 원래 연결된 소켓을 requestId로 구분하지 않아 같은 페이지의 다른 소켓 이벤트를 해석할 수 있었고, 방종 상태 확인도 한 차례 조회에 의존했다. 오류 기록에는 실제 SOOP 헤더 정보가 없어서 과거 두 중단의 원인을 확정할 수 없었다. **이번 수정이 과거 실패 패킷의 내용을 복원하거나 같은 원인이었음을 증명하지는 않는다.**

## 변경 내용과 소유 구성요소

1. **파서·수신기:** 14바이트 헤더와 길이 0 본문을 허용한다. 잘린 헤더·거짓 길이·잘못된 UTF-8·빈 후원 필드·계정 불일치는 계속 거부한다. 입장 완료 이후 성공 코드의 방종 신호 88을 정상 종료 후보로 기록한다.
2. **소켓 구분:** Chromium에서 계정 URL이 일치하는 유일한 열린 소켓을 확인한 후 requestId를 고정한다. 이후 다른 소켓의 프레임·종료는 무시하고, 대상 소켓 교체나 모호한 상태는 검토 대상으로 중단한다. `Network.enable`은 기존 생성 이벤트를 재전송하지 않으므로 실제 객체 목록을 읽기 전용으로 확인한다. 관측기 쪽 접속·토큰 갱신은 추가하지 않는다.
3. **방종 후 대기:** 종료 신호나 접속 거부 후 최대 180초 동안 기존 수집기의 신선한 heartbeat와 `broadcast_offline` 상태를 확인한다. 확인되면 해당 계정만 다음 방송을 기다리고, 다음 안정된 기존 연결에서 관측한다. 확인 실패·손상 데이터·수신 불일치는 자동 재시작하지 않는다. 180초 무수신만으로 종료하지 않는 기존 정책은 유지한다.
4. **진단 증거:** 양쪽 파싱 오류에 서비스 코드·반환 코드·선언/실제 길이·헤더 유효 여부·패킷 위치를 기록한다. 준비 완료 전 종료되는 경우도 남은 진단을 회수한다. 본문·원문·자격증명·requestId는 저장하지 않는다.
5. **관측 공백:** 정상 세션 만료 뒤 불필요한 관측기 15초 및 감독기 60초 대기를 제거·축소했다. 기존 연결 안정 확인 30초와 토큰 갱신 대기는 유지한다. 무중단 전환을 구현한 것은 아니며 실제 공백 시간은 후속 자료로 측정한다.

Chromium 동작 근거: [Network agent의 Enable 및 WebSocket 생성 처리](https://chromium.googlesource.com/chromium/src/+/1525bc2f5db2ad465d485826ddae72790b3aa039/third_party/blink/renderer/core/inspector/inspector_network_agent.cc).

## 사용자 영향과 복구

- 후원·업보·OBS 반영은 기존 경로만 담당한다. 후보는 수신 비교 전용이다.
- 세 대상은 각자의 방송 상태에 따라 관측하며 테스트 계정 선행 조건은 없다. 사용자가 관측완료를 선언할 때까지 지속하고, 취소한 예약 작업은 재개하지 않았다.
- 과거 두 파싱 실패의 실제 패킷 종류와 동시에 발생한 SDK 401의 구체 원인은 미확정이다. 앞으로 헤더 진단과 독립적인 방송 상태를 함께 기록한다.
- 새 오류·불일치·소켓 모호성·회수 실패는 안전 중단 대상으로 유지한다. 원인 미확정 상태에서 실패 후보를 반복 시작하지 않는다.
- 이상 시 비공개 receipt의 **새 연구 서비스만 중단**한다. 운영 수집기는 그대로 두고 이전 실패 버전으로 자동 복귀하지 않는다. 이전 구간은 증거로 보존한다.
- 실제 재관측 수신·방종·재개, 세 계정 동시 수신, 토큰 갱신 경계, 후보 데이터의 운영 DB/업보/OBS 종단은 아직 미검증이다. 이번 반영으로 운영 채택이나 500명 수용을 확정하지 않는다.

## 제거·보존한 파일과 근거

레거시·사용자 파일 삭제 없음. 기존 연구 서비스는 중단하고 JSONL·설정·receipt를 보존했다. 새 receipt의 `previousBroadcastSegment` 및 비공개 `before-broadcast-fix.json`으로 구간을 연결한다. 원격 위치·계정 식별자·실행 해시·진단 원본은 `.local`에 보관하며 공개하지 않는다.
