# 자동 출발 통신 제어 알림 지연 개선 · 2026-10-16

## 상태와 범위

- 상태: 운영 반영. 2026-10-16 03:13 KST 확인.
- 대상: iwinv의 로컬 운영 감시 프로그램과 전용 systemd 타이머.
- 이전 기준: [자동 출발 통신 운영 반영](2026-10-15-auto-egress-production.md).
- 수집기·자동 제어기·방화벽·웹·Agent·사용자 데이터 변경 및 재시작 없음.

## 목적과 변경 전 문제

10월 15일 API 인증 실패 알림은 20:52:20, 복구 알림은 20:56:30에 전송됐다. 보존된 표본에는 이미 20:49:46에 인증 실패, 20:54:24에 첫 정상 상태가 있다. 2분 간격의 운영 감시에서 정상 두 건을 기다리면서 첫 정상 관측 이후 알림까지 2분 6초가 추가됐다. 해당 표본의 수집 채널 오류·전송 대기·격리는 모두 0이었다.

이는 API 인증 장애 자체를 4분 만에 고쳤다는 증거가 아니다. 실제 API 복구 순간과 일시 인증 실패의 정확한 원인은 기존 표본만으로 확정할 수 없다.

## 변경 내용과 소유 구성요소

- `operations/iwinv/auto-egress/patch-fast-monitor.py`: 기존 모니터에 로컬 전용 실행 모드를 추가하는 소스 구조 검증 패치.
- 전용 타이머는 30초마다 이미 생성된 제어기 상태 파일만 읽는다. Supabase·웹·iwinv API 조회를 추가하지 않는다. Discord는 실제 알림 전환·기존 재시도에만 사용한다.
- 정상 두 건 확인 원칙은 유지하며 제어기 원본 관측 시각으로 중복을 제거한다. 기존 2분 감시와 같은 파일 잠금·알림 상태를 사용한다.
- 오래되거나 누락된 상태는 복구로 처리하지 않는다. 정상 알림 재시도 중 오류가 재발하면 대기 중이던 복구 알림을 취소한다.
- 최근 48시간, 최대 6,000개의 최소 상태 표본을 로컬에 보존한다. 원문·비밀값·후원자 정보는 저장하지 않는다.
- `install-fast-monitor.py`: 기존 파일 해시 확인, 백업, systemd 검사, 실행 확인 및 실패 시 원복. 기존 감시 타이머와 수집기에는 재시작 명령을 보내지 않는다.

## 사용자 영향과 복구

정상 관측 이후 알림 확정 대기를 약 1분 수준으로 줄인다. 실제 API 장애 지속 시간, Discord 통신 실패, 호스트 부하에 대한 복구 시간 보장은 아니다. 알림 내용은 자동 제어기 정상과 실제 수집 채널 복구를 구분한다.

문제 발생 시 전용 타이머를 중지하고 설치 직전 해시로 보관한 모니터를 원복한다. 기존 2분 감시가 계속 담당한다. 설치 실패 시 이 절차를 자동 수행하며 기존 표본·알림 상태를 삭제하지 않는다.

## 제거·보존한 파일과 근거

사용자 파일 삭제 없음. 기존 모니터 백업·표본·알림 상태를 보존한다. 배포 영수증과 연결 정보는 비공개 로컬 기록에만 보관한다.
