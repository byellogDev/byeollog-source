# 2026.09.24 · 직접 WebSocket 관측용 읽기 전용 API

## 목적과 결과

직접 WebSocket 후보가 운영 토큰을 갱신하지 않고 실제 방송을 관측할 수 있도록 `observe` 계약을 추가했습니다. 승인 이후 후보 검증과 운영 응답 확인까지 완료했습니다. **새 수집기를 운영 후원 처리 경로로 전환한 배포는 아닙니다.** 실제 데이터 반영은 기존 Chromium 경로가 계속 담당합니다.

## 변경 범위

관리자 런타임의 세 파일만 운영에 반영했습니다.

- `lib/runtime-isolation.js`: 인증정보 조회를 담당하는 관리자 런타임에서 `observe` 허용. 수집 런타임은 계속 거절합니다.
- `lib/soop-gateway-api.js`: 기존 서명·계정·수집 활성화 검사를 통과한 관측 요청만 처리하며 수집 lease를 발급하지 않습니다.
- `lib/soop-oauth.js`: 연결된 계정의 접근 토큰을 SELECT만 합니다. 만료 120초 이내 또는 만료 시각 불명은 409 대기 응답입니다. 공급자 갱신, 토큰·오류 상태 저장은 하지 않습니다.

기존 운영 배포 소스 140개를 canonical Git `36d02ac1b1e3bad5ccdcd3bf098a94f89e9fabac`과 대조했습니다. 실행 소스는 모두 일치하며 Git 제외 항목인 빈 출력 디렉터리 유지 파일도 현재 운영 해시와 대조했습니다. 이 기준 위에 세 파일의 관측 변경만 선택해 후보를 구성했습니다. 새 일반 OAuth·마크 연동 변경은 포함하지 않았고 작업 트리에는 별도 후보로 남겼습니다.

## 발견한 배포 위치 오류와 보완

처음에는 관측 준비 API를 수집 런타임에 구현했습니다. 배포 전 실제 경로를 읽어 인증정보 조회가 관리자 런타임으로 전달되며 수집 런타임에는 공급자 비밀값이 금지되어 있음을 확인했습니다. 최초 단위검사는 핸들러를 직접 호출하여 이 경계를 확인하지 못했습니다.

잘못된 수집 런타임 Preview를 운영에 반영하지 않았습니다. 구현을 관리자 런타임으로 옮기고 기존 13개 회귀검사 중 관측 검사 5개를 **웹의 런타임 선택 → 관리자 내부 인증·허용 목록 → 실제 관측 핸들러**를 거치도록 보강했습니다. 수집 런타임의 해당 요청 거절도 확인합니다. 기존 권한 금지를 해제하거나 공급자 키를 수집 런타임에 추가하지 않았습니다.

## 영향과 복구

웹과 수집 런타임의 운영 배포는 바꾸지 않았고 NCP 운영 수집기를 재시작하지 않았습니다. 조회 요청이 방송 접속이나 토큰 갱신을 시작하지 않음을 구분합니다. 인증값은 기존 승인된 프로젝트 안에서 후보에 재사용했고 임시 환경 대상은 원복했습니다.

Vercel `promote`가 새 운영 배포를 생성했으므로 배포 ID가 같다고 기록하지 않습니다. 운영 반영 후 실제 소스와 API를 다시 검사했습니다. 이전 관리자 운영 배포와 새 배포, 변경 목록·응답·환경 원복 기록은 비공개 `.local/candidate-fixes-20260924/`에 보관합니다. 이전 관리자 배포로 복구할 경우 연구 후보는 `observe` 실패 시 중단하며 기존 `lease`로 후퇴하지 않습니다.

공개 저장소에 키·토큰·원문 메시지·회원 정보를 게시하지 않았습니다.
