# 직접 WebSocket 지속 연결 교체 · 2026-09-30

## 상태와 범위

- **서버 연구 관측기에 배포 완료**, 2026-09-30 23:06:58 KST. 기존 승인된 운영 두 대상과 테스트 대상 집합을 유지합니다. 공개 증거에서는 계정 식별자를 제외합니다.
- 기존 Chromium 운영 수집 컨테이너·이미지·시작 시각은 변경하지 않았습니다. 후보는 수신 전용이며 DB·업보·풍벽지 쓰기 경로로 전환하지 않았습니다.
- 이전: [관측 재검증](2026-09-30-direct-observation-review.md), [180초 교체 시험 후보](2026-09-28-direct-handoff-preparation.md).
- **실제 방송 수신 재개 확인. 실제 새 토큰 교체 성공은 아직 미검증**입니다. 배포 성공을 토큰 교체 실검증 완료로 표현하지 않습니다.

## 목적과 변경 전 문제

구 관측본은 OAuth 만료 60초 전 정상 연결을 종료하고 새 토큰을 기다려 37~129초의 대조 공백을 만들었습니다. 기존에 만든 교체 코드는 제한된 180초 시험용이었고 관측기에 연결되지 않았습니다. 이번에는 동일한 새·구 연결 대조와 단일 출력 전환 원칙을 지속 관측 실행기에 연결해 실제 서버로 반영했습니다.

## 변경 내용과 소유 구성요소

- `rolling-observer.mjs`: 토큰 만료 시각만으로 정상 소켓을 닫지 않습니다. 새 토큰이 도착하면 같은 계정·앱·연장된 만료 시각을 검증하고 최대 두 소켓으로 새 연결을 준비합니다.
- 준비 직후 1초를 제외하고 최소 30초 동안 콘텐츠 순서·중복 횟수를 대조합니다. 한 건 이상 일치하고 미결이 없을 때 출력 권한을 동기적으로 바꾼 뒤 구 연결을 닫습니다. 동일 내용의 연속 후원은 발생 횟수대로 유지합니다.
- 새 연결의 인증·연결·순서 대조 실패나 90초 내 대조 불충족 시 준비 중 연결만 닫고 살아 있는 기존 연결을 유지합니다. 같은 실패 토큰을 무한 재시도하지 않습니다. 기존 연결 자체의 종료·축출은 성공한 교체로 처리하지 않습니다.
- `soak-monitor.mjs`: 기존 읽기 전용 observe API로 초기 토큰을 받고, 만료 3분 전부터 30초 간격으로 정상 갱신 토큰을 확인합니다. 후보가 OAuth 갱신 API를 호출하거나 갱신 소유권을 가져오지 않습니다. 갱신 토큰이 아직 없거나 조회가 실패하면 기존 소켓을 유지합니다.
- `rolling-entry.mjs`와 감독기: 새 인증값은 stdin 파이프로만 전달하고 관측 JSONL에 쓰지 않습니다. 교체 단계·결과·대조 개수만 기록합니다. 계정별 컨테이너·UID 65534·읽기 전용 FS·메모리 256 MiB/PIDs 32·CPU 0.25·호스트 마운트 0 제한을 유지합니다.
- 실제 배포 bundle의 observer/entry를 새 실행기로 연결했습니다. 예전 180초 probe와 업무 전달 후보는 독립 검사 자료로 보존합니다. 배포 후 새 구간을 시작하며 이전 구간은 합산하지 않습니다.

신규 검사 최초 실행에서 마지막 frame 콜백이 업무 event 콜백보다 먼저 시험을 중단해 최종 집계가 한 건 부족했습니다. 마지막 프레임의 처리 완료 뒤 취소하도록 시험을 수정한 뒤 통과했습니다. 서버 첫 검사에서는 운영 이미지 내부에 가정한 ws 경로가 없어 **교체 전에 중단**됐습니다. 실제 후보와 같이 고정된 ws 8.21.0 소스를 시험 컨테이너 tmpfs에 넣어 재검사했고, 통과한 뒤에만 관측기를 교체했습니다. 실패 이력을 숨기거나 두 실행의 통과 건수를 합산하지 않습니다.

## 사용자 영향과 복구

- 기존 Chromium만 운영 데이터를 기록합니다. 연구 후보 전환을 위해 관측 세션을 한 번 교체했으며 그 배포 경계는 비교 공백입니다.
- 새 연결이 실제 SOOP에서도 기존 연결을 축출하지 않는지, 갱신 경계에서 일치·순서·출력이 유지되는지는 다음 실제 토큰 갱신 기록으로 확인해야 합니다. 갱신 시점을 강제로 앞당기거나 운영 OAuth를 변경하지 않았습니다.
- 무음 방송에서는 입장 성공만으로 교체 성공을 선언하지 않고 기존 연결을 유지합니다. 네트워크 단절 등 모든 장애의 공백 0이나 exactly-once를 보증하지 않습니다.
- 계정별 개별 실행의 기존 48시간 보호 상한은 남아 있으며 OAuth 만료로 인한 종료와 별개입니다. 전체 관측은 사용자 종료 선언까지 계속하고 예약 자동화는 재개하지 않습니다.
- 문제 시 새 연구 서비스만 멈추고 이전 연구 디렉터리·receipt로 복구할 수 있습니다. 복구 시 후보 중복 실행을 금지하고 이전 회수를 확인합니다. 실사용 데이터·운영 수집기를 복원하거나 초기화할 필요는 없습니다.

## 제거·보존한 파일과 근거

삭제 없음. 이전 관측 코드와 JSONL, 배포 직전 receipt를 비공개로 보존하고 현재 receipt에 previousRollingSegment를 연결했습니다. 토큰·회원 식별자·원문·서버 경로는 게시하지 않습니다.
