# 직접 WebSocket 무이벤트 교체 · 2026-10-02

## 상태와 범위

- **연구 관측기 배포 완료: 2026-10-02 13:35:57 KST.** 기존 Chromium만 운영 데이터에 반영하며 새 경로는 수신 전용입니다.
- 기존 두 운영 대상과 테스트 대상, 사용자 선언 종료 정책, 독립 계정 관측을 유지합니다.
- 이전 [실제 토큰 교체 검증](2026-10-02-direct-handoff-review.md)의 내용 일치·교체 2회 근거는 보존합니다. 이번 구간은 무이벤트 교체 변경 이후로 분리합니다.

## 목적과 변경 전 문제

기존 방식은 새·구 연결의 실제 콘텐츠가 최소 1건 일치해야 교체했습니다. 조용한 방송은 새 토큰을 미리 받아도 교체하지 못해 만료 시각을 넘길 수 있었습니다. 사용자가 승인한 방향에 따라 콘텐츠 대조와 무이벤트 연결 확인을 분리합니다.

## 변경 내용과 소유 구성요소

- `client.mjs`: 연구 rolling 경로에서만 WebSocket ping에 16바이트 난수 challenge를 보내고, 동일 payload의 pong이 5초 안에 돌아온 경우 연결 응답으로 인정합니다. 입장 후 즉시 및 10초 간격으로 확인합니다. 보내기 성공·아무 pong 수신·과거 응답을 확인 완료로 취급하지 않습니다. probe 무응답만으로 기존 연결을 종료하지 않습니다.
- `rolling-observer.mjs`: 같은 계정·앱에 더해 같은 방송의 chatNumber 입장을 확인합니다. 1초 준비 후 최소 30초 공존 동안 콘텐츠가 한쪽에라도 들어오면 기존 순서·횟수 대조를 유지합니다. 준비 구간에 들어온 콘텐츠도 무이벤트로 오분류하지 않습니다.
- 새 연결 준비 이후 양쪽 콘텐츠가 전혀 없고, 공통 구간 이후에 받은 새 연결의 검증된 pong이 15초 이내라면 `quiet_transport_verified`로 교체합니다. 이때 `matched=0`, `contentVerified=false`를 기록합니다. 콘텐츠로 교체한 경우 `content_matched`, `contentVerified=true`입니다.
- 응답 없음·잘못된/오래된 pong·다른 방송·한쪽 콘텐츠만 수신이면 무이벤트 교체를 허용하지 않습니다. 90초 준비 시한과 기존 연결 유지, 최대 두 소켓, 단일 출력 권한·동일 sequence 원칙을 유지합니다.
- 감독기는 교체 근거를 허용 목록으로 보존하고 인증값·challenge·방송 식별자를 기록하지 않습니다. `transportHealthAgeMs`로 검증된 응답의 경과 시간을 관측합니다.
- 연구 bundle을 `direct-ws-rolling-v3`로 배포했습니다. 기존 운영 OAuth 갱신 소유권·DB·큐·권한·도메인·Agent는 변경하지 않았습니다.

## 사용자 영향과 복구

- 콘텐츠가 없다는 이유만으로 항상 교체가 막히던 조건을 개선했습니다. 인증·동일 방송 입장·왕복 연결 응답과 일정 공존 시간을 근거로 교체하며 **내용 대조 미검증 사실은 그대로 남깁니다**.
- 정상 응답 환경에서는 새 입장 후 약 31초부터 교체 가능하지만 시각을 보장하지 않습니다. 새 토큰의 공급이 늦거나 제공자가 pong에 응답하지 않으면 기존 연결을 유지합니다. 토큰 만료 전 교체 보장·모든 장애에서 공백 0을 주장하지 않습니다.
- 실제 SOOP pong 응답과 무이벤트 교체는 다음 방송 관측 과제입니다. 실패한 새 연결을 무조건 재시작하거나 기존 안전장치를 우회하지 않습니다. 운영 종단·단일 writer 전환은 여전히 별도 과제입니다.
- 연구 관측 교체만 수행했습니다. 이전 연구 서비스 중지와 후보 회수를 확인한 뒤 새 연구 서비스를 실행했습니다. 방송 대기 중 배포였으며 운영 서비스는 재시작하지 않았습니다.
- 복구는 새 연구 서비스만 정리한 뒤 보존한 이전 연구 코드·receipt를 사용합니다. 중복 후보를 금지하고 운영 DB나 Chromium을 초기화하지 않습니다. 전체 관측 종료 시각은 추가하지 않았습니다.

## 제거·보존한 파일과 근거

삭제 없음. 이전 전체 관측 자료와 receipt를 비공개로 보존하고 `previousQuietSegment`로 연결했습니다. 이전의 `previousRollingSegment`와 과거 구간 연결도 유지합니다. 원문·회원 식별자·인증값은 Git에 게시하지 않습니다.
