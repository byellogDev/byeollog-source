## 상태와 범위

- 상태: **2026-10-05 02:51 KST 운영 반영**, 02:53 KST 실제 상태 확인.
- 대상: NCP 공식 SDK 수집기의 브라우저 세션 정리. 웹·DB·Agent 설치본·직접 WebSocket 연구 후보의 코드는 변경하지 않는다.
- 이전 기준: 운영 이미지의 세션 소스와 canonical 소스가 동일함을 확인했다. [직접 연결 후보의 이전 수정 기록](2026-10-04-passive-handoff.md)은 별도 연구 이력이다.

## 목적과 변경 전 문제

공식 SDK는 소켓 종료 시 페이지 공용 이벤트 처리기를 없앤다. 같은 페이지에서 SDK 객체를 다시 만들면 `handleReady` 등록 중 null 참조가 발생한다. 기존 수집기는 동시 계정은 분리했으나 종료 후 빈 페이지를 최대 5분 동안 재사용하여 이 오류를 반복했다. 연결 종료와 명시적 disconnect 모두 현재 공식 SDK에서 운영 스택과 같은 위치의 오류를 재현했다.

## 변경 내용과 소유 구성요소

- `browser-session.mjs`: 정상 종료, 방송 대기, SDK 오류, 시작 실패, 방 소유자 거부, 취소, 시간 초과 모두에서 사용한 페이지와 격리 컨텍스트를 폐기한다. Chromium 프로세스 공유와 방 소유자 검증은 유지한다.
- 회귀 검사: 종료된 페이지 재사용을 금지하는 계약 검사와 실제 Chromium의 로컬 합성 SDK 검증 도구를 추가했다. 이 도구는 실제 계정이나 외부 소켓에 연결하지 않는다.
- 소스 manifest: 의도한 단일 운영 파일 변경의 해시를 기록했다.

## 직접 WebSocket 후보 확인

이번 SDK 결함은 SDK·브라우저를 사용하지 않는 직접 연결 후보에는 해당하지 않는다. 그러나 현재 후보가 정상 수집 중이라는 뜻은 아니다.

- 관측 서비스는 active이지만 운영 대상 A 후보는 10월 4일 **19:39:47 KST** `event_mismatch`로 안전 중단됐다.
- 실제 연결은 약 **7분 5초**. 채팅 74건과 코드 109 한 건은 일치했고, 일반 별풍선 코드 18은 양쪽 각각 1건 수신했으나 원문 해시가 달랐다.
- 비교기는 정상 파싱 패킷의 HMAC만 보존하므로 다른 필드가 무엇인지 현재 기록만으로 복원할 수 없다. 유실·변조·수집 결과 불일치 중 어느 것인지 단정하지 않는다.
- 나머지 두 대상은 이 구간의 실제 후보 세션 없이 방송 대기다. 무이벤트 토큰 교체 및 장기 연결은 이번 구간에서 검증되지 않았다.
- 후보를 재시작하거나 안전 중단을 해제하지 않았다. 서비스 active를 수집 성공으로 계산하지 않는다. 이전 내용 검증 수락과 이번 새 불일치의 해결 필요성을 구분한다.

## 사용자 영향과 복구

- 종료된 SDK 페이지 때문에 반복적으로 연결에 실패하는 문제를 제거한다. 후원 분류·전송·권한·계정 경계는 바꾸지 않는다.
- 매 시도마다 새 페이지를 생성하므로 방송 대기 시 페이지 생성 비용이 증가할 수 있다. Chromium 프로세스는 공유하며 운영 반영 후 자원과 오류를 확인한다.
- 교체는 모든 채널 방송 대기, 전송·메모리 큐와 실패 보관이 비어 있을 때만 실행한다. 기존 환경·볼륨·메모리·프로세스 상한을 보존한다.
- 실패 시 비공개 영수증의 이전 이미지와 소스 파일로 동일 compose 서비스를 복구한다. 큐 볼륨을 삭제하지 않는다.

## 제거·보존한 파일과 근거

사용자 파일은 삭제하지 않았다. 원본 이미지·소스·원문 로그·검사 영수증은 비공개 보관한다. 공개 저장소에는 합성 검사와 비식별 요약만 게시한다.
