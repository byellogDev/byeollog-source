# 직접 WebSocket v6 관측 재검증 · 2026-10-08

## 상태와 범위

- 상태: **연구 관측 재검증 완료, 운영 쓰기 전환 전**.
- 조회: 2026-10-08 04:09 KST. 10월 5일 계정 접미사 수정 이후 현재 v6 구간만 집계했다. 과거 실패 구간은 합산하지 않았다.
- [수정·배포 기준](2026-10-05-room-owner-suffix.md), [운영 전환 과제](../research/2026-09-28-direct-production-readiness.md).
- 읽기 전용 조회와 문서 게시만 수행했다. 운영·후보 재배포, 재시작, 데이터 주입, 관측 종료는 하지 않았다.

## 목적과 변경 전 문제

과거 후보는 방종 처리, 토큰 교체, 계정 접미사 검증 문제를 차례로 보완했다. 현재 배포본에서 실제 수신뿐 아니라 교체 중 기존 연결 유지, 정상 종료와 자원 회수가 동작했는지 확인한다. 사용자가 이미 수락한 내용 검증을 다시 장기 관측의 선행 조건으로 만들지 않는다.

## 변경 내용과 소유 구성요소

- 현행 연구 디렉터리의 세 대상 JSONL과 소스 해시, 운영 상태를 읽어 비공개 로컬에 저장했다.
- 각 세션의 마지막 비교 결과만 합산했다. 주기적으로 기록한 누적 집계를 반복 더하지 않았다.
- 양쪽 수신 건수 = 일치 건수 + 편측 건수 + 미결 건수의 관계를 검산하고, 연결 준비·방송 대기 시간은 실제 연결 시간에서 제외했다.
- 운영 코드 변경은 없다. 연구 상태와 운영 전환 문서에 이번 증거를 연결했다.

## 검증

| 대상 | 실제 연결 세션 | 실제 연결 시간 | 일치 이벤트 |
| --- | ---: | ---: | ---: |
| 운영 대상 A | 3 | 15시간 16분 30초 | 4,494 |
| 운영 대상 B | 4 | 15시간 7분 56초 | 2,231 |
| 테스트 대상 | 0 | 0 | 0 |

두 운영 대상의 동시 관측은 9시간 30분 37초다. 캠페인 경과 시간과 실제 연결 시간을 구분한다. 테스트 대상은 계속 방송 대기이며 검증 성공으로 계산하지 않는다. 대상 B의 두 세션은 콘텐츠 이벤트가 없었으므로 수신 내용 검증 실적은 없다.

- 합계 **6,725건 일치**: 채팅 계열 6,652건, 일반 별풍선 이벤트 60건, 미션 후원 이벤트 13건. 후원 수량 합계가 아닌 이벤트 건수다.
- 세션 최종 편측 수신·미결·종료 경계 잔여·공통 구간 밖 이벤트 각각 0. 현재 구간의 의미 비교 및 원문 차이 집계도 0.
- 파싱 오류·needs_review·계정/방 불일치 기록 0. 원래 방 일치 확인 3,642회, 격리 검사 7회 통과.
- 정상 방종 종료 7회, 후보 컨테이너 회수 7회. 조회 시 잔여 후보 컨테이너 0개, 감독 서비스 active, 세 대상 방송 대기. 서비스 active를 실제 수신 중으로 해석하지 않는다.
- 배포된 관측·감시·진입 코드 및 감독/비교 파일 7개 해시가 현재 receipt와 일치했다.
- 운영 pending/deadLetters 0. 후보는 수신 전용이며 기존 SDK만 운영 쓰기를 담당한다.

세 번 모두 기존 연결을 유지한 채 새 연결을 준비하고 대조 후 구 연결을 닫았다. 이 준비 시간은 수집 중단 시간이 아니다. 교체를 이유로 세션이 종료되거나 비교 이벤트가 편측으로 남은 기록은 없다. 토큰 조회가 잠시 unavailable인 동안에도 기존 연결을 유지했다.

별도로 10/06 05:39:01 KST 대상 B는 새 연결의 확인 근거가 부족하여 90초 후 `no_common_content`로 교체를 보류했다. 새 연결만 회수하고 기존 연결은 05:44:37 방종 신호까지 약 5분 36초 더 유지했다. 해당 세션은 콘텐츠 0건이므로 무이벤트 교체 성공 또는 이후 실제 후원 수신 성공으로 표시하지 않는다. 후보 소켓 표본은 평상시 1개, 교체 준비 중 최대 2개였으며 계속 누적되는 표본은 없었다.

### 지연·자원과 비교 한계

- 수신 시각 차이 버킷은 6,724/6,725건이 -100ms 초과~+20ms 이내, 나머지 1건은 -1000ms 초과~-100ms 이내였다. 이는 양쪽 수신 관측 시각의 차이이며 DB·풍벽지 전달 속도가 아니다.
- 후보 Docker 메모리 표본: A 중앙값 26.66MiB/최대 32.39MiB, B 중앙값 26.18MiB/최대 28.53MiB. CPU 중앙값은 각각 0.07%다.
- 프로세스 RSS는 별도 지표다. 세션 시작 약 71.6~75.8MiB, 마지막 약 73.9~82.9MiB였다. Docker 표기와 RSS를 같은 값으로 취급하거나 이 기간만으로 메모리 누수 부재를 보증하지 않는다.
- 기존 컨테이너는 여러 계정의 SDK, DB 전송·큐 및 관측 보조 작업을 포함하고 후보는 계정별 수신 전용이다. 단순 비율을 운영 절감률 또는 500명 수용 근거로 쓰지 않는다.
- 로컬 집계 검산과 게시 전 검사를 수행했다. 코드 변경이 없어 전체 회귀 검사는 재실행하지 않았다.

## 사용자 영향과 복구

**현재 관측 범위의 수신·일반 콘텐츠 기반 교체·정상 방종은 통과다. 운영 전체 완료 판정은 아니다.**

남은 범위는 직접 경로의 단일 writer/lease 및 내구성 전송 큐 결합, 재시작·실패 재전송, 승인된 테스트 워크스페이스의 DB→업보→풍벽지/OBS 종단, 계정별 전환과 SDK 복귀다. 동일 세션에서 두 번 이상 반복 교체, 무이벤트 교체 성공, 실제 네트워크 장애 복구·인증 철회는 이번 자료에서 확인하지 못했다. 새 구간에는 영상후원 등 미발생 이벤트 종류도 있다.

관측은 사용자 종료 선언까지 유지한다. 연구 후보를 운영 쓰기로 바꾸거나 테스트 계정의 선행 통과를 다른 계정 관측 조건으로 추가하지 않는다. 기존·후보 병행은 계정당 채팅 연결 2개, 후보 교체 중 일시적으로 3개를 만들 수 있다. SOOP 시청자 집계 영향은 별도 미검증이다.

## 제거·보존한 파일과 근거

삭제한 파일 없음. 현재·과거 관측 구간을 보존한다. 원문, HMAC 진단, 계정 식별자, 토큰, 호스트 정보와 전체 JSONL은 비공개 `.local`에만 보관한다.
