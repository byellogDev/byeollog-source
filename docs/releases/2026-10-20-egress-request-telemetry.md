# 자동 통신 API 요청·장애 전후 기록 확대 · 2026-10-20

## 상태와 범위

- 상태: 운영 반영. API 장애 자체가 해결됐다는 판정은 아님.
- 확인 시각: 2026-10-20 19:51 KST.
- 대상: 자동 방화벽 제어기, 요청 진단, 상세 알림, 읽기 전용 장애 보고서.
- 이전 기준: [응답 실패 진단 보강](2026-10-20-egress-response-diagnostics.md).
- 수집기·웹·Agent·오버레이·야추·사용자 데이터 및 방화벽 허용 범위 변경 없음.

## 목적과 변경 전 문제

실패만 기록하면 정상 요청 대비 지연, 연결의 어느 단계에서 멈췄는지, 같은 시각의 서버·수집 상태를 놓칠 수 있습니다. 기존 상태 이력도 상세 요청별 기록이 아니었습니다.

이전 진단 보강 후 **19:44:30 KST, GET /instances, 8.014초 timeout**을 실제로 포착했습니다. 해당 시점의 기존 `connect` 단계는 DNS/TCP/TLS/HTTP 응답 대기를 합친 값이므로 원인을 더 좁혀야 합니다. 이를 인증 실패나 특정 네트워크 장애로 단정하지 않습니다.

## 변경 내용과 소유 구성요소

- 성공·실패 모든 실제 API 요청에 임의 요청 ID, 작업 종류, 시작/종료 시각, 결과와 소요 시간을 기록합니다.
- 표준 라이브러리의 실제 연결 호출을 그대로 사용하면서 DNS+TCP, TLS/프록시 터널, HTTP 응답 헤더 대기, 응답 본문 읽기를 계측합니다. 인증서 검증·호스트 이름 검증·리다이렉트 거부는 유지합니다.
- HTTP 상태, 허용된 Content-Type 분류, 응답 바이트 수와 서버 Date 시각 차이도 기록합니다. URL·그룹/규칙 ID·응답 본문·키·서명·사용자 식별자는 저장하지 않습니다.
- 오류 시 메모리 여유, 디스크 여유, 로드 평균, 네트워크 오류/드롭 누적값과 프로세스 파일 디스크립터 수를 기록합니다. 인터페이스 이름·IP·연결 상대는 제외합니다. 자원 스냅샷은 최대 1분에 한 번이며 추가 외부 요청은 없습니다.
- 유지 관리 단계와 결과를 기록해 실패 요청과 상태 변경을 연결합니다.
- 상세 로그는 서비스 계정 소유 `0600`, 파일당 4MiB, 백업 15개를 포함해 총 최대 약 64MiB로 순환 보관합니다. 시간 기준 보존 기간을 보장하지 않으며 높은 호출량에서는 더 빨리 순환합니다.
- 로그 쓰기 실패를 상태에 반영하고 감시 알림으로 전달합니다. 쓰기 실패가 API 요청을 재전송하거나 결과를 바꾸지 않습니다.
- Discord에서 시간 초과·DNS·TLS·연결 끊김·잘못된 응답 형식과 실패 단계·소요 시간을 구분합니다. 오래되거나 알 수 없는 상세 값은 표시하지 않습니다.
- `diagnostic-report.py`는 최근 최대 48시간의 지정 구간에서 순환 로그와 기존 감시 SQLite를 읽기 전용으로 대조합니다. 요청 결과·지연 분포·실패·자원 스냅샷·수집 오류/대기/격리 표본을 반환하며 자료 부족·상세 1,000건 한도·보존 범위 제한을 표시합니다.

## 사용자 영향과 복구

19:50:32 KST 자동 제어기만 재시작해 반영했고, 19:51:08에 준비 상태를 확인했습니다. 수집 채널 오류·전송 대기·격리는 0이었습니다. 방화벽 목록·구성 및 수집기·오버레이·야추의 컨테이너 이미지/시작 시각은 불변입니다.

진단 확대 때문에 외부 조회·POST·DELETE 재전송은 추가하지 않았습니다. 불확실한 변경 요청 중복 방지와 규칙 불일치 시 안전 중단을 유지합니다. 타임아웃 확대나 포트 권한 변경은 없습니다.

설치 전 소스와 모니터를 비공개 백업하고 검증 후보만 적용했습니다. 준비 상태, 로그 쓰기, 파일 해시 또는 다른 서비스 불변 검증이 실패하면 원본 코드·감시기로 복구합니다. 로그는 복구 과정에서도 근거로 보존합니다.

**남은 범위:** 19:44의 시간 초과가 연결/응답 중 어느 부분에서 발생했는지는 이전 기록으로 복원할 수 없습니다. 새 계측은 다음 실패를 구분하기 위한 것으로 공급자 장애가 해결되었다는 인증이 아닙니다.

## 장애 구간 확인과 대응

운영 호스트에서 아래 도구를 사용합니다. 네트워크 요청 없이 로컬 기록만 읽습니다.

```sh
sudo python3 -B /usr/local/lib/byeollog-egress/diagnostic-report.py \
  --since 2026-10-20T19:40:00+09:00 --until 2026-10-20T20:00:00+09:00
```

- `tcp_dns`: DNS 또는 TCP 연결 과정. DNS 오류 코드와 네트워크 카운터를 함께 확인합니다.
- `tls_or_tunnel`: TLS 또는 프록시 터널 과정. 인증서 검증을 끄지 않고 TLS 오류·시각·연결 경로를 확인합니다.
- `response_headers`: 연결 후 HTTP 응답 대기. 5xx 여부, 정상 요청 지연 분포와 같은 시각의 서버 자원을 함께 확인합니다.
- `response_body`/`decode`: 본문 읽기 또는 형식 오류. 길이·MIME 분류로 구분하며 원문을 저장하지 않습니다.
- 공급자 API 장애가 확인되면 시각·상태 코드·지연·서버 상태를 문의 근거로 사용합니다. 이번 작업에서 외부 문의를 발송하지 않았습니다.
- 기존 수집 상태와 제어기 장애를 구분하며, 감시 표본 정상만으로 후원 누락 없음을 확정하지 않습니다.
