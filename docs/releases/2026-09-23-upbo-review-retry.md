# 2026.09.23.1 · 업보 분류 대기와 기술 오류 구분

## 목적과 변경 전 문제

룰렛 결과를 수신했으나 업보 분류 규칙이 없으면 처리기는 `unknown_rule`로 보류합니다. 재시도 예약기는 이 정상 대기도 횟수에 포함해, 실제 처리 시도가 없어도 5회 뒤 재시도 종료 경고를 발생시켰습니다.

## 변경 내용과 소유 구성요소

- 수집 런타임의 재시도 작업은 처리 결과의 `unknown_rule`, `validation_review`, `no_roulette_result`를 대기로 구분합니다. 기존 `needs_review` 상태를 사용해 사용자 분류·확인 기능과 호환됩니다.
- `byeollog_finish_upbo_retry_v1`은 계정·원본 UID·업로드 시각·예약 횟수가 모두 일치할 때만 이번 예약 1회를 반환하고 대기 예약을 해제합니다. 이전 기술 오류 횟수를 초기화하지 않습니다. 중복 완료 호출, 새 결과 도착, 처리 중·완료된 행은 덮어쓰지 않습니다.
- 처리 전 예외나 잘못된 저장 결과는 기술 오류로 기록합니다. 기존 한도·지연·중단 복구 로직은 유지합니다. 일반 `pending` 결과를 무조건 사용자 대기로 간주하지 않습니다.
- 대기 행에 새 결과가 도착해 `pending`으로 전환되면 2분 뒤 복구 예약을 다시 잡습니다. 사용자가 분류한 행의 기존 수동 처리 경로는 유지합니다.
- DB 함수는 `SECURITY INVOKER`이며 기존 서버 역할만 실행할 수 있습니다. 브라우저 역할에는 실행 권한을 부여하지 않았습니다.

## 사용자 영향과 복구

후원·룰렛 원본은 유지됩니다. 미분류 결과는 사용자가 분류할 때까지 확인 대상으로 남습니다. 기술 오류는 기존과 같이 제한된 재시도 후 경고 대상이 됩니다.

원인이 확인된 기존 오경고 1건은 계정·UID·업로드 시각·기존 오류 문구·미분류 상태를 다시 대조한 후 잘못 소진된 횟수와 오류 표시만 정정했습니다. 나머지 행 필드가 동일한지도 비교했습니다. 결과 분류나 업보 생성은 대신 수행하지 않았습니다.

NCP 수집기를 재시작하지 않았습니다. `byeollog.com` 웹 배포는 기존 버전을 유지했고 수집 런타임만 승격했습니다. 후보 생성 중 Vercel이 변경한 팀 시스템 alias는 검증 전에 기존 운영 배포로 복원했습니다.

복구 시 비공개 기록의 직전 수집 런타임 배포를 먼저 승격합니다. 추가한 DB 함수는 이전 코드와 호환되므로 그대로 둘 수 있습니다. 필요하면 보관한 이전 스케줄 트리거 정의를 복원합니다. 정정한 사용자 대기 상태를 잘못된 오류 상태로 자동 되돌리지는 않습니다.

## 파일·배포 기록

신규 SQL 이력은 `20260923104919_separate_upbo_review_wait.sql`입니다. CLI 생성 후 실제 원격 적용 이력의 버전과 파일명을 일치시켰습니다. CLI 임시 상태는 Git에서 제외합니다. 이 릴리스에는 레거시 삭제나 비밀키 변경이 없습니다.

정확한 배포 ID·원본 상태·개별 계정 식별자는 비공개 운영 기록에 보관합니다. 공개 가능한 릴리스 문서에는 넣지 않습니다.
