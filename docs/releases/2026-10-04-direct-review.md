# 직접 WebSocket 무이벤트 교체 관측 재검증 · 2026-10-04

## 상태와 범위

- **연구 체크포인트: 장기 연결 검증 실패, 운영 전환 보류.** 2026-10-04 03:15 KST 읽기 전용 SSH 조회 기준입니다.
- 10월 2일 무이벤트 교체 배포 이후 구간만 집계했습니다. 이전 구간의 내용 검증 수락과 실제 교체 2회 결과를 이번 구간과 섞지 않습니다.
- 운영 변경·재시작·후보 재실행·자동화 생성 없음. 원격 연구 서비스는 active이지만 두 운영 대상 후보는 `needs_review`로 종료되어 수신하지 않습니다. 테스트 대상은 방송 대기입니다.

## 목적과 변경 전 문제

무이벤트 교체 변경 후 실제 연결 연속성, 내용 일치, 계정 격리, 교체 근거를 재검증했습니다. 감독 서비스의 active 상태만으로 실제 수집 지속을 판단할 수 없음을 확인했습니다.

## 변경 내용과 소유 구성요소

문서만 변경했습니다. 서버의 현재 계정별 기록 전체와 코드 해시를 한 번 조회하여 비공개 로컬 자료에 보존하고, 종료 기록·텔레메트리·관측기 코드를 대조했습니다. 계정은 공개 문서에서 A/B로 익명화합니다.

두 후보는 입장 완료 후 각각 약 1,569.918초에 종료했습니다. 종료 직전 표본은 `oauthExpired=false`, 소켓 1개, 정상 수신 상태였습니다. 따라서 현재 증거로 OAuth 만료·방종·파싱 오류라고 단정할 수 없습니다. 동일한 연결 수명은 추가 진단 대상입니다.

코드 추적에서 `client.mjs`는 close code와 stage를 반환하지만 `rolling-observer.mjs`가 상위 반환값에 전달하지 않는 것을 확인했습니다. 감독기에 남은 최종 `transport={}`, `stage=null` 때문에 정확한 종료 코드를 소급 판별할 수 없습니다. 또한 현재 무이벤트 교체 조건에는 검증된 pong이 필요하므로, 이번 실제 환경에서 확인된 자료만으로 해당 경로의 성공을 입증할 수 없습니다. ping 추가와 단절 사이의 인과관계는 아직 미확정입니다.

자원 표본: A RSS 73.46~76.92 MiB, heap 8.49~9.38 MiB, 컨테이너 CPU 0.05~0.17%; B RSS 78.63~81.89 MiB, heap 8.43~9.40 MiB, CPU 0.04~0.11%. 둘 다 PIDs 11입니다. 종료 전 마지막 프로세스 누적 CPU는 각각 약 1.44/1.46초였습니다. 약 26분 자료로 장기 누수 여부를 확정하지 않습니다. 기존 컨테이너는 DB 전송·큐·관측 보조 프로세스까지 포함하고 후보는 수신 전용이므로 단순 절감률이나 500명 수용량으로 환산하지 않습니다.

## 사용자 영향과 복구

- 기존 Chromium 운영 경로는 유지합니다. 후보 중단이 곧 운영 후원 손실을 뜻하지 않습니다. 이번 점검은 운영 DB·풍벽지 종단 재검증은 아닙니다.
- 10월 3일에는 이 후보 구간의 실제 수신 증거가 없습니다. 사용자 선언 종료 정책을 바꾸지 않았지만 안전 중단 때문에 관측이 계속되지 못했습니다.
- 다음 수정 대상은 종료 진단 전달 누락, 실제 제공자에서 검증 가능한 무이벤트 연결 확인 방식, 반복 단절 원인입니다. 안전 중단을 무조건 재시작으로 우회하지 않습니다.
- 코드 수정·재배포는 이번 확인에 포함하지 않았습니다. 복구 시 중단 자료를 보존하고 연구 후보만 교체하며 기존 운영 수집기와 데이터를 유지합니다.

## 제거·보존한 파일과 근거

삭제 없음. 원격 기록·receipt와 이번 전체 조회 자료는 비공개로 보존했습니다. 원문, 인증값, 회원 식별자는 게시하지 않습니다. 실행 코드 변경이 없으므로 제품 회귀 검사를 반복하지 않았습니다. 문서 게시 전 diff·게시 대상 민감정보 검사를 수행합니다.
