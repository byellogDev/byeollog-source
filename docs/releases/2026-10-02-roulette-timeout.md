# 룰렛 연결 대기 3분 자동 종료 · 2026-10-02

## 상태와 범위

- 상태: 운영 반영. DB 마이그레이션 2개, 웹·관리 런타임의 검증된 후보를 각각 승격했습니다.
- 확인 시각: 2026-10-02 22:31 KST. 실제 배포 ID·해시·이전 배포·복구 SQL은 비공개 운영 기록으로 보존합니다.
- 수집기·Agent 배포는 포함하지 않습니다. 공유 관리 화면 소스는 네 앱에 동기화하되 수집·공개 런타임은 이번에 재배포하지 않았습니다.
- 이전 기준: [Agent 1.0.0.46](2026-10-02-agent-10046.md)의 운영 웹 소스. 설치본과 자동 업데이트 피드는 유지합니다.

## 목적과 변경 전 문제

결과가 오지 않는 룰렛 후원이 연결 대기에 계속 남아 있었습니다. 오래된 FIFO 선두 항목은 다음 후원 결과의 연결에도 영향을 줄 수 있었습니다. 사용자 결정에 따라 마지막 결과 이후 3분 동안 추가 결과가 없으면 대기만 종료합니다.

## 변경 내용과 소유 구성요소

- DB: 결과가 없으면 후원 시각, 있으면 마지막 결과 시각을 기준으로 180초 제한을 적용합니다. 단순 설정 수정 시각으로는 대기를 연장하지 않습니다.
- 수신·상태 조회: 계정 권한 확인과 기존 계정별 쓰기 잠금을 유지합니다. 종료된 후원은 자동 연결 대상에서 제외하며, 오래된 항목이 다음 유효한 후원을 막지 않습니다. 구형 수신 경로도 정리 한도 1,000건을 넘긴 상황에서 기한을 직접 검사합니다.
- 정리: DB 내부 작업이 30초마다 실행됩니다. 별도 HTTP 호출이나 화면 접속이 필요하지 않습니다. 평상시 종료 기록 반영은 다음 실행까지 최대 약 30초이며, 잠금 경합·대량 적체 시 늦어질 수 있습니다. 수신과 조회의 기한 검사는 정리 완료를 기다리지 않습니다.
- 보존: 원래 후원 금액·받은 결과·업보·처리 상태를 삭제하거나 다시 처리하지 않습니다. 종료 시각과 이유를 후원·수집 내역에 추가합니다. 기존 데이터 보존 기간은 변경하지 않습니다.
- 화면: 대기 종료 예정 시각과 최근 자동 종료 최대 50건을 표시합니다. 폴링을 추가하지 않으며, 기존 갱신 또는 새로고침으로 상태를 확인합니다.
- 특수룰렛 배수 대기의 별도 규칙은 변경하지 않습니다.

## 검증

| 항목 | 방법 | 결과 | 확인하지 못한 범위 |
| --- | --- | --- | --- |
| DB 동작 | `npm test --prefix tools/db-tests` | 26건 통과: 이번 13건·기존 알림 13건 | PGlite의 격리된 스키마 fixture이며 운영 전체 트리거·동시 경합 재현은 아님 |
| 경계·격리 | 실제 SQL 실행 | 180초 경계, 마지막 결과로 갱신, 늦은 결과 차단, 계정·방송 격리, 중복 수신, 대량 구형 경로, 금액·부분 결과·처리 상태 보존 확인 | 실제 방송의 새 후원을 통한 종단 확인은 미실시 |
| 자동 검사 | `npm test`, `npm run build:web` | Node 855건·웹 빌드 통과 | 사용자의 브라우저 조작 확인은 별도 |
| 소스 | `node tools/verify-source.mjs` | 기준 1,183개 대조 통과 | 변경 의도는 diff로 별도 확인 |
| 후보·운영 | 소스·라우팅·함수 설정·응답 대조 | 두 앱 소스 790개·비인증 응답 8개 일치, 실제 지역 hnd1 확인 | 로그인 후 실제 계정 UI 종단 검증을 대신하지 않음 |
| 운영 DB | 적용 후 SQL 조회 | 정리 작업 11회 성공 확인, 실패 0; 인덱스·컬럼·기한 조건·비공개 함수 권한 확인 | 실제 사용자 후원의 새 자동 종료 발생은 아직 확인하지 않음 |

DB fixture는 운영 함수 정의와 필요한 스키마만 포함하며 회원 데이터·인증값·로그 원문은 포함하지 않습니다. 특수룰렛 v3는 테스트에서 전달 stub을 사용하므로 해당 기능 전체 검증으로 계산하지 않습니다. 원격 전체 CI 결과는 연결된 GitHub Release에 덧붙입니다.

## 사용자 영향과 복구

- 연결 결과가 들어올 때마다 3분을 다시 계산합니다. 필요한 결과가 모두 수집되면 기존 완료 처리 규칙이 우선합니다.
- 이미 기한을 넘긴 기존 대기도 자동 종료 대상입니다. 자동 종료 후 늦게 온 결과로 같은 후원을 되살리지 않습니다.
- 문제 시 기록한 이전 웹·관리 배포를 승격하고 DB 정리 작업을 해제한 뒤 보관한 이전 함수 정의를 복원합니다. 새 컬럼·종료 내역은 보존하며 이미 종료된 후원을 일괄 재개하지 않습니다.
- 종료 기록을 영구 보관하는 기능은 아니며 기존 내역 보존 정책을 따릅니다.

## 제거·보존한 파일과 근거
