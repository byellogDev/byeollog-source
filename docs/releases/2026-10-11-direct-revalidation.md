# 직접 WebSocket 재검증 · 2026-10-11

## 상태와 범위

- 상태: 연구 체크포인트 및 기존 부분 운영 반영의 읽기 전용 검증. 이번 작업의 배포·재시작·관측 종료 없음.
- 확인 시각: 연구 2026-10-11 06:48:35 KST, 운영 06:49:41 KST.
- 대상 A는 SDK 운영과 직접 WebSocket 수신 전용 비교, 대상 B는 10/08 전환한 직접 WebSocket 운영 쓰기다. 나머지 운영 계정은 SDK를 유지한다.
- 이전 기준: [10/08 비교](2026-10-08-direct-observation-review.md), [계정별 운영 전환](2026-10-08-direct-production.md). 이전 검증과 새 구간을 합쳐 새 실적으로 표시하지 않는다.

## 목적과 변경 전 문제

운영 전환 뒤 실제 수신·전달·DB 저장을 확인하고, 연구 비교의 새 방송 구간과 토큰 교체 결과를 검산했다. 기존 내용 일치의 사용자 수락은 유지하며 추가 관측 기간 자체를 승인 조건으로 삼지 않는다.

## 변경 내용과 소유 구성요소

제품 코드 변경은 없다. 비공개 로컬 집계 스크립트의 검산식에 업무 처리 제외 패킷의 별도 일치 수를 반영했다. 기존 식은 수신 1,283건을 업무 이벤트 1,278건과만 비교해 5건 차이를 냈다. 실제 비교기는 해당 5건을 이미 양쪽 일치로 분류했다. 업무 이벤트와 제외 패킷은 계속 분리하며 이 수정은 수집 장애 수정이 아니다.

## 검증

### 대상 A: 새 비교 구간

10/08 이전 조회 뒤 새로 종료된 4개 세션의 실제 준비 완료부터 종료까지 합계는 **20시간 29분 42초**다. 방송 대기는 제외했다.

| 세션 시작 KST | 종료 KST | 업무 이벤트 일치 |
| --- | --- | ---: |
| 10/08 19:03:44 | 10/09 02:54:29 | 2,514 |
| 10/09 20:01:59 | 10/10 00:26:11 | 1,278 |
| 10/10 12:01:31 | 10/10 17:53:43 | 1,619 |
| 10/10 18:01:38 | 10/10 20:24:12 | 785 |

- **6,196건 일치**: 채팅 계열 6,145건, 일반 별풍선 47건, 미션 후원 4건. 업무 제외 패킷 5건도 별도 일치하여 양쪽 수신은 각각 6,201건이다.
- 편측·미결·종료 꼬리·공통 구간 밖 수신·원문 차이·파싱 오류·계정 혼선·needs_review 기록은 모두 0이다. 이는 관측된 양쪽 수신 범위의 결과다.
- 실제 토큰 교체 3회: 10/09 00:22:30, 10/10 00:20:36, 10/10 16:19:47 KST. 준비 시간은 각각 31.360초·31.364초·38.109초이며 기존 연결을 유지한 준비 시간이다. 내용 대조 후 교체했고 수집 중단 시간으로 계산하지 않는다.
- 4회 모두 방송 종료 확인 및 후보 회수 성공. 현재 v6 대상 A 누적은 7개 세션·10,690건이지만 새 검증 건수는 위 6,196건이다.

### 대상 B: 실제 운영 전달과 저장

- 두 방송의 실제 연결 합계 **16시간 58분 45초**. 10/08 21:04:00~10/09 02:51:51 및 10/10 15:59:07~10/11 03:10:01 KST.
- 전송 큐에 넣은 76개 항목은 모두 전달 완료했다. 큐와 완료 로그를 항목 식별자로 대조했으며 후원뿐 아니라 전달 대상 채팅도 포함하므로 후원 76건이라고 해석하지 않는다.
- 동일 계정·조회 종료 구간에서 일반 별풍선 **24건·3,455개**가 핵심 후원 DB, 기존 후원 DB, 풍벽지 타일 저장에 각각 존재한다. 후원 식별자 중복 그룹은 0이다.
- 후원 발생 시각과 핵심 DB 생성 시각 차이는 약 0.117~0.483초다. 서로 다른 시스템의 시계 영향을 포함할 수 있으며 사용자 화면 표시 지연은 아니다.
- 10/08 21:32:01 KST 교체 1회 성공: 31.231초 준비·내용 3건 대조 후 전환.
- **10/10 21:28:37 KST 교체 1회 보류**: 90.001초 동안 교체 근거가 부족해 no_common_content로 새 연결만 닫고 기존 연결을 유지했다. 이후 전달 49건, 실제 후원 17건·3,177개가 저장됐고 기존 연결은 다음 날 03:10:01 정상 방송 종료까지 유지됐다. 교체 보류를 90초 수집 공백으로 해석하지 않는다. 무이벤트 교체 성공은 이번에도 미검증이다.
- **10/10 01:55:05 KST 방송 대기 중 chatinfo_http_failed 1회**: 연결 전 HTTP 요청 실패이며 수신 프레임 0, 약 1.617초 뒤 정상 방송 대기로 복귀했다. 당시 진행 중인 수집 세션은 없었다. 상위 HTTP 상태·본문은 해당 로그에 없어 정확한 공급자 원인은 확정하지 않는다.

### 공통 운영 상태와 근거

| 항목 | 방법 | 결과 | 한계 |
| --- | --- | --- | --- |
| 배포 소스 | receipt 해시와 원격 파일 비교 | 운영 6개·연구 7개 일치 | 새 배포 없음 |
| 운영 상태 | 컨테이너·계정·전송 큐 읽기 | healthy, 재시작 0·OOM 없음, 5계정 방송 대기, 큐·실패 보관 0 | 조회 시점 상태 |
| 비교 집계 | 종료 세션별 수신 보존식 검산 | 업무 제외 일치까지 포함해 통과 | 수신되지 않은 공급자 이벤트는 증명 불가 |
| 실제 저장 | 동일 구간·계정 DB 읽기 | 일반 별풍선 24건·3,455개 및 타일 저장 일치 | Agent·OBS 화면은 미확인 |

연구 프로세스는 수신 전용이고 운영 컨테이너는 전송 큐·DB 전달 등을 포함한다. 이 자료로 자원 효율이나 최대 수용 인원을 단순 비교하지 않는다. 테스트 대상은 방송하지 않아 새 실수신이 없으며 다른 계정 판정을 차단하지 않는다.

## 사용자 영향과 복구

- 기존 운영 경로와 관측을 유지했다. 예약 자동화를 재개하지 않았고 서비스·데이터·권한 변경도 없다.
- 대상 B는 전환 이후 SDK 동시 비교가 없어 운영 저장 성공만으로 공급자 전체 이벤트의 누락 0을 보증하지 않는다.
- 실제 무이벤트 교체 성공, 장애 주입 후 복구, 이번에 발생하지 않은 후원 종류 및 실제 방송 화면 표시는 미검증이다.
- 연구 결과의 정정은 문서 후속 기록으로 처리한다. 실제 운영 복귀가 필요하면 [기존 전환 문서](2026-10-08-direct-production.md)의 계정별 SDK 복귀 절차를 사용하며 이번 검증에서 실행하지 않았다.
