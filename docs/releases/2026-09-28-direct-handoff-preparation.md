# 직접 수집 연결 교체·운영 전환 준비 · 2026-09-28

> 후속: [9월 30일 지속 교체 관측기 배포](2026-09-30-direct-rolling-deployment.md). 아래는 180초 독립 probe의 준비 당시 기록이며, 이후 별도 지속 실행기와 토큰 전달을 서버 관측에 연결했습니다.

## 상태와 범위

- **검증 후보 구현·로컬 검증 완료, 미배포.** 기존 수집 내용 비교는 사용자가 완료로 인정했다. 이후 과제는 운영 연속성과 종단 전달이다.
- 기존 운영 수집기·관측 후보·OAuth·회원 데이터·배포 설정은 변경하지 않았다. 신규 모듈은 현재 운영과 관측 bundle의 import 대상이 아니다.
- 이전: [실방송 검증](2026-09-28-direct-observation-review.md). 후속 기준: [운영 전환 과제와 실검증 절차](../research/2026-09-28-direct-production-readiness.md).

## 목적과 변경 전 문제

현재 연구 후보는 OAuth 만료 1분 전 스스로 연결을 닫고 재준비하여 실제 대조에서 38.916초 공백이 있었다. 토큰 만료 자체가 열린 소켓의 종료를 요구하는지는 별도 문제다. 새 토큰으로 준비한 연결을 확인한 뒤 구 연결을 닫는 방식의 검증 후보를 추가했다. 이번 미배포 코드가 현재 관측 공백을 제거했다고 표현하지 않는다.

## 변경 내용과 소유 구성요소

- `handoff-probe.mjs`: 제한된 시간에 계정 하나의 구·신 연결을 최대 2개 실행한다. 같은 계정·앱, 서로 다른 토큰, 연장된 만료 시각을 확인한다. 새 연결이 실제 이벤트의 순서·횟수를 따라잡은 뒤 단일 출력 권한을 넘기고 기존 연결을 닫는다. 입장 응답만으로 교체하지 않는다.
- 준비 실패·인증 거절·타 계정·불일치·시한·용량 제한은 교체 취소로 처리한다. 구 연결 축출과 현재 출력 연결의 단절은 검토 대상으로 기록한다. 대조 버퍼 10,000건/방향, 전체 시험 180초 기본 상한과 종료 회수를 둔다.
- `handoff-probe-entry.mjs`: 별도 stdin 파이프 실행기, 30초 감독 신호 감시, 명령 인자 설정 금지, 입력 크기 상한, 고정 오류 출력. 새 토큰을 요청하지만 직접 갱신하지 않는다. 현재 운영 observe API와 이 입력 파이프 사이의 자동 감독 연결은 후속 작업이다.
- `delivery-candidate.mjs`: 기존 업무 분류기·후원자 채팅 필터·계정별 순서 처리·내구성 쓰기·암호화 outbox를 재사용한다. 선택된 스트림은 하나의 논리 연결 ID와 증가 sequence로 연결한다. 실제 전송 함수·DB 쓰기·운영 gateway 선택기는 아직 연결하지 않았다.
- 신규 검사 18건을 기본 `npm test`가 실행하도록 wrapper를 추가했다.

## 검증

| 항목 | 방법 | 결과 | 남은 범위 |
| --- | --- | --- | --- |
| 연결 교체 및 실패 | 실제 로컬 WebSocket 서버, 서로 다른 합성 토큰 | 새 입장→공통 수신→교체→구 연결 종료, 인증/연결/소유자 실패에서 기존 연결 유지 | 실제 SOOP 동시 연결 제한·OAuth 동작 |
| 같은 내용의 연속 후원 | 동일 100풍 패킷을 두 번씩 양쪽에 전송 | 교체 전후 각 발생 횟수 보존, 선택된 출력 1개 | 실제 경계의 지연·유실·고유 ID 부재 |
| 내구성 전송 준비 | 선택된 이벤트→기존 분류기→임시 암호화 outbox→503→재시작→재전송 | 순서·금액·발생별 ID 유지, 저장 파일에서 원문/인증값 노출 없음 | 실제 ingress·DB·업보·OBS |
| 격리·실패 전달 | 잘못된 방 입력과 저장 실패 주입 | 저장 전 소유자 차단, 치명적 저장 실패를 drain에 전달 | 운영 계정별 writer 소유권 |
| 파이프 보안·회수 | 잘못된/과대/만료 입력, 종료 및 읽기 시한 | 입력 비노출, 소켓 회수 확인 | 실제 서버 감독기 결합 |

- 로컬 Node 24.19.0에서 신규 검사 **18건 통과**, 실패·건너뜀 0. 기존 직접 클라이언트·암호화 큐 관련 **39건 통과**. 총 서로 다른 검사 57건이며 반복 실행 횟수를 합산하지 않았다. 배포 환경과 같은 Node 22 검사는 게시 후 GitHub CI에서 별도로 확인한다.
- 실행: `node --test tests/soop-direct-handoff.test.mjs tools/soop-direct-lab/client.test.mjs tests/adapted/soop-gateway-outbox.test.mjs`. 신규 파이프 검사 추가 후에는 신규 18건만 다시 실행했다. entry 구문 검사 통과.
- 대조는 제한된 구간의 콘텐츠 HMAC와 순서·횟수 검사다. 플랫폼 고유 이벤트 ID가 없는 경우 두 경로가 함께 놓친 이벤트나 임의 지연까지 판별하지 못하므로 exactly-once·모든 장애에서 공백 0을 보증하지 않는다. 이 한계는 기존 수집 내용의 사용자 수락을 취소하지 않는다.
- 기존 기준 소스 1,183개 대조 실패 0, 게시 파일 1,731개 민감정보 검사 탐지 0, staged diff 검사 통과.

## 사용자 영향과 복구

현재 서비스 변화 없음. 검증 후보를 운영에 연결하지 않았으며 기존 39초 공백이 서버에서 수정된 상태도 아니다. 실제 새 토큰 연결·교체, 자동 토큰 공급, 장애 재연결, 실제 전송과 테스트 계정 화면 종단, 계정별 단일 writer 전환이 남았다. 내용 비교를 위한 추가 장기 관측 대신 이 과제들을 완료한다.

실제 시험 실패 시 이 독립 시험만 중단한다. 기존 운영·관측 서비스를 재시작하거나 상태를 초기화하지 않는다. 중단·복구 범위 및 다음 단계는 전환 준비 문서를 따른다.

## 제거·보존한 파일과 근거

삭제 없음. 기존 소스·배포 receipt·과거 관측 자료는 보존했다. 새 자동검사는 합성 계정과 임시 파일만 사용하며 비밀값·회원 데이터·원문·`.local`을 게시하지 않는다.
