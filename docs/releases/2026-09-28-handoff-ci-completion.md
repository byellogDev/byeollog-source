## 목적과 변경 전 문제

GitHub [실행 29](https://github.com/byellogDev/byeollog/actions/runs/36347755871)와 [실행 31](https://github.com/byellogDev/byeollog/actions/runs/36360972679)에서 Node 검사 820건 중 전송 큐 검사 1건이 실패했다. 기대 송신 건수보다 실제 저장이 각각 2건 적었다. 사이의 [실행 30](https://github.com/byellogDev/byeollog/actions/runs/36360523196)은 성공했다. 기준 소스·게시 검사·DB 검사 13건은 두 실패 실행에서도 통과했다.

시험 서버는 두 개씩 같은 후원 패킷을 계속 보내면서 송신 횟수를 올렸지만, 후보는 연결 교체 뒤 100ms가 지나면 관측을 끝냈다. 소켓에 쓰기를 요청한 시점과 수신한 시점이 같다는 잘못된 전제가 있었다. 마지막 송신 뒤 이벤트 루프를 100ms 멈추는 재현에서 송신 12건·수신 및 저장 10건, `post_observation_complete` 종료를 확인했다. GitHub 실패와 같은 차이를 재현했으며, GitHub 원래 실행에는 패킷별 시각 기록이 없었다.

이 실패는 로컬 정리 전 커밋에서도 발생했다. 로컬 캐시 삭제로 GitHub의 소스가 사라진 문제가 아니며, 실제 운영 후원 누락을 입증하는 로그도 아니다.

## 변경 내용과 소유 구성요소

- 정상 교체·전송 검사는 교체 후 반복 송신을 멈추고 마지막 두 패킷을 보낸다.
- 마지막 패킷까지 수신한 것을 확인한 뒤 시험 연결을 종료하고, 전송 큐의 영구 저장 완료를 기다린다.
- 제한 시간을 유지한다. 수신이 완료되지 않으면 완료 플래그·송신/저장 건수 비교가 실패하며, 누락을 통과로 바꾸지 않는다.
- 전송 큐 검사에서 150ms 이벤트 루프 지연을 강제로 넣어 예전 100ms 종료 조건보다 늦는 상황을 계속 검사한다.
- 암호화 저장·재시작·503 재시도·동일 내용 후원의 개별 ID·순서·계정 격리 검증은 유지한다.
- 운영 코드, 연구 후보 구현, 검사 워크플로와 합격 기준은 변경하지 않는다.
