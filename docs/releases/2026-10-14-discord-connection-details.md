# Discord 수집 연결 오류 상세 안내 · 2026-10-14

## 상태와 범위

- **운영 반영:** 2026-10-14 21:21:25 KST. iwinv 운영 모니터의 Discord 메시지 내용만 보완했다.
- 이전 기준: [수집 연결·출발 포트 감시](2026-10-14-collector-health-hardening.md).
- 수집 컨테이너·방화벽·인바운드·SSH·인증값·DB 스키마 변경 없음. 자동 방화벽 허용 기능을 켠 배포가 아니다.

## 목적과 변경 내용

기존 알림은 수집 채널 상태 이상이라는 제목과 시각 위주여서 어떤 오류를 확인해야 하는지 알기 어려웠다. 미허용 포트 알림도 숫자만 제공했다.

- 미허용 출발 포트: 등록된 허용 정책 밖의 TCP 포트 번호, 실제 차단 여부 미확정, SOOP 할당 접속 정보와 규칙 대조 및 필요한 목적지·포트만 허용하는 조치를 안내한다.
- 채널 오류: 연결 완료 미확인·worker 갱신 중단·잘못된 상태·실패 채널 누락을 구분한다. 오류 채널 수와 함께 관측된 미허용 포트를 표시하되, 그 포트가 특정 채널의 직접 원인이라고 단정하지 않는다.
- 포트 관측 실패: 허용 여부를 판정할 수 없음을 알리고 호스트 조회 도구·권한 점검을 안내한다.
- 복구 알림: 허용 정책 불일치 해소와 실제 채널 연결·방송 종료 확인을 구분한다.
- 메시지에는 허용 목록으로 검증한 포트·고정 문구·제한된 개수만 포함한다. 원문 오류·주소·회원명·토큰을 그대로 전달하지 않으며 Discord 멘션 차단을 유지한다.

## 사용자 영향과 복구

오류 발생 시 알림에 내용과 확인할 조치가 함께 나온다. 허용 정책 불일치는 실제 클라우드 차단 확인과 구별한다. 알림 주기·재시도·냉각 시간과 기존 복구 확인 조건은 유지했다.

`deploy-alert-details.py`는 이전 모니터 해시를 확인하고 격리 후보 검사를 실행한다. 감시 타이머만 잠시 멈춰 파일을 교체하며 수집기는 재시작하지 않는다. 실패 시 이전 파일로 되돌리고 타이머를 재개한다. `rollback`은 이 변경의 바로 이전 버전으로 복구하며 이후 다른 변경이 있으면 중단한다. 더 이전 건강 점검 릴리스로 복구하려면 이 변경부터 역순으로 복구한다.

## 자동 포트 허용 검토와 한계

[iwinv 공식 규칙 추가 API](https://api.iwinv.kr/api-24458202)는 통신 방향·포트·IP를 지정하는 규칙 추가 경로를 제공한다. 이는 자동화 가능성을 뒷받침하지만, 현재 계정의 API 권한과 운영 방화벽 적용 가능성까지 실증한 것은 아니다.

향후 구현 시 공식 SOOP 응답의 접속 정보를 검증해 필요한 목적지·TCP 포트만 허용하고 적용 완료 후 연결하는 구조를 검토한다. 수집기에 광범위한 클라우드 관리 권한을 직접 주거나 오류 문자열만 보고 임의 포트를 열지 않는다. 이번 변경은 이러한 자동 개방을 구현·활성화하지 않았다.
