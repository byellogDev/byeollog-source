- 구성요소: 업보 설정 API, 결과 게시 DB, 수집 처리기, 서버의 오버레이 수집 관리, 웹 안내.
- 이전: [업보 수집 설정·Agent 1.0.0.56](2026-10-11-upbo-collection-production.md). 당시 별도 보관하던 오버레이 결과를 이번부터 새 업보의 기준으로 사용한다.
- Agent 안정 버전은 1.0.0.56을 유지한다. SOOP 직접 수집기, 별풍선 통계, 풍벽지, 공개 읽기 런타임은 별도 경로로 유지한다.

## 목적과 변경 전 문제

이전 단계는 오버레이 주소와 ON 설정을 제공했지만 업보 결과 처리는 채팅에 의존했다. 채팅 결과가 빠지면 화면에 표시된 룰렛을 온전히 기록하지 못할 수 있었다. 사용자 정정에 따라 채팅의 우선·보조·복구 입력을 모두 제거하고, 오버레이가 반환한 저장 결과만 업보에 사용한다.

## 변경 내용과 소유 구성요소

- 주소를 확인하고 ON으로 저장하면 계정에 맞는 수집 등록을 만든다. 계정·오버레이 설정·소켓 출처가 다르면 등록하지 않는다. 제공자의 영문·숫자 식별자도 지원한다.
- 서버가 계정별 작업을 관리하며 준비된 Agent에 수집 권한을 넘긴다. 브라우저를 실행하지 않는다. 기존 시험 서비스는 종료했고 원문과 상태 파일은 보존했다.
- 후원 접수 당시 ON, 이름, 방송 구간을 저장한다. OFF 뒤 새 접수는 중단하고 이미 접수한 건은 처리한다. URL 변경 시 기존 미완료 건을 다른 설정으로 처리하지 않는다.
- 기본 이벤트명은 한국 시간 후원 발생 월과 수량으로 구성한다. 사전 이름이 있으면 접수 당시 이름을 사용한다.
- 180초 지연 후 조회하며 요청을 먼저 영속 예약한다. 불확실한 요청은 제공자에게 재전송하지 않는다. 동일 요청의 지연된 응답 전달은 복구할 수 있다.
- 원본 응답의 저장 여부, 결과 개수와 순서를 DB에서 다시 검증한다. 같은 글자가 반복돼도 순번별로 보존한다. 후원 UID의 계정·수량·시각 충돌, 미확정 응답과 게시 오류는 별도 진단으로 남긴다.
- 배수는 후원자·방송별 결과 순서에 따라 한 번만 소비한다. 앞선 미확정 결과를 건너뛰어 다음 결과에 임의 적용하지 않는다. 기존 분류와 `&` 업보 분리 처리를 유지한다.
- 오버레이 결과는 업보 대기열에만 게시한다. 별풍선 통계에 같은 후원을 다시 저장하지 않는다. 기존 시험 자료·재생·테스트 이벤트는 자동 승격하지 않는다.

웹 검사 중 관리자 기본 주소가 임시 검증 배포를 가리켜 404가 발생했다. 사용자 도메인과 프로젝트의 production 지정만 확인했던 범위가 부족했다. 웹이 참조하는 기본 별칭까지 같은 검증 후보로 연결한 뒤 정상 응답을 확인했다. 임시 배포 3개는 별칭 복구 후 삭제했다.

## 사용자 영향과 복구

- 후원알림 오버레이 주소와 ON이 필요하다. 채팅이 누락돼도 채팅을 기다려 룰렛 결과를 구성하지 않는다. 미등록 결과의 기존 업보 분류 대기는 유지한다.
- 현재 지원은 검증된 제공자의 일반 별풍선 룰렛, 정확한 수량 조건, 최대 100회다. 안내에 나온 다른 제공자의 주소가 모두 지원된다는 뜻은 아니다.
- 결과가 아직 없는 API는 추첨을 만들 가능성이 있다. 승인된 지연 조회 정책을 유지하며, 생성 징후가 확인되면 수집을 안전 중단한다. 단순 지연만으로 생성 가능성이 없어졌다고 보증하지 않는다.
- 전환 후 실제 후원이 아직 없어 새 운영 결과의 실방송 검증은 남아 있다. 연결 정상·자동 검사 통과를 실후원 완료로 대신하지 않는다.
- 장애 시 원문·예약·응답·receipt를 보존하고 신규 접수를 중지한다. 시험 데이터를 운영에 재생하거나 불확실한 요청을 다시 보내지 않는다. 운영 제어를 끄면 이전 채팅 함수가 재개될 수 있으므로 단독으로 끄지 말고, 신규 업보 접수 차단 및 이전 배포·함수 복원 계획을 함께 적용해야 한다.
- 복구용 DB 함수와 이전 배포 ID, 소스 대조표, 서비스 설정은 비공개 운영 기록에 보존한다.

이전 시험 증거와 프로그램·DB 이력은 보존했다. 검증 전용 원격 배포와 임시 API 소스만 제거했다. 비공개 주소·원문·계정 식별자·접속키는 Git에 넣지 않는다.
