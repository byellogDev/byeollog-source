# 자동 출발 통신 API 인증 반복 실패 수정 · 2026-10-16

## 상태와 범위

- 상태: 운영 반영. 2026-10-16 14:09 KST 설치 후 확인.
- 대상: 호스트 자동 제어기의 `iwinv_api.py`와 회귀 검사. 수집기·Agent·웹·야추·방화벽 권한 범위는 변경하지 않습니다.
- 이전 기준: [자동 출발 통신 알림 지연 개선](2026-10-16-auto-egress-alert-latency.md). 당시 수정은 복구 알림 지연만 줄였고 인증 실패 자체의 원인은 미확정이었습니다.

## 원인과 재현

2026-10-16 00:00~14:02 KST의 로컬 감시 표본 1,254개에서 인증 오류 표본 32개, 오류 진입 29회가 있었습니다. 수집 채널 오류·전송 대기·격리가 0이 아닌 표본은 없었지만, 이를 후원 누락이 전혀 없었다는 종단 검증으로 해석하지 않습니다.

실행 중인 인증값과 디스크의 인증값이 동일하고 호스트 NTP가 동기화된 것을 확인했습니다. 운영과 같은 API 클라이언트로 읽기 전용 조회를 반복하자 초가 바뀐 직후 401 `INVALID_SIGNATURE`를 재현했습니다. 실패 응답의 Date는 요청에 서명한 시각보다 이전 초였습니다. 같은 키·경로로 조금 뒤 보낸 요청은 정상입니다.

동일한 초 경계에서 서명 시각만 바꾼 대조 결과, 기존 시각은 **3/3 실패**, 1초 전 시각은 **3/3 성공**했습니다. 공급자 내부 구현은 확인할 수 없지만, 재현된 원인은 미세한 양쪽 시계 차이가 초 단위 서명의 경계에서 거절되는 호환 문제입니다. 키 만료나 방화벽 포트 누락으로 판정하지 않습니다.

[공식 인증 문서](https://iwinv-common.readme.io/reference/api-request)는 초 단위 시각과 경로를 서명하며 서버 기준 5분 이상의 시각 차이는 유효하지 않다고 설명합니다. 1초의 여유는 이 유효 범위 안에 있습니다.

## 변경

- 호출 간격 대기가 끝난 뒤 현재 시각을 한 번 읽고, 1초 전의 정수 시각으로 헤더와 HMAC을 동일하게 생성합니다.
- 요청 재전송, 인증 생략, 권한 확대, 실패 알림 억제는 추가하지 않습니다. 불확실한 규칙 생성의 중복 방지와 정책 불일치 시 안전 중단을 유지합니다.
- HTTP 실패 시 상태 코드, 허용된 공급자 오류 코드, 작업 종류, 요청·응답 시각만 서비스 저널에 남깁니다. 응답 본문은 최대 4KiB만 해석하고 키·서명·URL·본문·임의 메시지는 기록하지 않습니다. 알 수 없는 코드도 원문 대신 OTHER로 기록합니다.
- `policy.test.py`에 초 경계, 호출 간격 대기 후 새 서명, 실패 진단의 비밀값 제거, 변경 요청 재전송 금지 검사를 추가했습니다.

## 배포 확인과 복구

배포는 설치 전 파일 해시를 검증하고 원본을 보존한 뒤 동일 검증 후보만 교체합니다. 자동 제어기만 재시작합니다. 새 상태 표본, 오류·검토 필요 여부, 방화벽 목록 및 수집기·야추 컨테이너의 시작 시각/이미지 불변을 확인하며 실패 시 원본으로 복구합니다.

14:09:15 KST에 적용했고, 이후 정상 상태 표본 3개와 14:09:51 최종 확인에서 오류·검토 필요 없음, 방화벽 목록/구성 불변, 수집기·야추 컨테이너 시작 시각/이미지 불변을 확인했습니다. 수집 채널 오류·전송 대기·격리는 모두 0이었습니다. 설치된 API 소스 SHA-256은 `95cb664fd86d504a8ae19cede9bc8a0bc86411574760f09162c9efe7fb0c0287`입니다.
