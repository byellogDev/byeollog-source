# 2026.09.26-tokyo-region · 운영 실행 지역 정합화

## 상태와 범위

- 상태: 웹·관리 API 운영 반영 완료.
- 확인 시각: 2026-09-26 11:07 KST.
- 대상: `apps/web`, `apps/admin-runtime`의 Vercel 프로젝트 기본 지역과 실제 함수 실행 지역. 애플리케이션 소스와 권한 경계는 유지했다.
- 이전 기준: [리포트 버튼 수정](2026-09-26-report-button-visibility.md). [백그라운드 요청 절감](2026-09-26-background-usage.md)과 별개의 변경이다.

## 목적과 변경 전 문제

모든 화면에서 느리다는 제보를 받아 실제 요청을 조사했다. 소스의 `vercel.json`은 도쿄(`hnd1`)를 지정했지만 두 프로젝트의 기본 설정과 운영 배포는 미국 동부(`iad1`)였다. DB는 도쿄에 있어 인증·데이터 조회의 지역 간 왕복이 발생했다. 이전 배포 검증에는 실제 실행 지역 대조가 빠져 있었다.

## 변경 내용과 소유 구성요소

- 웹·관리 API의 프로젝트 기본 지역을 도쿄로 변경하고 현재 운영 배포의 소스를 재사용해 후보를 만들었다.
- 후보의 지역을 명시하고 소스 해시·라우팅·환경변수 적용 범위·공개 응답을 대조한 뒤 순차 승격했다. 승격 과정에서 플랫폼이 새 운영 배포 ID를 생성하므로 최종 ID도 다시 검증했다.
- 최초 후보에서 운영 환경변수가 상속되지 않는 것을 발견해 해당 후보는 승격하지 않았다. 기존 승인 범위에서 동일 프로젝트의 보호된 Preview에 운영 환경을 일시 적용하고 원래 범위를 복원했다.
- `tools/verify-deployment-region.mjs`와 회귀 검사 4건을 추가했다. 설정/메타데이터 누락, 다른 지역, 예상 밖 추가 지역, 미완료 배포를 통과시키지 않는다. 배포 절차에 후보·운영 검사 명령을 추가했다.

## 사용자 영향과 복구

- 화면·API 로직 변경 없이 서버와 DB 사이의 불필요한 장거리 왕복을 줄였다. 기존 사용자 데이터·로그인 권한·수집기 설정은 변경하지 않았다.
- 비밀값 재조회가 불가능해 단기 검증 세션을 만들지 못했다. 인증된 후보 비교를 수행한 것으로 기록하지 않으며 운영에서는 기존 브라우저 로그인 세션을 사용했다.
- 오류·인증 회귀 발생 시 비공개 기록에 저장한 직전 운영 배포로 복구하고 실제 alias와 응답을 확인한다. 필요하면 함께 저장한 이전 프로젝트 지역도 복원한다.
- 이번 측정은 모든 지연 원인이 제거됐다는 보증이나 동시 사용자 수 검증이 아니다.

## 제거·보존한 파일과 근거

운영 파일은 제거하지 않았다. 첫 후보·배포 ID·소스 해시·환경 복원 정보·측정 근거는 비공개 `.local`에 보관하며 게시하지 않는다. 공개 변경은 지역 검사 도구·검사·절차·릴리스 기록이다.
