# 별록 에이전트 v0.7.0.56 인계

기준선은 `v0.7.0.56`이다. v0.7.0.55 산출물과 운영 업데이트 경로는 불변으로 유지한다.

## 핵심 변경

- 추첨 상태를 `접수 중 → 봉인·추첨 중 → 완료`로 분리했다.
- 사용자가 당첨 개수를 1~100 사이에서 설정한 뒤 `추첨 시작 · 추첨함 봉인`을 누른다.
- 봉인된 응모 풀은 변경되지 않으며 이후 추첨권은 다음 open 회차에 적립된다.
- `다음 1장 추첨` 요청은 예상 추첨 순서를 함께 보내므로 중복 클릭과 오래된 화면의 재요청을 차단한다.
- 서버는 한 요청에 당첨자 한 명만 확정하고 해당 한 명의 OBS 실행만 큐에 넣는다.
- 진행률, 현재 당첨자, 다음 회차 접수 현황을 추첨 관리 화면에 표시한다.
- 기존 `draw_raffle_v1`은 구버전 호환용으로 보존하되 봉인된 다른 회차를 우회하지 못하도록 서버 트리거로 보호한다.

## 서버 변경

- migration: `supabase/migrations/20260823171308_add_manual_raffle_draw_control.sql`
- RPC: `get_raffle_state_v2`, `start_raffle_draw_v1`, `draw_next_raffle_winner_v1`
- 내부 추첨 테이블은 직접 Data API에 노출하지 않고 기존 RLS deny와 revoke 경계를 유지한다.

## 비회귀 원칙

- 기존 추첨권 지급과 과거 추첨 결과는 보존한다.
- 봉인 이후 들어온 후원을 버리지 않고 다음 회차로 분리한다.
- 당첨 결과는 서버 트랜잭션과 advisory lock 안에서 한 장씩 확정한다.
- OBS 송출 실행이 생성되지 않으면 해당 한 장의 당첨 확정도 함께 롤백한다.
