# 별록 웹 대시보드 아이콘·성능 점검 보고서

## 결론

- 대시보드 아이콘을 별록 메인페이지와 동일한 `/assets/byeollog_app_icon.png`로 통일했다.
- 초기 화면의 다섯 데이터 요청을 인증 한 번을 거치는 단일 `dashboard-bootstrap` 요청으로 합쳤다.
- 첫 화면 표시를 막던 기존 데이터 정리·자동 연결·Collector 후처리를 첫 렌더 이후 유휴 시간 작업으로 옮겼다.
- 접힌 작업까지 IndexedDB 파일을 모두 읽던 구조를 제거하고, 사용자가 펼친 작업만 지연 로드하도록 변경했다.
- 신규 분류와 학습된 분류 수정은 저장 직후 화면을 갱신하고, Collector 후처리와 전체 동기화는 백그라운드에서 한 번만 수행하도록 변경했다.
- 운영 Supabase가 도쿄(`ap-northeast-1`)인데 Vercel Functions가 미국 동부(`iad1`)에서 실행되던 구조를 확인하고, Functions 기본 실행 리전을 도쿄(`hnd1`)로 고정했다.
- 인증된 `/dashboard` HTML 응답에 첫 화면 데이터를 안전하게 포함해, HTML 표시 후 초기 데이터 API를 다시 기다리던 네트워크 단계를 제거했다.

## 원인 확인

- 운영 DB의 주요 대시보드 조회 평균 실행 시간은 약 0.34~0.86ms였고 테이블 크기도 작았다. DB 쿼리 자체는 병목이 아니었다.
- 기존 초기 진입은 별도 API 요청 다섯 건을 순차 수행했고, 각 요청마다 멤버십·워크스페이스 권한을 다시 확인했다.
- 서버 응답 뒤에도 유지보수 작업과 화면 밖 파일 조회를 기다린 후 렌더링했다.
- 분류 저장은 후처리, 전체 렌더, 수신함 재조회 일부를 중복 수행했다.
- 최적화 1차 배포 뒤에도 실제 요청은 한국 Vercel POP(`icn1`)에서 미국 함수(`iad1`)로 넘어간 뒤 도쿄 Supabase까지 왕복했다. 최근 운영 로그의 서버리스 요청도 전부 cache MISS였으므로 이 대륙 간 왕복이 남은 체감 지연의 핵심 원인이었다.

## 안전성

- DB 스키마와 운영 데이터는 변경하지 않았다.
- 기존 권한 검사는 제거하지 않고, 단일 bootstrap 요청 안에서 한 번 수행한 뒤 동일 워크스페이스 필터를 모든 조회에 적용했다.
- HTML에 초기 데이터를 넣기 전에도 멤버십과 `data:read` capability를 실시간 재검증한다.
- HTML inline JSON은 `<`, `>`, `&`, U+2028, U+2029를 이스케이프하며 CSP nonce를 적용한다.
- 응답은 `no-store, private`이며 내부 오류 상세는 외부 응답에 노출하지 않는다.
- 유지보수 작업은 삭제하지 않고 첫 화면 표시 뒤에 실행한다.

## 검증

- Node 계약 테스트 37/37 통과.
- API와 생성 스크립트 구문 검사 통과.
- 대시보드 inline script 4개 구문 검사 통과.
- 편집 원본 `lib/admin-source.html`과 배포용 `lib/admin-html.js`의 byte 동일성 계약을 추가했다.

## 운영 확인 항목

- 인증된 계정에서 첫 진입 체감 시간, 처음 보는 룰렛 분류 직후 반응, 펼친 작업의 파일 표시를 실제 브라우저로 최종 확인한다.
