# 별록 안정화 체계

이 체계는 기능 테스트의 개수보다 실제 방송 데이터 흐름의 불변조건을 우선합니다. 모든 자동 검사는 운영 후원 전송과 DB 쓰기를 수행하지 않습니다.

## 1. 배포 전 안정성 게이트

```powershell
npm run stability:gate
```

다음 항목을 한 번에 검증합니다.

- 익명 SOOP 이벤트 6종을 실제 정규화·룰렛·오버레이 TTS 함수에 재생
- 동일 이벤트 중복 수신 시 한 번만 실행
- 같은 이벤트 ID의 내용이 바뀌면 실행하지 않고 차단
- 구독 이벤트가 후원이나 룰렛으로 잘못 분류되지 않음
- 152개 단일 룰렛과 330개 연차 룰렛 결과·TTS·이벤트 ID 연결
- 장애·역순·OBS 재시작을 포함한 디지털 트윈 1,000회
- 룰렛 활성화 함수가 재시도 가능한 `40001`을 반환하지 않음

결과는 저장소 밖 `output/stability-gate/latest.json`과 `latest.md`에 남습니다.

## 2. 배포 후 운영 스모크 검사

```powershell
npm run stability:smoke
```

로그인, 세션 만료 리디렉트, OBS API 인증 경계, 에이전트 업데이트 피드와 설치 링크를 GET 요청만으로 검사합니다. 5xx 또는 잘못된 응답은 실패하며 HTTP p95가 2.5초를 넘으면 경고합니다.

## 3. Supabase CPU·재시도 폭주 검사

Supabase CLI가 운영 프로젝트에 연결된 관리자 PC에서 실행합니다.

```powershell
npm run stability:db-pressure
```

15초 간격의 두 읽기 전용 스냅샷을 비교합니다. 룰렛 활성화 호출이 100회보다 많이 증가하거나 장기 실행·잠금 대기가 임계치를 넘으면 실패합니다. SQL 본문, 키, 사용자 데이터는 출력하지 않습니다.

## 4. 자동 게이트

GitHub Actions는 `master`와 현재 릴리스 브랜치의 push 및 모든 pull request에서 서버·에이전트·TTS 테스트를 실행합니다. 세 작업이 모두 성공한 push만 운영 스모크 검사를 수행합니다. 같은 브랜치에 새 커밋이 오면 이전 검사를 취소해 오래된 결과가 최신 결과처럼 보이지 않게 합니다.

## 릴리스 판정

- 필수: 서버, 에이전트, TTS/Relay, 이벤트 재생, 디지털 트윈 모두 통과
- 필수: 운영 스모크 5xx 0건
- 필수: 이벤트 중복 실행 0건, 이벤트 ID 연속성 100%
- 경고: 공개 HTTP p95 2.5초 초과
- 즉시 중단: Supabase 활성화 호출 15초당 100회 초과 또는 잠금 대기 10개 초과

실제 후원 반응속도 SLO는 기존 비식별 관측값을 이용해 기준선을 충분히 모은 뒤 강제 게이트로 승격합니다. 기준선 없이 임의 수치를 강제해 정상 방송을 차단하지 않습니다.
