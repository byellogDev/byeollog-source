# 별록 룰렛·추첨 난수 감사 (2026-08-28)

## 결론

- 자체 룰렛의 운영 예정 추첨 경로는 `pgcrypto.gen_random_bytes(4)`로 만든 32-bit 난수와 rejection sampling을 사용한다.
- 확률표는 실수가 아닌 `probability_ppm` 정수 합계 1,000,000으로 저장·선택한다. 최소 단위는 0.0001%다.
- 2^32를 1,000,000으로 나눈 불완전한 꼬리 967,296개를 버리므로 modulo 편향이 없다.
- 한 추첨에서 4-byte 블록을 한 번만 생성하도록 정리했다. 기존 구현도 각 byte가 독립 균등이라 결과 편향은 없었지만 호출이 네 번이라 불필요했다.
- 룰렛 신뢰성 시뮬레이터의 보조 정수·shuffle도 같은 rejection sampling으로 통일했다.

## 발견해 보완한 별도 추첨권 경로

기존 추첨권 당첨 순번은 감사 가능한 256-bit seed와 당첨 차수를 SHA-256으로 해시한 뒤, 앞 60-bit를 후보 티켓 수로 바로 modulo 축소했다. 편향은 현실적으로 극미량이지만 후보 티켓 수가 2^60의 약수가 아니면 이론상 완전 균등하지 않다.

`20260828022116_harden_unbiased_random_sampling.sql`은 다음 계약을 보존하면서 편향을 제거한다.

- 기존 seed 기반 재현성과 감사 가능성 유지
- 60-bit 범위의 불완전한 꼬리 구간 rejection
- 최대 티켓 1,000,000, 당첨 순서 1~100 제한 유지
- 128회 안에 유효 블록이 나오지 않는 비정상 상태는 편향된 fallback 없이 fail-closed
- 공개 RPC, 원장, 중복 방지, Agent 송출 payload 및 권한 경계 유지

## 확률 선택 경계

샘플은 0..999,999이고 누적 확률 상한보다 작은 첫 항목을 선택한다. 예를 들어 A=250,000, B=750,000이면 A는 0..249,999, B는 250,000..999,999를 받아 각각 정확히 25%, 75%다.

## 검증

- Node 계약·보안·UI 회귀검사 145/145 통과
- 운영 PostgreSQL 17에서 동일 32-bit 산식을 100,000회 읽기 전용 실행: 유효 99,980, 꼬리 폐기 20, 범위 이탈 0
- 자체 룰렛 500,000회 확률 시뮬레이션 최대 편차 1.7159 sigma
- 10,000개 이벤트, 18,460회 실행에서 유실 0, 중복 노출 0
- duplicate storm, 순서 뒤바뀜, crash-after-commit, cache retry, retry exhaustion 통과
- 자체 룰렛은 SOOP 공식 API 승인 전 dormant 상태이며 운영 방송 동작에는 변화가 없다.

## 운영 적용 상태

- 자체 룰렛 보완: dormant migration에 반영됨. 승인 후 새 활성 migration으로 복원할 때 그대로 사용한다.
- 추첨권 보완: active migration으로 준비됨. 운영 DB 반영 전후 `draw_next_raffle_winner_v2`의 보안 속성과 ACL을 대조한다.
